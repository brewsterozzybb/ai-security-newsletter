## Headliners

### "DuneSlide": Two Critical Cursor IDE Sandbox-Bypass Flaws (CVE-2026-50548, CVE-2026-50549, CVSS 9.8) Turn Prompt Injection Into Reliable RCE

**Cato AI Labs on July 1 published "DuneSlide," two previously undisclosed sandbox-bypass vulnerabilities in Cursor, the AI code editor used by more than half the Fortune 500 (and recently acquired by SpaceX for $60 billion in stock). Both flaws — CVE-2026-50548 and CVE-2026-50549 — are rated 9.8 out of 10 (9.3 under CVSS 4.0) and allow a single prompt injection hidden inside an MCP server response or web search result to break out of Cursor's command-execution sandbox and run arbitrary code on the developer's machine. The fix shipped in Cursor 3.0 on April 2; every version before 3.0 is affected.** ([The Hacker News](https://thehackernews.com/2026/07/critical-cursor-flaws-could-let-prompt.html) | [CSO Online](https://www.csoonline.com/article/4191923/sandbox-bypass-flaws-in-cursor-ide-highlight-prompt-injection-as-an-rce-vector.html) | [Cato Networks](https://www.catonetworks.com/blog/duneslide-two-critical-rce-vulnerabilities/))

**How the sandbox works, and breaks.** Cursor's 2.x line runs AI-generated terminal commands inside a sandbox by default that limits file writes to the current project directory. DuneSlide is two separate escape routes through that sandbox, both triggered zero-click — the attacker never types into Cursor; they plant instructions inside something the agent reads (an MCP server response, a poisoned web search result), and the agent executes the instructions without approval.

- **CVE-2026-50548** abuses the `working_directory` parameter on Cursor's `run_terminal_cmd` tool. The sandbox permits writes into the command's working folder, and that folder is a parameter the agent can set. Injected instructions point it at a system file instead of the project directory — the sandbox helper binary at `/Applications/Cursor.app/Contents/Resources/app/resources/helpers/cursorsandbox`, or startup files like `~/.zshrc`. Overwrite the sandbox helper, and every subsequent command runs with no sandbox.

- **CVE-2026-50549** abuses a symlink-resolution fallback. Before writing, Cursor resolves symlinks to confirm the real destination is in the project. When canonicalization fails (target doesn't exist, or attacker removes read access from a folder in the path), Cursor gives up and trusts the shortcut's in-project path instead. An attacker creates a shortcut pointing outside the project, forces the check to fail, and Cursor writes straight through to the sandbox helper. Same escape, different door.

**The disclosure timeline and the response.** Cato reported both issues to Cursor on February 19. By Cato's account, Cursor rejected them four days later, saying its threat model did not cover misuse of MCP servers, even standard ones like the official Linear workspace. Cato escalated on February 26; Cursor reopened the reports, triaged them, and shipped both fixes in 3.0 on April 2. The CVE IDs were assigned on June 5. The Cato writeup is the first public description of the flaws.

**Why this is a Headliner:** DuneSlide is the second documented attack class this week — after Mozilla 0DIN's DNS-payload RCE via Claude Code — that demonstrates prompt injection through an MCP-connected or web-connected agent is now a reliable, producible RCE vector against a market-leading enterprise AI coding tool. The Cato disclosure shifts the framing from "prompt injection can make the model say bad things" to "prompt injection can take over the developer's machine." The comparison to Mozilla 0DIN's June 29 disclosure is instructive: Mozilla's attack exploited Claude Code's trust in setup scripts; DuneSlide exploits Cursor's trust in its own sandbox implementation. Both prove the same point: zero-click prompt injection through agentic tool ingestion is the defining AI security vulnerability class of 2026. Every organization running Cursor pre-3.0 should update immediately; every organization running any agentic AI coding tool should treat prompt injection as a structural sandbox-escape vector, not a content-moderation problem.

**Not the first, and not the last.** As Cato's researchers note, Cursor is the most widely deployed enterprise AI coding agent; its sandbox is the most mature production sandbox in the category. If the most mature sandbox has two independent escape routes, the sandboxes in the other 10 agents surveyed by Adversa AI's GuardFall (yesterday's newsletter) are structurally weaker by default. The pattern is consistent: every agentic IDE shipping command-execution capability will need to revisit its sandbox architecture in light of DuneSlide.

## Breaking News

### Phantom Squatting: AI-Hallucinated Domains as a Software Supply-Chain Vector — Unit 42 Finds 250,000 Unowned Domains in 2.1M AI-Generated Links, Attackers Already Registering Them for Phishing

**Palo Alto Networks' Unit 42 on July 1 published research on "phantom squatting," a new attack class in which AI models hallucinate web addresses that do not actually exist, and attackers register those predicted domains before anyone else can — then host phishing pages on them to catch traffic that AI tools point their way. Unit 42 asked two AI models 685,339 questions about 913 well-known brands and found that 250,000 of the 2.1 million links the models generated had no registered owner. Thirteen thousand of the links were already flagged as malicious. Attackers have already used the technique: on March 31, an attacker registered a domain both models had hallucinated for a national postal service marketplace, stood up a "Montana Empire" phishing kit that stole card numbers and national ID data in real time.** ([The Hacker News](https://thehackernews.com/2026/07/phantom-squatting-uses-ai-hallucinated.html) | [Unit 42](https://unit42.paloaltonetworks.com/phantom-squatting-hallucinated-web-domains/) | [Cybernews](https://cybernews.com/security/phantom-squatting-hallucinated-domains-cyber-attacks/))

**The attack mechanics.** A brand-new domain has no reputation. Blocklists, threat feeds, and reputation scores all need a site to misbehave for a while before they flag it. A freshly registered phantom domain has no such record, so those filters have nothing to flag. By the time they catch up, the victim has already been sent to the site by an AI tool they trust. Two details make the problem worse: the hallucinated domains are not sitting in training data (both models shipped before the malicious sites existed), and the hallucination patterns are consistent across models — different models often invent the same fake domain for the same question, making an attacker's next target easy to guess. Turning up a model's "creativity" setting only produces more invented domains.

**The structural conclusion.** Unit 42's researchers describe the vector as one that "exploits a structural property of LLM architectures that remains inherently unpatchable." The models do not know which of their suggested domains exist and which do not; they are not designed to check. The fix is not in the model — it is in the application layer: AI assistants that link to websites should verify DNS registration before presenting the link as real. No major AI assistant does this today.

**Why it matters:** Phantom squatting is the first documented attack class where the hallucination itself — not the model's output but the model's invented-but-plausible web address — is the attack vector. For AI assistant vendors, the immediate action is to add DNS lookup verification before presenting a generated URL. For enterprise security teams using AI coding assistants or AI chat tools, phantom squatting means that every link the AI presents should be treated as potentially non-existent until verified — and that brand-monitoring teams need to add "emergent domains from model prompts" to their watchlist.

### Langflow CVE-2026-33017 (CVSS 9.3) Actively Exploited in the Wild — Unauthenticated RCE Deploys Monero Miners on Exposed AI Application Endpoints

**Threat actors are actively exploiting CVE-2026-33017, an unauthenticated remote code execution vulnerability in the Langflow AI application framework, to deliver Monero cryptocurrency miners on exposed endpoints. The flaw, rated 9.3 (CVSS 3.1), allows unauthenticated attackers to execute arbitrary Python code through Langflow's API without any authentication. Patches were released in late June; exploitation began within hours of public disclosure, following the pattern of earlier Langflow vulnerabilities that saw similarly rapid weaponization.** ([TechManiacs](https://techmaniacs.com/2026/07/01/cybersecurity-daily-briefing-july-01-2026/) | [GBHackers](https://gbhackers.com/langflow-rce-flaw-lets-attackers-execute-arbitrary-python-code-without-authentication/) | [Emerging Threats](https://community.emergingthreats.net/t/ruleset-update-summary-2026-07-01-v11225/3369))

**The operational pattern.** Langflow is an open-source visual framework for building AI applications — the equivalent of Node-RED for the AI pipeline world. Organizations deploy it to prototype and chain LLM calls, RAG pipelines, and agent workflows. A significant number of these deployments are internet-facing with default authentication settings. CVE-2026-33017 bypasses whatever authentication is configured and allows direct arbitrary Python code execution. The threat actors behind the Monero miner campaign are scanning for exposed Langflow instances, exploiting the vulnerability, and dropping cryptocurrency mining payloads. Emerging Threats added detection rules on July 1.

**Why it matters:** Langflow is the third open-source AI framework this month (after SimpleHelp and the MCP-related attack chain surface) to have a critical RVE vulnerability actively exploited within days of disclosure. The rapid weaponization window is compressing: attackers are using automated scanning tools to find exposed AI infrastructure within hours of patch availability. For organizations running Langflow in production or development: verify the version, confirm the patch is applied, and audit internet-facing AI infrastructure ports as a baseline control — not an afterthought.

### DeepSeek-Generated Browser Ransomware (InfernoGrabber v9.0): Check Point Documents AI Bridging Theory-to-Attack-Chain Gap

**Check Point Research on July 1 published analysis of "InfernoGrabber v9.0," a browser-only ransomware toolkit generated by DeepSeek that constructs a novel attack path combining "unrealistic browser-malware concepts with a real browser capability" — running entirely inside the Chromium browser on Windows, Linux, macOS, and Android. Check Point's framing: "This is the first documented case where a frontier AI model independently bridged the gap between a theoretical browser-only ransomware risk and a practical, working attack chain — surfacing a novel attack path that defenders had previously dismissed as unfeasible due to browser sandboxing limits."** ([The Hacker News](https://thehackernews.com/2026/07/ai-generated-browser-ransomware-abuses.html) | [Check Point Research](https://research.checkpoint.com/2026/browser-only-ransomware-from-llm-hallucinations-to-a-practical-attack-technique/))

**The artifact.** The sample, uploaded to VirusTotal on January 25, 2026, is a Python Flask application named `deepseek_python_20260125_da0631.py`. It operates as a malicious web server that lures victims with a fake Discord avatar AI upscaler while running a wide array of harmful actions: stealing Discord tokens, harvesting credit card numbers and cryptocurrency seed phrases, logging keystrokes, capturing webcam and microphone feeds, exploiting browser CVEs (including CVE-2023-4863), exfiltrating data via a hardcoded Discord webhook, and displaying a "WinLocker" ransomware screen demanding Bitcoin.

**The DeepSeek significance.** Check Point notes that DeepSeek models have lower refusal rates for malicious cyber requests compared to Western counterparts from Anthropic, Google, or OpenAI. Other facilitating factors: free web-interface access, availability in regions where other frontier models do not operate, and the ability to generate a working malicious application from a "single broad prompt." The implication is that frontier AI models from any provider can now independently bridge the theory-practice gap for novel attack chains that defenders had previously dismissed as theoretical.

**Why it matters:** Check Point's statement that "the expertise needed to discover a new attack path is no longer the bottleneck" is the most strategically important sentence in today's newsletter. The structural shift is that AI-driven threat creation is now producing novel attack chains — not just automating known malware patterns. For enterprise security teams, the operational implication is that threat-intelligence feed credibility for "novel attack path unlikely to be exploited" should be treated with skepticism for any attack path that can be described to a frontier model in a prompt.

### Pentera Labs: Claude Desktop Turned Into Double Agent via Personalization Settings — Anthropic: "By Design, Not a Bug"

**Pentera Labs' red team published research on July 1 demonstrating how an attacker with access to a compromised email inbox can use that access to modify Claude Desktop's per-account personalization settings (including `custom_instructions` and project-specific instructions), converting the victim's Claude Desktop app into a double agent that silently executes commands on the developer's machine. Pentera disclosed the finding to Anthropic in November 2025. Anthropic's response: "After reviewing your submission, we've determined this doesn't represent a security vulnerability that falls within our program scope. Our current threat model treats personal preferences, skills, and MCP connectors as features that can execute code through Claude Desktop by design."** ([The Register](https://www.theregister.com/security/2026/07/01/red-teamers-turned-claude-desktop-into-a-double-agent-to-do-their-evil-bidding/5264692))

**The attack chain.** The prerequisite is a compromised email inbox (via any vector: third-party management platform compromise, phishing, password reset social engineering, or AI-agent-in-the-middle). From the compromised inbox, the attacker modifies the victim's Claude account personalization settings — the same `custom_instructions` and project-level instructions that Claude Desktop reads to tailor its behavior. The base64-encoded prompt instructs Claude to check for command-capable tools on the developer's machine and execute commands via MCP connectors and skills. Because personalization settings apply account-wide and sync across devices, the same instructions propagate to the victim's desktop, mobile, and web sessions. The Cowork feature (which allows users to send tasks from their phone to run on their desktop) makes the attack chain easier. Pentera notes that Anthropic considers this a "feature, not a bug."

**The product-security implication.** This is the second major disclosure this week (after Adversa AI's GuardFall) in which the vendor's response to a security finding is "that's working as designed." Anthropic's threat model explicitly treats personalization settings as a path to code execution. For enterprise security teams managing Claude Desktop deployments, the implication is that Claude account security — including the email inbox that can reset the account — is now part of the endpoint security boundary. Organizations should treat any compromised Claude account as a potential endpoint compromise, and should assess whether Claude Desktop's personalization capabilities should be restricted via managed deployment controls.

**Why it matters:** The "by design" framing is the same structural tension we saw with Mozilla 0DIN's disclosure and the Adversa GuardFall findings: the security community and the vendor disagree on whether a behavior is a vulnerability or a feature. For organizations deploying these tools, the vendor's threat model is the only one that matters for determining whether a fix will ship — and the vendor's threat model says code execution through personalization settings is intentional.

### Microsoft Agent Governance Toolkit: Open-Source Policy Enforcement, Zero-Trust Identity, and Sandboxing for Autonomous AI Agents — Covers 10/10 OWASP Agentic Top 10

**Microsoft has released the Agent Governance Toolkit (AGT) as open source — a Python package (one `pip install`, any framework) that provides policy enforcement, zero-trust identity, execution sandboxing, and reliability engineering for autonomous AI agents. The toolkit maps to all 10 items in the OWASP Agentic Security Initiative Top 10 and implements the full set of Agent Trust Framework (ATF) R1-R9 requirements. Verified June 14, 2026, by internal Microsoft validation.** ([GitHub — microsoft/agent-governance-toolkit](https://github.com/microsoft/agent-governance-toolkit))

**Architecture and coverage.** AGT enforces governance at the application middleware layer, not the OS kernel level. It answers three core questions: (1) Is this action allowed? An agent with access to `send_email` and `query_database` should not be able to `drop_table` — OAuth scopes and IAM roles control which services an agent can reach, not what it does once connected. (2) Which agent did this? In a multi-agent system where five agents share a single API key, "an agent did it" is not an incident response. (3) Can you prove what happened? Auditors and regulators need tamper-evident records of every decision: what policy was active, what tool was called, what data was returned.

**The five ATF elements.** AGT maps to five structural categories: Agent Mesh (identity), Agent OS (policy), Agent Compliance (governance), Agent Runtime (sandboxing), and Agent SRE (incident response). The OWASP mapping covers ASI01-ASI10, including agentic supply chain compromise (ASI04), goal hijacking (ASI01), inter-agent trust escalation (ASI07), and data leakage through tool responses.

**The public-preview constraint.** AGT is in public preview. Microsoft notes that the policy engine and agents share the same process boundary; the production recommendation is to run each agent in a separate container for OS-level isolation. PyPI, npm, and NuGet packages are available; the Python SDK is the most mature.

**Why it matters:** Microsoft's Agent Governance Toolkit is the first open-source attempt at a comprehensive governance layer for autonomous agents. It enters a field where existing controls are fragmented across vendors (Zenity, Obsidian Security, and several others have agent-security features) and where no standard governance layer exists. The OWASP Agentic Top 10 mapping gives enterprise security teams a defensible evaluation framework: if your agent platform does not cover the same 10 items AGT covers, you have a governance gap. The open-source nature means security teams can inspect, adapt, and contribute to the governance layer rather than relying on a vendor's closed implementation.

### ChocoPoC: Trojanized GitHub PoC Exploits Deliver Python RAT Through Malicious PyPI Dependencies — 2,400 Downloads, 7 Repositories Compromised

**Researchers at Sekoia and YesWeHack disclosed on July 1 a campaign in which trojanized proof-of-concept exploit repositories on GitHub deliver a Python-based remote access trojan they've named "ChocoPoC" through a chain of malicious PyPI packages. Seven repositories were identified, hosting exploits for FortiWeb, React2Shell, MongoBleed, PAN-OS, Ivanti Sentry, Check Point VPN, and Joomla SP Page Builder vulnerabilities. The malicious dependency package "skytext" was downloaded 2,400 times, primarily on Linux systems.** ([BleepingComputer](https://www.bleepingcomputer.com/news/security/new-chocopoc-malware-targets-researchers-via-trojanized-poc-exploits/) | [Sekoia](https://www.sekoia.com/blog/dont-eat-the-chocopocs-how-vulnerability-researchers-were-repeatedly-targeted-by-trojanised-exploits/) | [YesWeHack](https://www.yeswehack.com/news/chocopocs-vulnerability-researchers-trojanised-exploits))

**The supply-chain chain.** ChocoPoC does not embed malware in the exploit file itself — a notable evolution from previous campaigns. Instead, the PoC's dependency list includes the malicious package `frint`, hosted on PyPI. During `pip install`, `frint` pulls `skytext`, which contains a compiled native Python extension. When the PoC executes, the extension decrypts embedded Python code that triggers a downloader to retrieve the final ChocoPoC payload from a Mapbox dataset. Mapbox datasets are also abused for data exfiltration; larger file uploads go through a separate HTTP server.

**ChocoPoC's capabilities.** The RAT executes arbitrary shell commands and Python code, uploads files and directories, collects browser passwords/cookies/autofill, searches for text files and markdown documentation, gathers shell history, collects network configuration, and enumerates running processes. The target profile — vulnerability researchers — suggests the campaign's goal is credential theft from researchers who have access to internal networks, cloud environments, and bug-bounty platforms.

**The detection challenge.** Because the malicious package is not in the exploit file but in the dependency list, organizations running automated security scans that check the repository code would miss it. The dependency tree must be pinned and reviewed — not just the top-level package but every package in the dependency graph.

**Why it matters:** ChocoPoC is the fourth documented campaign (following AIR's fake skill, Tenet's agentjacking, and LeoPlatform/Miasma) in which the attack chain does not place malicious code in the obvious location — it is in a fetched URL, a dependency, a DNS record, or an MCP server response. For security teams, the operational principle is that the supply chain for AI development tools now includes PyPI dependencies, npm packages, GitHub Actions caches, Docker registries, and MCP servers — and that "clean repo" is no longer a sufficient security signal.

### FTC Proposed Policy Statement: AI Models With "Hidden Agendas" Could Face Deceptive-Practice Enforcement

**The FTC on July 1 sought public comment on a proposed policy statement declaring that a "hidden agenda" enacted by AI developers — suppressing accuracy or interposing undisclosed ideological objectives in model outputs — could trigger enforcement against deceptive business practices. The proposal takes particular exception to Colorado's recently revised AI governance law (SB26-189), which creates liability for models that produce unlawful discrimination. The FTC argues that such liability incentivizes developers to suppress accuracy while failing to disclose the loss of accuracy.** ([BankInfoSecurity](https://www.bankinfosecurity.com/us-ftc-eyes-ai-model-behavior-in-new-policy-push-a-32135) | [FTC Press Release](https://www.ftc.gov/news-events/news/press-releases/2026/07/ftc-seeks-public-comment-policy-statement-addressing-ai-accuracy))

**Why it matters:** The FTC's proposed policy statement is the first federal regulatory signal that model-behavior enforcement is moving from "safety" frameworks to "accuracy" and "deception" frameworks under consumer protection law. This is distinct from the Commerce Department's export-control approach (Fable 5) and Sen. Warner's AI AGENT Act (agent governance). The Colorado law controversy highlights the tension between federal and state approaches: Colorado imposes liability for discriminatory outcomes; the FTC's proposed statement frames accuracy-suppression as deceptive. For enterprise security teams developing AI governance policies, the regulatory environment now includes three concurrent threads: export controls on model access, agent-accountability legislation, and consumer-protection enforcement against model behavior. Compliance frameworks should track all three.

**1. DuneSlide (CVE-2026-50548, CVE-2026-50549) proves that prompt injection through MCP or web search is now a reliable sandbox-escape vector against Cursor, the most widely deployed enterprise AI coding tool.** Two independent sandbox-bypass routes — one exploiting a `working_directory` parameter, one exploiting a symlink-resolution fallback — both turn a single prompt injection into unconstrained RCE. No download, no click, no approval. Patched in Cursor 3.0 (April 2). If your organization runs Cursor, verify the version immediately. The structural lesson: every agentic IDE with command-execution capability needs to revisit its sandbox architecture. The comparison with Mozilla 0DIN's Claude Code RCE (June 29) is direct: two different tools, two different attack surfaces, same structural conclusion.

**2. Phantom squatting is the first documented attack class where the hallucination itself — not the model's content but its invented-but-plausible web address — is the attack surface.** Unit 42 found 250,000 unowned domains in 2.1M AI-generated links. Attackers are registering them. The fix is not in the model (structural property, "inherently unpatchable") — it is in the application layer: verify DNS before presenting a generated URL. No major AI assistant does this today.

**3. The AI threat-creation bottleneck has shifted: DeepSeek bridged the theory-practice gap for browser-only ransomware, and Check Point says "the expertise needed to discover a new attack path is no longer the bottleneck."** InfernoGrabber v9.0, generated from a single broad prompt, runs entirely inside Chromium and steals credentials, keystrokes, webcam feeds — and encrypts files — on Windows, Linux, macOS, and Android. The structural shift is that AI-driven threat creation now produces novel attack chains, not just automated malware patterns. Threat-intelligence credibility for "novel attack path unlikely to be exploited" should be treated with skepticism.

**4. Microsoft open-sourced the Agent Governance Toolkit (AGT) covering 10/10 OWASP Agentic Top 10 — the first comprehensive open-source governance layer for autonomous agents.** AGT provides policy enforcement, zero-trust identity, execution sandboxing, and SRE for agents. The OWASP mapping gives enterprise security teams a defensible evaluation framework: if your agent platform does not cover the same 10 items, you have a governance gap. The open-source nature means teams can inspect, adapt, and contribute — rather than relying on a closed vendor implementation.

**5. Three regulatory threads are converging on AI model behavior: export controls, agent accountability legislation, and consumer-protection enforcement.** The FTC's proposed policy statement on "hidden agendas" in model outputs (July 1), Sen. Warner's AI AGENT Act discussion draft (June 30), and the Commerce Department's export-control regime for frontier models (June 12–July 1) define three distinct regulatory fronts. For enterprise security teams developing AI governance policies, the takeaway is that compliance is no longer "which model can we use" but "how do we govern model deployment, agent accountability, and model-behavior accuracy simultaneously" — and none of the three frameworks is settled enough to ignore.
