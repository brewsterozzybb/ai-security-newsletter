## 1. Headliners

### Cursor 0day: Mindgard Publishes Full Disclosure of 7-Month-Old Unpatched RCE — Opening a Malicious Repo Executes Code with No Approval

Security research firm **Mindgard** published full technical details of a vulnerability in **Cursor IDE** on July 14 — seven months after reporting it to the vendor on December 15, 2025. The bug is as simple as it is severe: open a malicious repository in Cursor on Windows, and if a file named `git.exe` sits in the project root, Cursor runs it. No click. No approval dialog. No model interaction. Just a clone and an open.

**The mechanism.** When a project loads, Cursor checks several locations for a Git binary. One of them is the workspace itself. Process Monitor logs show `Cursor.exe` spawning the repo-root binary with `git rev-parse --show-toplevel`. The binary runs as the logged-in user with full access to source code, SSH keys, and cloud tokens. Cursor re-executes it as long as the project stays open.

**The precondition is the attack.** An attacker needs no foothold — just a repository anyone can clone. Cloning a stranger's repository is how binaries land on disk, and developers and their AI agents do it all day. Mindgard's proof of concept was Windows Calculator, renamed `git.exe` and committed to the root. Clone, open, done. The screenshot shows Calculator windows stacking up while the project sat open.

**No patch, no CVE, no advisory.** Mindgard's most recent confirmed test was against Cursor 3.2.16 on April 30, 2026. The current release is 3.11, shipped July 10. The Hacker News reviewed all 33 security advisories Cursor has published on GitHub — none covers this issue. Cursor has not responded to the disclosure. The vulnerability is still live in the latest tested version.

**The HN response.** The story hit #7 on Hacker News with 395 points and 185 comments. Community reaction was split between those who see the Windows search-order behavior as a known OS limitation and those who argue that a vendored IDE that claims security awareness must not hand unqualified `git` to the OS search path. The most practical take: "AppLocker or Windows App Control deny rules that block executables by name under workspace roots."

**Why it matters:** This is the most consequential unpatched AI coding tool vulnerability on the market. The attack requires no prompt injection, no agent compromise, no model access — just a cloned repository. The seven-month silence from Cursor sets a troubling precedent for responsible disclosure in the AI tooling ecosystem. Microsoft's VS Code documentation describes the same search behavior, but VS Code does not auto-execute on open. The difference is everything.

### White House Launches "Gold Eagle" Cybersecurity Clearinghouse for AI-Discovered Software Flaws

The Trump administration launched a new AI cybersecurity initiative called **Gold Eagle** on July 14 — a clearinghouse designed to help federal agencies, critical infrastructure operators, and AI companies identify and patch software vulnerabilities discovered by advanced AI models.

**The architecture.** The clearinghouse serves as a central coordination point for vulnerabilities that AI-driven bug-hunting tools discover. As AI models increasingly find deep bugs — like the GhostLock kernel root vulnerability that Nebula Security found using its VEGA tool, or the record 622 vulnerabilities Microsoft patched this month using AI-assisted discovery — the bottleneck shifts from discovery to triage and patching. Gold Eagle aims to compress that bottleneck.

**The policy context.** The initiative follows the June 2026 executive order on AI innovation and security (NSPM-11) and operates alongside the voluntary federal pre-release review process that OpenAI submitted GPT-5.6 to. Together, these three initiatives — the executive order, the pre-release review, and the Gold Eagle clearinghouse — represent the most concrete federal AI security infrastructure to date.

**Why it matters:** This is the first federal infrastructure specifically designed for the AI-discovered vulnerability pipeline. The clearinghouse formalizes what has been an ad hoc process: researchers find bugs with AI, notify vendors, and hope patches ship. For enterprises, Gold Eagle means a new expectation that AI-discovered vulnerabilities in critical software will be centrally tracked and patched on a compressed timeline. Whether the clearinghouse has enforcement teeth or is purely coordinating remains to be seen — but the precedent is set.

### Microsoft Patch Tuesday Record: 622 Vulnerabilities Patched Including Two Active Zero-Days — AI-Driven Discovery Cited

Microsoft released patches for **622 vulnerabilities** on July 2026 Patch Tuesday, the largest single update in the company's history. Two are being actively exploited: **CVE-2026-56155** (ADFS elevation of privilege) and **CVE-2026-56164** (SharePoint Server elevation of privilege, remotely exploitable in low-complexity attacks).

**The AI connection.** The record-breaking count was pre-announced: Microsoft confirmed it has been using AI to accelerate internal vulnerability discovery, and acknowledged that other security researchers and attackers are doing the same. The July release follows a pattern established in June — AI-assisted discovery is producing more vulnerabilities than the traditional patch pipeline was designed to handle.

**CISA urges SharePoint hardening.** CISA separately urged organizations running SharePoint servers to apply additional hardening measures, noting that attackers are also exploiting two recently patched vulnerabilities (CVE-2026-32201 and CVE-2026-45659). The SharePoint CVE-2026-56164 was reported by Google's incident responders and an anonymous researcher.

**The LegacyHive complication.** The patch release was once again followed by "Nightmare Eclipse" publishing a stripped-down proof-of-concept exploit for an unpatched Windows EoP vulnerability dubbed **LegacyHive** — a reminder that the gap between patch release and exploit publication continues to shrink.

**Why it matters:** 622 patches in a single month is not a spike — it is the new baseline. AI-assisted discovery, by both defenders and attackers, is producing vulnerabilities at a rate that traditional patch management cannot keep up with. Organizations that take weeks to deploy patches are now operating on a timeline that is weeks late.

### Claude for Chrome Flaw (CVSS 7.7 / 9.6): Rogue Extensions Can Trigger Gmail, Google Docs, and Calendar Reads

Security researchers at **Manifold Security** disclosed a vulnerability in the **Claude for Chrome** browser extension on July 14 that allows any other browser extension with access to the `claude.ai` DOM to trigger reads of Gmail, Google Docs, and Google Calendar — without the user's knowledge or consent.

**The mechanism.** After Anthropic's response to the ClaudeBleed flaw in May, the extension restricted external callers to nine fixed task IDs. Three of those — `usecase-gmail`, `usecase-gdocs`, and `usecase-calendar` — read the user's email, latest document, and calendar. The weak point is the trigger: the content script listens for a click on a specific element but never checks `event.isTrusted`, the browser flag that distinguishes a real user click from a script-dispatched synthetic one. Any extension whose content script can reach the DOM on `claude.ai` can build the element, set the task ID, and dispatch a synthetic click. The extension treats it as genuine.

**Two severity levels.** With the default "ask before acting" mode, the forged task hits an approval box — Manifold rates this CVSS 7.7 (High). With "Act without asking" enabled, the same task runs silently — CVSS 9.6 (Critical). A second issue, a `?skipPermissions=true` URL parameter that boots straight into `skip_all_permission_checks`, is not remotely reachable today but removes the approval step entirely if another flaw ever exposes it.

**No patch as of July 14.** The Hacker News confirmed both mechanisms remain in v1.0.80, the current release. The one-line fix — rejecting synthetic clicks at the top of the handler — has not shipped.

**Why it matters:** This is an extension supply chain vulnerability. The user does not need to install a malicious extension — any extension already installed that can touch `claude.ai` is a potential vector. For organizations with agents deployed in browser contexts, the "Act without asking" mode is the risk multiplier. Turn it off.

**Sources:** [The Hacker News](https://thehackernews.com/2026/07/claude-for-chrome-flaw-lets-other.html) | [Manifold Security](https://www.manifold.security/blog/claude-for-chrome-extension-bypass)

### CVE-2026-6875: Critical ServiceNow AI Platform Sandbox Escape Enables Unauthenticated Remote Code Execution

ServiceNow has addressed a critical vulnerability in its **AI Platform** — tracked as **CVE-2026-6875** — that allows unauthenticated attackers to escape the sandbox and execute arbitrary code on affected instances. The flaw affects both hosted and self-hosted deployments.

**The technical picture.** The sandbox is designed to isolate untrusted workloads from the broader ServiceNow application environment. A successful escape breaches this isolation, permitting access to resources outside the sandbox's permissions — including connected identity systems, cloud services, endpoint management tools, and internal business applications. ServiceNow has not publicly disclosed technical exploit details, but the advisory notes that the vulnerability can be exploited "under certain conditions" without authentication.

**Patch status.** ServiceNow has deployed security updates to hosted instances. Self-hosted customers must upgrade to fixed versions across the Brazil, Australia, Zurich, and Yokohama family releases. No active exploitation has been reported as of the advisory's last update on July 13.

**Why it matters:** ServiceNow is the central nervous system of enterprise IT operations — identity management, workflow orchestration, CMDB, and incident response. A sandbox escape in the AI Platform means that an unauthenticated attacker can potentially pivot from an AI workload into the full ServiceNow environment. The fact that the platform is frequently connected to cloud providers, directory services, and endpoint management tools makes this a critical patch priority for any organization running ServiceNow.

### Internet-Wide Scanning Campaign Targets MCP Servers, Claude Credentials, and Exposed LLM Endpoints

The SANS Internet Storm Center has detected a widespread scanning campaign actively probing for exposed **Model Context Protocol (MCP)** servers, AI assistant configuration files, and unauthenticated local LLM endpoints. The activity was identified across two weeks of Apache and ModSecurity logs from a small web host.

**The scope.** Researchers found roughly 200 requests tied to AI-agent reconnaissance, with MCP handshake probes originating from **49 separate source IP addresses**. The scans targeted `.claude`, `.cursor`, and `.env` configuration files — the same files that the jscrambler infostealer and countless other attacks now target as a matter of routine. The activity was observed across low-traffic websites that did not appear to host AI infrastructure, suggesting **broad reconnaissance** rather than targeted intrusion.

**What is being probed.** The campaign specifically targets:
- MCP server endpoints for handshake and capability negotiation
- AI assistant credential and configuration files (.claude, .cursor, .env)
- Unauthenticated local LLM endpoints (Ollama, LM Studio, vLLM)

**Why it matters:** This is confirmation that MCP infrastructure is now a routine reconnaissance target. The broad, untargeted nature of the scans — hitting sites that have no apparent AI infrastructure — suggests attackers are building a map of the MCP attack surface. For organizations running MCP servers, even internally, the implication is that the protocol's standard ports and endpoints are now being actively cataloged. Treat every MCP endpoint as discoverable and ensure authentication, rate limiting, and network segmentation are in place.

## 3. Technical Deep Dives

### Google Open-Sources Mantis: A 15-Stage AI Pipeline for Autonomous Vulnerability Hunting, Reproduction, and Patching

Google published **Mantis** on GitHub on July 14 — a stack-agnostic toolkit of fifteen linked coding-agent Skills that let AI agents autonomously find, reproduce, and patch software vulnerabilities. The release packages Google's Big Sleep research capability — which found a memory-safety bug in SQLite before it reached stable release — into a repeatable pipeline any engineering team can install and point at its own repository.

**The architecture.** A supervising agent called `mantis_meta_agent` orchestrates fourteen other agent stages in sequence, archiving results between loops. The stages progress through:
1. Building a persistent knowledge base of the codebase and a living threat model
2. A planning stage targeting specific files
3. A researcher agent sweeping targeted files for flaws
4. Merging duplicate findings and filtering false positives
5. Confirming reproduction in a release build inside an isolated container
6. Attempting a working exploit
7. Assigning a risk score (1-10) to every surviving finding
8. A reflection stage logging lessons for the next run

**Multi-domain support.** Mantis is not limited to application code. Google's documentation lists targets including register-transfer-level hardware designs (SystemVerilog, VHDL), infrastructure configurations (Terraform, Kubernetes access controls), data and ML pipelines (unsafe model serialization formats), and compiled binaries/firmware audited without source.

**The tiering insight.** Google recommends mixing model tiers: cheap, fast models handle triage and deduplication; flagship models handle exploit writing and patching. This is the difference between a scan that finishes overnight and one that never does.

**The critical guardrails.** Google insists that a human must sign off on every result. The documentation is explicit: these agents remain non-deterministic and can invent vulnerabilities that never existed or misjudge whether a patch actually closes the hole. Running the reproduction and patching stages requires sandboxing (gVisor, networking off) and should never be run near production systems.

**Why it matters:** Mantis turns AI-driven vulnerability research from a bespoke research project into a reusable pipeline. For security teams, the tool is both an opportunity and a risk: an opportunity to find bugs in their own code before attackers do, and a risk if teams skip the guardrails and pipe Mantis output straight into a public bug bounty program — recreating the exact reporting mess the toolkit's own warnings were written to prevent.

**Sources:** [AI Insiders](https://aiinsiders.net/article/google-open-sources-mantis-a-15-stage-ai-pipeline-for) | [GitHub — google/mantis](https://github.com/google/mantis)

### Ant Group Open-Sources SingGuard-NSFA: Agent Security Guardrails Targeting the JadePuffer Attack Class

Twelve days after Sysdig documented the first end-to-end AI-agent ransomware operation (JadePuffer), **Ant Group's AI Security Lab** released **SingGuard-NSFA**, an open-source guardrail framework designed to intercept the exact attack sequence that campaign used. The tool is available on GitHub and Hugging Face and runs inline in any autonomous agent pipeline.

**What it blocks.** SingGuard sits between an agent and its tools, evaluating each intended action before it fires. The specific risks it targets map precisely onto what JadePuffer demonstrated:
- Prompt injection attempts
- Sensitive data theft patterns
- Malicious code execution
- Resource abuse
- Permission misuse

**The JadePuffer connection.** The JadePuffer attack — which used an LLM to autonomously break into a Langflow instance, harvest credentials, move laterally to a production MySQL server, encrypt 1,342 configuration items, and leave a ransom note — was notable not for the sophistication of any individual technique but for the complete automation of the full kill chain. SingGuard intercepts at the action loop layer, before autonomous decisions become irreversible.

**The trust caveat.** As of July 14, no independent third-party audit of SingGuard-NSFA's code has been published. The primary risk for teams considering it is supply-chain trust: whether the published code contains hidden functionality. Organizations should review the code before deploying it in production.

**Why it matters:** This is the first purpose-built, auditable open-source tool designed to address the threat class that JadePuffer proved is operational. For teams running AI agents in production — especially those that can execute tool calls against cloud infrastructure — SingGuard provides a reference architecture for agent-level security controls. The release also signals that major fintech players (Ant Group processes over a billion users) are taking agent security seriously enough to open-source their internal tooling.

**Sources:** [TechTimes](https://www.techtimes.com/articles/320508/20260714/ant-group-open-sources-agent-security-tool-days-after-agentic-ransomware-hit.htm) | [BusinessWire](https://www.businesswire.com/news/home/20260712722454/en/Ant-Group-Open-Sources-SingGuard-NSFA-to-Establish-New-Security-Paradigms-for-Autonomous-AI-Agents)

### Praetorian Augustus: Enterprise-Grade Go-Based LLM Security Testing Framework Ships with 210+ Probes

Security firm **Praetorian** released **Augustus** on July 14 — a Go-based LLM vulnerability scanner that tests models against **210+ adversarial attacks** across 47 attack categories, covering prompt injection, jailbreaks, encoding exploits, data extraction, agent attacks, and safety benchmarks. The tool integrates with 28 LLM providers and 43 generator variants.

**Key differentiators.** Unlike research-oriented tools, Augustus is built for production security testing: concurrent scanning via goroutine pools, rate limiting, retry logic, and timeout handling come out of the box. It ships as a single Go binary with no runtime dependencies. The detector suite includes 90+ patterns: pattern matching, LLM-as-a-judge, HarmJudge, Perspective API, and unsafe content detection.

**Why it matters:** The gap between research LLM testing tools and production security testing has been a pain point for security teams. Augustus fills that gap with a tool that runs in CI/CD pipelines, produces actionable vulnerability reports, and is designed for security professionals who need repeatable, auditable testing. The 210+ probe count across 28 providers means teams can test their model supply chain against a consistent adversarial benchmark.

### GitHub Copilot Adds /security-review Command — AI-Driven Vulnerability Scanning in PR Workflows

GitHub added a **`/security-review`** command to the **GitHub Copilot** app in public preview on July 14, bringing AI-driven vulnerability scanning to in-flight code changes. The command runs within pull request workflows, allowing developers and reviewers to request a security analysis of proposed changes before they land.

**The context.** The feature arrives at a moment when AI-generated code is under increasing scrutiny. Research published by Veracode in spring 2026 found that security pass rates for AI-generated code remain stuck at approximately 55% across major languages — nearly identical to where they stood two years earlier. AI-generated Java code performed worst, which researchers attributed to over-training on legacy patterns from public repositories. The `/security-review` command gives teams a way to surface those issues in the review workflow rather than after deployment.

**Why it matters:** Native security review in the PR workflow is the right architectural layer — catching vulnerabilities before they merge rather than scanning after the fact. The feature's effectiveness will depend on the model's detection rate and false positive rate, both of which are unproven in public preview. But the direction is correct: security review embedded at the code review step, not bolted on after.

### Mindgard's Full Disclosure: When 7 Months of Silence Leaves Users With No Protection

The Cursor 0day disclosure (covered in Headliners) deserves a separate note on the disclosure process itself. Mindgard reported the vulnerability to Cursor on December 15, 2025. After seven months with no patch, no advisory, no CVE, and no response from the vendor, Mindgard exercised the full disclosure option — publishing technical details, proof-of-concept code, and mitigations because, as the company wrote, "we have no indication that users are being protected, that remediation is underway, or that affected organizations have been informed."

The story hit **#7 on Hacker News** with 395 points and 185 comments, and the community discussion surfaced a broader concern: the AI coding tool ecosystem lacks any coordinated vulnerability disclosure standard. There is no CNA (CVE Numbering Authority) for AI IDEs, no industry-wide disclosure framework, and no mechanism for escalating unpatched vulnerabilities.

**Why it matters:** The Cursor situation is a case study in what happens when an AI tooling vendor goes silent on a security report. The community's only recourse is full disclosure, which benefits users but also informs attackers. The incident makes the case for an industry-wide vulnerability disclosure standard for AI development tools — the same way the browser vendors coordinate through the Browser Vulnerability Research program.

## 6. Five Things to Take Into the Rest of the Day

1. **Assume Cursor users on Windows are vulnerable today.** The git.exe auto-execution bug has no patch and no workaround from the vendor. If your team uses Cursor on Windows, the only practical mitigations are AppLocker/Windows App Control deny rules blocking executables by name under workspace roots, or opening untrusted repositories in a disposable VM. The attack requires no model interaction — just a cloned repository. This is the most urgent unpatched threat in the AI coding tool space.

2. **Turn off "Act without asking" in Claude for Chrome.** The Claude for Chrome flaw (CVSS 9.6 in hands-off mode) means any extension with access to `claude.ai` can trigger reads of your Gmail, Google Docs, and Calendar. The default approval mode reduces the risk to CVSS 7.7, but the synthetic click bypass is still open. In the "Act without asking" mode, there is no approval step at all. This is a simple config change that materially reduces risk.

3. **Patch ServiceNow AI Platform instances for CVE-2026-6875.** The sandbox escape vulnerability allows unauthenticated remote code execution. ServiceNow is connected to identity systems, cloud services, and endpoint management tools — a sandbox escape in the AI Platform is a potential pivot point into the full enterprise environment. If you run ServiceNow, verify that your hosted instance has received the update, or upgrade self-hosted deployments to the fixed patch levels.

4. **Audit your MCP server exposure.** The SANS ISC scanning campaign confirms that MCP servers and AI assistant config files are being actively probed at internet scale. Check whether any MCP endpoints are exposed without authentication. Review `.claude`, `.cursor`, and `.env` files for exposure. The scanning is reconnaissance, not exploitation — but the follow-on attacks will come.

5. **Evaluate the Google Mantis pipeline — but keep the guardrails in place.** Google's open-source 15-stage AI bug-hunting pipeline is a powerful tool for finding vulnerabilities in your own code. But the documentation's warnings about hallucinated findings, sandbox requirements, and mandatory human review are not optional. Teams that skip the guardrails and pipe Mantis output straight into bug bounty programs will recreate the false-positive flood that the tool was designed to filter. The tiered model approach — cheap models for triage, frontier models for exploit — is the operational insight that makes the tool practical.
