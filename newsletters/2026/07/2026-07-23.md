### RefluXFS: Nine-Year-Old Linux Kernel XFS Race Condition Gives Any Local User Root — Qualys Estimates 16.4M+ Systems Affected

**Qualys Threat Research Unit** disclosed on July 22, 2026 a local privilege escalation in the Linux kernel's XFS filesystem tracked as **CVE-2026-64600**. The vulnerability, a race condition in the handling of reflinked files on XFS volumes, has been latent in the kernel for approximately nine years and allows an unprivileged local user to overwrite the on-disk contents of any readable file on a reflink-enabled XFS volume. Qualys' proof of concept reliably gains host root privileges by surgically modifying `/etc/passwd` or SUID-root binaries — and the exploit works even with SELinux in Enforcing mode, the most restrictive common configuration.

**The attack mechanics.** The bug is triggered when two concurrent O_DIRECT writes target the same reflinked file on an XFS volume. The timing flaw lets the attacker overwrite file contents that the kernel has marked as protected, including files owned by root with restricted write permissions. Because the overwrite happens at the filesystem layer, the OS's permission model is bypassed entirely. Qualys' TRU estimates the affected footprint at more than 16.4 million publicly reachable Linux systems, with the broader footprint (including internal infrastructure) much higher.

**The patch timeline.** Red Hat has published an advisory across RHEL 8 and later, and major distribution kernels are in the process of shipping the fix. The exposure window is the gap between the public disclosure and the patch deployment on internet-facing systems — the standard LPE-to-root exposure window that defenders know to treat as urgent.

**Why it matters:** This is the largest blast-radius kernel LPE in months, and it lands in the same week that attackers are chaining AI-assisted recon with credential reuse (the bandcampro / Trim patterns, the week-old ShareFile emergency) — meaning the same attacker who has a low-privilege shell on a Linux host can now reliably escalate to root with a published PoC. The exposure is not theoretical: any internet-facing Linux host running XFS with reflink enabled (default on most modern distros) is one exploit away from a root compromise. The operational rule for the rest of the day is the same as for any kernel LPE: patch priority-one on all internet-facing XFS hosts, audit `/etc/passwd` integrity on any XFS host that may have been exposed to unprivileged local users, and review sudo/SUID logs for the same window.

### Check Point SmartConsole CVE-2026-16232: Actively Exploited Authentication Bypass to Full Admin — CISA KEV Deadline July 25

**Check Point** released security updates on July 22, 2026 for a critical authentication-bypass vulnerability in **SmartConsole** that is already under active exploitation. Tracked as **CVE-2026-16232** with a CVSS of 9.3, the flaw allows an unauthenticated remote attacker to obtain an application login token and use it to authenticate with full administrative privileges. Check Point VP of Research **Lotem Finkelstein** confirmed the vendor is aware of "a small number of customers being targeted" and has notified them directly. CISA has added the flaw to the Known Exploited Vulnerabilities catalog with a remediation deadline of **July 25, 2026** for Federal Civilian Executive Branch agencies.

**The exploitation shape.** The bypass targets SmartConsole's login process specifically. A successful attacker modifies security policies and security configurations on the management server — meaning the network security infrastructure itself can be reconfigured by the attacker. The flaw only affects a specific configuration: management servers exposed directly to the internet without IP restrictions on trusted clients. That configuration exists in many production deployments where teams have not isolated the management plane.

**The patched family.** Check Point shipped patches for two related flaws in the same advisory — **CVE-2026-62144** (CVSS 9.3), a separate authentication bypass allowing administrative command execution on the Management Server including `run-script` and `exec-command` on Security Gateways; and **CVE-2026-62145** (CVSS 7.5), an improper privilege management flaw in the Gaia Portal allowing read-only users to execute commands with root privileges. All three affect Check Point R77.30 through R82.10. Six IoC IP addresses have been published.

**Why it matters:** The attacker's prize on a network-security-management console is not just a host — it is the entire security policy. An attacker with admin on SmartConsole can open firewall rules, disable inspection, add unauthorized admin accounts, and pivot through any tunnel the firewall terminates. The "configuration-dependent" framing (only affects internet-exposed management) is the same framing the Cisco IOS XE and Ivanti cases used — and in both cases the number of affected deployments in the wild turned out to be much higher than the vendor-acknowledged footprint. The KEV deadline is Friday July 25. For any organization running a self-managed Check Point deployment: patch today, audit SmartConsole access logs for the IP block published in the advisory, and confirm the management plane is not internet-exposed.

### ANSI Escape Sequence Injection in MCP Servers: Hidden From Humans, Visible to AI

**Bright Security** published research on July 23, 2026 documenting a new injection class targeting the Model Context Protocol: **ANSI Escape Sequence Injection (AESI)**. The technique smuggles terminal control codes — invisible to humans on a rendered terminal but fully legible to language models processing raw text — into MCP server outputs, creating an injection surface that human review cannot catch. The research was reported as a fresh HN post (item #14 with 32 points and 14 comments as of this morning).

**The attack mechanics.** ANSI escape sequences are 1970s-era terminal control codes (color changes, cursor movement, text hiding) that begin with the escape byte (`0x1B`). A human reading a rendered terminal never sees the bytes — only the visible effect (the color change, the cleared line). A language model reading the same content sees every byte. An attacker hosts a URL laced with the codes, the MCP fetch-tool retrieves the content, the server relays the raw bytes into a model-consumable field (`result.content[].text`, `result.contents[].text`, `result.messages[].content.text`), and the model reads and obeys the concealed instructions. Two variants are documented: **direct-fetch AESI** (attacker-hosted content fetched at the model's request) and **stored AESI** (the codes are persisted in a resource the agent will read later).

**The CVE precedent.** The class is not new — Kubernetes `kubectl` shipped **CVE-2021-25743** (control sequences in Event strings) and Git shipped **CVE-2024-52005** (remote sideband messages without terminal-control neutralization). Both products now sanitize escape sequences. The MCP ecosystem has not yet implemented the same neutralization. The injection is exploitable in any MCP server that does not strip control bytes from response fields the model will ingest.

**The detection angle.** The research proposes a DAST-based detection methodology. Because whether a payload survives depends on how the live server processes and relays it, black-box dynamic scanning is the natural fit — the scanner exercises the running target, sends crafted inputs, and inspects the actual responses. The article walks through detection of both direct-fetch and stored variants with concrete scanner logic.

**Why it matters:** Every MCP server that fetches URL contents and relays them to the agent is potentially vulnerable. The exposure is invisible to humans by construction — there is no UI to see the attack in. The "Spotlighting delimiter" defense Microsoft added to the Azure DevOps MCP wiki and build-log tools does not catch escape-sequence injection; the delimiter is visible to the model, and the escape sequence payload can be written to operate around the delimiter. For any team shipping or running MCP servers, the immediate action is to add a control-byte neutralization pass (strip `0x1B` and follow-on control characters) on every model-consumable response field, and to add a DAST check that posts a request with embedded escape sequences and verifies the response does not echo them into model-consumable fields.

### Qoder Security: Alibaba Embeds Three Progressive Scan Layers Directly Into the AI Coding Session — 60% More Vulnerabilities, 80% Fewer False Positives

**Qoder**, the agentic coding platform with more than 5 million registered users, launched **Qoder Security** on July 23, 2026 as a built-in capability that runs three progressive layers of security review directly inside the AI coding session. The platform's framing — "we believe security cannot depend on a model's good behavior. It has to be built into the product architecture" — is the strongest public statement yet from a major coding-platform vendor that model-level guardrails are not a sufficient control. The launch pairs a proprietary security LLM with a multi-agent architecture that separates the code-writing agent from the code-reviewing agent.

**The three layers.** Qoder Security runs an escalating cascade to balance cost and depth: **Static Check** does pattern-based screening at generation time (catching hardcoded secrets, known dangerous calls, no latency, no model cost); **Lightweight Scan** triggers after a coding task completes, running semantic analysis on the diff; **Deep Scan** runs the proprietary security LLM over the full repository context, verifying that detected issues are actually reachable before reporting and then driving the fix in-session. Each fix is re-verified on the next scan, closing the loop so no security debt is left behind.

**The "reviewing its own work" architectural choice.** The architecture deliberately separates the agent that writes code from the agent that reviews it, a pattern that addresses the structural risk of a single LLM grading its own output. On the review side, scanning and verification are split between two cooperating agents. The reference framing is a "dedicated security engineer" that reviews, verifies, and fixes while the developer's context is intact.

**The empirical claim.** Qoder cites a July 2026 academic study that applied multi-tier verification to nearly 9,000 C++ programs and found that AI-generated code triggers confirmed runtime violations at roughly twice the rate of human-written code — even after controlling for code length and test pass rates. The Qoder Security pipeline claims a 60% improvement in vulnerability detection and an 80% reduction in false positives compared with traditional solutions. The numbers are vendor benchmarks; independent replication is the natural next step.

**Why it matters:** The Qoder launch is the first major coding platform to embed security natively in the AI coding session rather than as a CI/CD-layer scan. The architecture is a direct response to the FakeGit / AgentBaiting / sandbox-escape threat model covered in the previous two newsletters: the agent that writes code is no longer trusted to be its own reviewer. The pattern — generate-fix-verify loop with a separate review agent and a separate verification step — is the architecture that every coding platform will need to adopt over the next 12 months. The open question is whether the same architecture is composable for non-Qoder agents (Cursor, Claude Code, Codex CLI, Gemini CLI) or whether it is locked to the Qoder platform.

### Anthropic Claude Security Plugin: First-Party Vulnerability Scanner Shipping in Claude Code Beta

**Anthropic** released the **Claude Security plugin** in beta on July 22, 2026, bringing AI-powered vulnerability scanning directly into Claude Code. The plugin is the first first-party security tool Anthropic has shipped for its own agent and is the most direct answer yet to the prompt-injection-and-generated-code-security question raised by every FakeGit / sandbox-escape / supply-chain disclosure of the last 30 days. The launch positions Anthropic in the same vendor-tooling category as Google CodeMender and Capital One VulnHunter, but with the credibility of being shipped by the model vendor itself.

**The architecture.** Claude Security runs as a multi-agent system inside Claude Code. The first agent maps the code architecture; the second identifies potential threats; the third verifies findings to cut false positives; the fourth suggests style-matched patches. The verification step is the structural addition that distinguishes Claude Security from a pattern-matching scanner — it asks "is this finding actually exploitable" before reporting. Humans still review and apply every fix; nothing is auto-committed.

**The two scan modes.** Developers can scan uncommitted changes before a commit, or run a full-codebase analysis from the terminal on the Claude inference they already use. The "from your terminal" framing keeps the workflow inside the developer's existing Claude Code session rather than routing through a separate web UI.

**The cost caveat.** Full-repository scans can drive up token costs and sometimes shift to more expensive models. Anthropic's guidance is to use scoped or incremental runs for routine development, with full-repo scans reserved for security audits. The cost-shaping guidance is honest about the trade-off between scan coverage and inference spend.

**Why it matters:** Claude Security is the first time a frontier model vendor has shipped a first-party security tool for its own agent, and it lands in the same week that the OpenAI/Hugging Face eval-sandbox-escape story (July 22) and the GPT-5.6 Sol GPT-6 briefings (July 22) make the model-vendor-as-security-steward role unavoidable. The "verification before reporting" architecture is the pattern every other agent-tooling vendor will need to adopt — and the fact that it ships in beta is the early signal. For security teams, the immediate evaluation is whether Claude Security reduces false-positive volume enough to be useful in CI/CD, and whether the in-agent workflow (vs. a separate scanner UI) fits the team's developer-experience standards.

### "Trim" Builds AI Pentest Checker From Jailbroken Claude Opus — Russian Threat Actor's Blueprints Become a Criminal Underground Standard

The actor's most recent disclosure includes a modified system prompt leaked from Anthropic's Fable. The Cato CTRL team described Trim's blueprint as the operationalization of the jailbreak-as-a-service category — and as a template the criminal underground is beginning to follow.

**The method.** Trim's jailbreak techniques for Claude Opus include the standard suite: creating a benign context before a harmful request, reframing instructions to focus only on code structure, and retrying softened versions of previously refused prompts. The actor also recommends alternative AI services and locally hosted models as fallbacks when commercial systems refuse — giving the workflow provider-agnostic resilience. **The operationalization.** AI Pentest Checker automates reconnaissance, vulnerability validation, and report generation. The platform is the AI-as-operator pattern that the "bandcampro" case foreshadowed: instead of an AI helping a human write code, the AI is the operator. The reconnaissance-to-report loop compresses what was previously a multi-day human engagement into a session-scale automated workflow.

**The Fable prompt leak.** The latest Trim post includes a modified system prompt leaked from Fable — the Anthropic model subject to the export-control debate in June. **Why it matters:** "Trim" is the second publicly documented case (after "bandcampro") of an AI model being the operator in a criminal workflow — but the first case where the operator product is named, documented, and sold as a platform. The criminal underground has moved from "AI helps me do a thing" to "AI is the thing." The same threat surface is opening up in both directions: defenders are shipping Claude Security, Qoder Security, and CodeMender as agents that find vulnerabilities, while attackers are shipping AI Pentest Checker as agents that exploit them. The capability parity at the model layer means the contest is now at the workflow and infrastructure layer — which is the argument Neo's $100M raise is making on the defender side.

## 6. Five Things to Take Into the Rest of the Day

1. **Patch the Linux XFS kernel LPE to root on every internet-facing XFS host today.** CVE-2026-64600 (RefluXFS) is a 9-year-old race condition, the PoC is public, the SELinux-Enforcing bypass is confirmed, and Qualys estimates 16.4M+ systems are affected. The exposure window is the gap between today's disclosure and your distribution's kernel patch reaching production. Audit `/etc/passwd` integrity on any XFS host that may have been exposed to unprivileged local users in the last 90 days — the attack is silent at the kernel layer.

2. **Check Point SmartConsole: confirm the management plane is not internet-exposed and patch by Friday July 25.** CVE-2026-16232 is actively exploited, CISA KEV, and the prize for an attacker is full reconfiguration of the network security policy. The configuration-dependent framing (only affects internet-exposed management) is the same framing Cisco IOS XE and Ivanti used — the actual exposed footprint is consistently larger than the vendor-acknowledged count. Audit SmartConsole access logs for the six published IoC IPs, and treat any successful SmartConsole login from a non-trusted IP in the last 30 days as a high-confidence incident.

3. **Add control-byte neutralization to every MCP server that returns user-controlled text to a model.** The Bright Security research on ANSI escape sequence injection is a published technique with a public PoC pattern, and the same class of vulnerability was patched in Kubernetes and Git. The neutralization is straightforward — strip `0x1B` and follow-on control characters from any text field that ends up in a model-consumable response. If you ship an MCP server, this is the patch that needs to ship this week. If you run third-party MCP servers, file the issue and add a DAST check to your agent supply-chain verification.

4. **Shut down ShareFile Storage Zone Controllers per Progress's urgent advisory.** The vendor has not yet published a CVE, which is the operational signal that the threat is still being characterized. The MOVEit precedent says the CVE and patch will follow within days, and that the exploitation window is "in the wild right now." Route document exchange through a secondary channel or pause the workflow until the patch is available.

5. **Treat the agent as the security product, not just the security surface.** Today's announcements — Neo's $100M agent-governance raise, Anthropic's Claude Security plugin beta, Qoder's three-layer in-session security, Google's CodeMender + Gemini 3.5 Flash Cyber, Capital One's VulnHunter, NVIDIA's SkillSpector — are not seven separate products. They are the first wave of a structural shift: the AI agent is moving from attack surface (FakeGit, sandbox escapes, MCP injection) to control surface (the agent that finds, verifies, and fixes vulnerabilities is the same agent that runs the workflow). The procurement question for the rest of 2026 is not "which agent is safe to use" — it is "which agent do we want watching the others, and what is the audit trail when it does."
