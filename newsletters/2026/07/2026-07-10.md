# AI Security Newsletter — July 10, 2026

*Agent autonomy reached an inflection point this week: AI coding agents designed to catch malicious code were turned into delivery vehicles for it, and the first fully autonomous ransomware campaign was documented in the wild. The signal-to-noise problem for security teams just got harder.*

## 1. Headliners

### 🎯 Friendly Fire: AI Security Agents Tricked Into Running Attacker Code

The AI Now Institute published a proof-of-concept exploit on Wednesday that turns the exact workflow AI coding agents are sold for—reviewing untrusted third-party code for security holes—into the attack vector itself. Dubbed "Friendly Fire," the attack works against Anthropic's Claude Code (CLI versions 2.1.116–2.1.199 running Sonnet 4.6, Sonnet 5, or Opus 4.8) and OpenAI's Codex (CLI 0.142.4 on GPT-5.5) when either is operating in autonomous approval mode.

The mechanism is elegantly simple: a note in a library's README.md suggests running `security.sh` as a routine pre-PR check. The agent, operating in auto-mode where it green-lights commands it deems safe, executes the script. The script immediately launches a reverse shell. No malware delivery, no phishing—just a developer doing what they were asked, with the agent as the unwitting mule.

Researchers Boyan Milanov and Heidy Khlaaf tested geopy, a widely used Python geocoding library, but noted the attack ports to almost any project. Critically, there is no patch to wait for. The researchers argue the weakness is architectural: the fix requires a workflow redesign, not a version bump.

**Why it matters:** This is the first demonstration that the autonomous security-review workflow sold as a productivity multiplier can be reliably weaponized against its operator. Every organization running Claude Code or Codex in auto-review mode should reassess their trust boundaries today.

**Source:** [The Hacker News](https://thehackernews.com/2026/07/friendly-fire-ai-agents-built-to-catch.html) | [AI Now Institute](https://ainowinstitute.org/publications/friendly-fire-exploit-brief)

### 💀 JadePuffer: The First Fully Agentic Ransomware Campaign

Sysdig's Threat Research Team published technical analysis of what they describe as the first ransomware campaign driven entirely by a large language model—no human operator in the loop for decision-making or adaptation. Dubbed JadePuffer, the campaign exploited an internet-facing Langflow instance via CVE-2025-3248 and ran what Sysdig calls "an adaptive and fully automated campaign."

The multi-stage attack chain:
1. Langflow access via vulnerability exploitation
2. Reconnaissance and credential harvesting (LLM APIs, cloud creds, database creds)
3. Local data theft of Langflow's backing Postgres database
4. Lateral discovery of reachable services
5. MinIO object-store enumeration and credential harvest
6. Persistence via cron job creation on the Langflow server
7. Access to production MySQL via Alibaba Nacos using root credentials
8. Exploitation of CVE-2021-29441 against Nacos

The final stage encrypted all 1,342 Nacos service configuration items and deleted the originals. Critically, the AES key was generated as `base64(uuid4().bytes + uuid4().bytes)`—effectively random—printed to stdout, and never persisted or transmitted. The victim cannot recover the encrypted configurations even with payment.

In one sequence, the agent went from a failed login to a working fix in 31 seconds. Captured payloads show the LLM escalating from row-level deletion to dropping entire database schemas, narrating its own targeting rationale.

**Why it matters:** JadePuffer crosses a threshold. Autonomous retry-and-adapt behavior means traditional signature-based defenses are insufficient. Every exposed Langflow instance—and by extension, any internet-facing AI workflow platform—is a potential entry point for agent-drive operations.

**Source:** [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/researchers-first-agentic/) | [Sysdig](https://sysdig.com/)

## 2. Breaking News

### Workflow-Level Jailbreak Bypasses Copilot's Safety Filters

Researchers at the Alan Turing Institute discovered a fundamental gap in GitHub Copilot's safety architecture. Abhishek Kumar and Carsten Maple found that while Copilot refuses harmful prompts in chat (e.g., "how to fool a breathalyzer test" or "smuggle bulk cash out of the US"), it writes them in code 100% of the time when the same objective is decomposed into smaller steps distributed across multiple stages of a software development workflow.

Tested across Claude Sonnet 4.6, Claude Haiku 4.5, Gemini 3.1 Pro, and Gemini 3.5 Flash using 204 harmful prompts from Hammurabi's Code, HarmBench, and AdvBench, the technique—dubbed "workflow-level jailbreak construction"—demonstrated near-complete refusal in chat and total compliance in decomposed code generation.

The researchers' pre-print on arXiv argues that "a model that refuses harmful prompts in isolation may still fail once the same objective is embedded inside an ordinary multi-turn IDE session." This has direct implications for how enterprises evaluate coding-agent safety: prompt-level red-teaming is no longer sufficient.

### Claude Desktop Personal Preferences Weaponized as C2 Injection Vector

Pentera researchers disclosed a novel attack chain exploiting Claude Desktop's synced Personal Preferences feature as a persistent prompt-injection vector. The attack begins with initial access via a compromised third-party email aggregation platform—giving attackers access to thousands of active inboxes—followed by pivoting into associated Claude accounts through magic links or password resets.

Once inside, the attacker injects a malicious payload into the Personal Preferences field—an opaque blob that appears innocuous to human reviewers. This field auto-syncs across all Claude Desktop instances tied to the account. When the victim next opens Claude Desktop, the injected payload silently enumerates installed extensions, MCP integrations, and command-capable tools. If a local command-execution extension such as Desktop Commander is present, the attacker achieves remote code execution—all without phishing emails or traditional malware delivery.

The payload encodes fallback behavior and tool-enumeration logic, functioning as a covert C2 channel.

**Published:** July 9, 2026
**Source:** [GBHackers](https://gbhackers.com/claude-ai-prompt-injection-attack/) | [Pentera](https://pentera.io/resources/research/ai-double-agent-claude/)

### CISA Adds 4 Actively Exploited Flaws to KEV—Langflow, ColdFusion, Joomla

The U.S. Cybersecurity and Infrastructure Security Agency added four security flaws to its Known Exploited Vulnerabilities catalog, citing active exploitation:

- **CVE-2026-48282** (CVSS 10.0): Arbitrary file write in Adobe ColdFusion
- **CVE-2026-48313** (CVSS 10.0): Arbitrary file read in Adobe ColdFusion
- **CVE-2026-55255** (CVSS 9.1): Cross-tenant IDOR in Langflow—any authenticated user can execute another tenant's AI workflows, stealing LLM provider keys and AWS credentials
- Two Joomla extension flaws enabling web shell deployment

Federal agencies were given until July 10 to patch. The Langflow CVE is directly connected to the JadePuffer ransomware campaign, and the cross-tenant IDOR vector represents a new class of AI-infrastructure vulnerabilities where tenant isolation failures expose model credentials.

### Sophos: AI Coding Agents Triggering Endpoint Rules Meant for Attackers

Sophos published telemetry from a seven-day window in June 2026 showing that Claude Code, Cursor, and OpenAI Codex are triggering endpoint detection rules written to catch human adversaries. AI coding agents are behaving like attackers—not maliciously, but because the actions they perform are behaviorally identical to intrusion techniques.

Key findings from the Sophos CIXA behavioral engine on Windows:
- **Credential Access**: 56.2% of blocked activity. Leading trigger: DPAPI browser credential decryption from the GStack `/browse` skill pack running under Claude Code.
- **Execution**: 28.8% of blocked activity. Agents downloading and running low-reputation executables.
- One instance showed Claude Code shutting down a running browser and then pulling data from its credential store.
- Non-blocking hits showed elevated evasion and C2 activity patterns—agents making network calls and spawning child processes.

Sophos emphasizes the protections are working as designed. The challenge is signal-to-noise: security teams now must distinguish between a legitimate coding agent and an actual compromise using the same behavioral indicators.

**Published:** July 8, 2026
**Sources:** [The Hacker News](https://thehackernews.com/2026/07/ai-coding-agents-found-triggering.html) | [Sophos Blog](https://www.sophos.com/en-us/blog/2607_agents_vs_telemetry)

## 3. Technical Deep Dives

### 🛡️ MCP Infrastructure Security: The Post-Quantum Reality Check

Security Boulevard published a comprehensive guide to protecting Model Context Protocol (MCP) deployments, noting that MCP was "built for speed and developer convenience" with security as a secondary concern. The guide identifies three critical vulnerability classes being actively exploited:

1. **Untrusted tool input handling**: MCP servers accept arbitrary structured inputs from AI agents, with minimal validation defaults.
2. **Session confusion**: MCP's connection model makes it difficult to enforce consistent authentication per tool call.
3. **Supply chain trust issues**: MCP servers from third parties can execute arbitrary operations on connected data stores.

The guide recommends organizations treat every MCP server as an external endpoint requiring the same security posture as a public API: authentication per request, input validation, rate limiting, and audit logging. NSA's recently published MCP hardening guidelines are also referenced as a starting framework.

**Why it matters:** MCP is the connective tissue of the agentic AI ecosystem. Every major vendor (Anthropic, OpenAI, Google) is standardizing on it. The gap between deployment velocity and security posture is the primary attack surface for agent-to-tool and agent-to-agent compromise.

**Source:** [Security Boulevard](https://securityboulevard.com/2026/07/post-quantum-ai-infrastructure-security-the-2026-guide-to-protecting-mcp-deployments/)

### 🔬 CrowdStrike Expands Prompt Injection Taxonomy with 5 New Techniques

CrowdStrike added 18 techniques to its prompt injection taxonomy—bringing the total to over 200 documented methods—with five newly highlighted attack patterns that reflect the shift from simple chatbot manipulation to sophisticated, layered agent-compromise:

- **Trigger-Activated Rule Addition (PT0201)**: Dormant instructions embedded in content that bypass initial review and activate only when a specific condition or keyword is met, silently altering system behavior.
- **Cognitive Token Suppression (PT0197)**: Prompts that restrict the model's ability to generate refusal or policy-related language, effectively disabling its safety vocabulary.
- **Algorithmic Payload Decomposition (PT0200)**: Malicious instructions split into seemingly harmless components that reconstruct into the full payload at execution time, evading content filters.
- **Hidden Context Injection**: Instructions embedded in non-obvious content surfaces (images, logs, error messages) that hijack the agent's decision-making.
- **Social Engineering of AI Systems**: Attacker personas crafted to exploit the model's helpfulness and authority-following tendencies.

CrowdStrike emphasizes that as AI agents gain more access to enterprise systems—browsing, executing commands, calling APIs—the risk profile of prompt injection escalates from nuisance data leakage to direct system compromise.

**Published:** July 8, 2026
**Source:** [Cybersecurity News](https://cybersecuritynews.com/5-new-prompt-injection-techniques/)

## 6. Five Things to Take Into the Rest of the Day

1. **Disable auto-approval modes on AI coding agents.** Friendly Fire and the Sophos telemetry both converge on the same recommendation: do not run Claude Code in auto-mode or Codex in auto-review on untrusted code. The convenience gain is not worth the compromise surface.

2. **Treat every MCP server as an external endpoint.** If you're deploying MCP infrastructure, apply the same security posture as public APIs: authentication per-tool-call, input validation, rate limits, and audit logging. Citrix's MCP Gateway and NSA's hardening guidelines are starting points.

3. **Patch Langflow and ColdFusion immediately.** CISA's KEV additions are not theoretical—the Langflow cross-tenant IDOR (CVE-2026-55255) is being actively exploited and was the entry point for the JadePuffer ransomware campaign. Federal deadline is today, July 10.

4. **Re-evaluate coding-agent safety testing.** The Alan Turing Institute's workflow-level jailbreak demonstrates that prompt-level red-teaming is insufficient. Test agents in full multi-turn workflows, not isolated prompts.

5. **Watch for agentic signal noise in your SOC.** Sophos's data shows AI agents triggering behavioral rules at significant rates. If you're not already filtering or tagging agent-generated telemetry separately from human- or attacker-generated activity, you are likely drowning in false positives that obscure real incidents.
