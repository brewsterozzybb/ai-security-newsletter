## 1) Wiz: an AI agent "was running the entire operation" in cloud intrusions (AI-native; vendor incident response)

**What changed:** Wiz's [write-up](https://www.wiz.io/blog/anatomy-of-ai-driven-cloud-attacks) (**Mon 7:26 AM**) says that in "several recent intrusions" an agent ran everything, including debugging its own scripts. One entry point was Java RCE in an exposed Kafka UI. It took credentials via IMDS, ran commands over AWS SSM, created a `probe` IAM user to assume OrganizationAccountAccessRole, made itself an IdP admin with a stolen API key, pushed Kubernetes manifests through GitOps, and exfiltrated to webhook[.]site. The same source scanned 600+ other Wiz customer environments.

**Fingerprints (per Wiz):** `pentest`/`probe`/`recon`/`redteam` naming ("likely" to bypass model guardrails), numeric task IDs with letter-suffix retries, and heavily commented generated code.

**Evidence type:** vendor IR observation. No victims, dates, actor or model are named, and the AI attribution rests on behavior. The post ends in product pitches. **Action:** alert on these patterns across cloud, IdP and CI/CD logs; after a foothold, assume every reachable credential is exposed.

## 2) Google Agent Mesh: two critical MCP-gateway authorization bypasses get CVEs (CVE-style main 1 of 3; AI-native; formalization of September advisories)

**What changed:** Only the CVE publication is in window: Google's CNA published [CVE-2026-102503](https://nvd.nist.gov/vuln/detail/CVE-2026-102503) and [CVE-2026-103091](https://nvd.nist.gov/vuln/detail/CVE-2026-103091) (**Sun 11:16 PM**, CVSS v4.0 9.3 each). The repo advisories date from Sep 4 and Sep 6, and fixes shipped in pre-release alphas.
- **102503:** the unauthenticated `/libp2p-http` ingress skipped Biscuit policy. Any peer could invoke backends "including command/stdio-backed MCP servers, A2A, and inference endpoints." Affects alpha.1–alpha.2; fixed in 0.1.0-alpha.3.
- **103091:** public OIDC config plus open `/register` let an attacker "self-enroll into the mesh and invoke arbitrary tools across all connected MCP backend nodes." Affects alpha.1–alpha.8; fixed in alpha.9.

**Evidence type:** official advisory; no exploitation reported, and the deployed base is likely small. **Our read:** these are textbook MCP-gateway failures, a side door around policy and open enrollment. **Use:** add both to MCP gateway review checklists, and confirm adopters are past alpha.9.

## 3) ConnectWise Cloud Backup (ex-SkyKick): services still suspended after an M365 app-credential compromise (general cyber; observed abuse, MSP emergency; event in the gap)

**Background (gap):** Huntress reported Oct 16 that a Cloud Backup app credential pulled Graph tokens in 162 customer M365 tenants (not re-checked).

**What's new in window:** ConnectWise's [advisory](https://www.connectwise.com/company/trust/advisories) was updated Sunday at 12:00 PM, 2:45 PM and **9:15 PM** (01:15Z). Containment is holding, and ConnectWise says it "ha[s] not observed successful threat activity" since mitigations. Cloud Backup, SaaS Security and Cloud Management remain suspended, and restores are unavailable with no restoration time. It added IPs **144.172.64[.]99** and **.60** alongside .128. The next update is due Mon 9:00 AM.

**Evidence type:** vendor advisory + researcher-observed abuse; no attribution. **Action:** apply ConnectWise's remediation guide in every managed tenant and hunt M365 logs for all three IPs. Check other apps for credentials added during the intrusion.
