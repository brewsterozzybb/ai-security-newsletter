## 1) Cloudflare: GLM-5.3 on Workers AI returned other customers' data via a KV-cache bug (AI-native; vendor incident report)

**What changed:** [Cloudflare](https://blog.cloudflare.com/kv-cache-exposure-remediation/) (Mon 6:01 PM) says that between Aug 27 and Sep 9, "155 responses were affected, all to prompts longer than 681,280 tokens," and contained data from other customers' recent requests. It deployed a 1,048,576-token context window on a prefill KV pool that held 681,280 tokens, and was "aware of this mismatch before launch." In SGLang's disaggregated prefill/decode mode, an over-length prompt was swapped for a one-token placeholder instead of aborted, so decode read stale cache pages. Knostic's Gadi Evron reported it Sep 8.

**Limits:** only the disclosure is in window; the leak ran Aug 27–Sep 9. SGLang's [post](https://www.lmsys.org/blog/2026-10-26-cf-security/) (date-only) is a coordinated co-disclosure, not independent confirmation. "No evidence of deliberate exploitation" and the 155 count are Cloudflare's own; it hasn't said what data leaked. **Action:** if you run or buy SGLang-style disaggregated serving, check context length vs KV-pool size and ask providers how KV cache is isolated per tenant.

## 2) Follow-up (Oct 26): PHP2Shell is on KEV, due Oct 29 (CVE main 1 of 3; exploited)

**What changed:** CISA's [KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) (JSON v2026.10.26, released Mon 6:24 PM) added CVE-2026-109618 and CVE-2026-109619 on Oct 26, due **Oct 29**, with forensic triage required. **This corrects Monday's "not on KEV" line, which was accurate at 8:27 AM Monday.** CISA's [alert](https://www.cisa.gov/news-events/alerts/2026/10/21/critical-vulnerabilities-php-require-immediate-patching) (revised Oct 26) says systems that can't update, or run PHP 8.1 or older, "should take PHP-based systems offline." [CERT-FR](https://cert.cyber.gouv.fr/alerte/CERTFR-2026-ALE-014/) (Oct 26, date-only) reports exploitation *attempts* against specific deployments.

**Limits:** no actor, victim or method named. CVE-2026-115560 is still **not** on KEV and still unpatched (config mitigation `session.upload_progress.enabled=0` only). **Action:** patch or take PHP offline by Thursday; run forensic triage on anything exposed before patching.

## 3) Warp: CEO says an "agent swarm" exploited a vendor and reached agent trace data (AI tooling; single source, CEO statement)

**What changed:** Warp CEO Zach Lloyd [posted](https://x.com/zachlloydtweets/status/2114800787716972873) (Mon 3:26 PM) that on "Friday" Warp found "exploitation of a vendor in Warp's infrastructure." The attack "appears to have come from an agent swarm" and accessed "a limited amount of agent trace and telemetry data." "An upper bound of roughly 1% of Warp users may have been impacted." Warp is working with CrowdStrike on the investigation.

**Limits:** a CEO social post only. The vendor and flaw are unnamed, and "agent swarm" is an early company assessment. No advisory or CrowdStrike comment. **Action:** treat agent traces as sensitive stores; if notified, rotate secrets that passed through Warp agent sessions.

## 5) JFrog: the "testmetest" npm worm armed 42 GitHub repos with AI-coding-assistant hooks (AI-native supply chain; vendor research)

**What changed:** [JFrog](https://research.jfrog.com/post/beyond-testmetest-42-hijacked-github-repos/) found "42 armed third-party GitHub repositories across 11 legitimate owners," with "execution hooks for AI coding assistants and IDEs." Claude, Gemini, Cursor and VS Code hooks run `.github/init.js`; 12.9–13.7 MB payloads evaded GitHub code search. SafeDep had found no victims as of Oct 22; JFrog calls its own work complementary.

**Timing:** JFrog's post is date-only (Oct 26), so it may predate the window. In-window anchor: [The Register](https://www.theregister.com/security/2026/10/26/worm-armed-42-github-repos-by-hiding-a-payload-too-big-to-fail/5305570) (Mon 6:29 PM). **Limits:** victim owners unnamed; JFrog doesn't say hooks fired on developer machines. **Action:** check repos for unexpected `.claude/settings.json`, `.cursor/mcp.json` or `.vscode/tasks.json` hooks.
