## 1) Swarmchasers: Tencent Cloud–linked agent fleet scraping Amap via urlquery (preliminary)

**What changed:** The [report](https://swarmcha.se/posts/chinese-agent-fleet) is dated **4 Oct**; evidence to **00:45Z Oct 5** (8:45 PM ET Oct 4), updated **10:45Z** (6:45 AM ET). Per the authors:
- Parallel agents (no observed coordination) used urlquery.net as a browser to pull navigation/entrance shares for Chinese parks, museums, zoos, and hospitals, reusing [Transluce-documented](https://transluce.org/agent-activity) techniques (background): httpbin-encoded programs, relays, webhook.site inboxes.
- First Amap scan **Sep 28** (three days after OpenAI's tool-use pause — background). Peak **Oct 4: 1,810 reports on 213 places**.
- Code reached webhook.site from **Tencent Cloud (Hong Kong)** via proxy **`hysandbox-ats`**; 15/16 readable inboxes from Tencent Cloud.
- 211 reports labeled "claude," but stylometry favors **Tencent Hy / Zhipu GLM**.

**Evidence type:** researcher observation, preliminary (full report promised). **Limits:** Tencent attribution is the **authors' inference** (proxy name + cloud + geography). They note: no model/job ID; `Via` is self-reported; anyone can rent Tencent Cloud; model tests were small. No Tencent/Amap/urlquery statement found. Per the authors, agents worked around Amap protections (most scripts generated Alibaba anti-bot tokens; at least 8 sent Amap-set cookies to an inbox or echo service); "Published keys, not stolen ones," except a fourth key they found nowhere (only its paired security code is in a public company repo). No intrusion claimed.

**Why it matters:** Public example that urlquery-style agent tradecraft isn't one-lab-only — independent runs, shared egress, open scanners as infrastructure, wrong self-labels. **Question:** do bot/API-abuse controls correlate on shared upstream infrastructure, or only per-session?

## 2) SciPhi R2R: hard-coded JWT + `api_base` SSRF (researcher PoC: forwards OpenAI key) (CVE-2026-105147 / -105148)

**What changed:** NVD **Oct 4** 9:16 AM ET (GHSAs 11:30 AM) for **R2R ≤3.6.6**:
- **[CVE-2026-105147](https://nvd.nist.gov/vuln/detail/CVE-2026-105147)** ([GHSA-hw45-xf9v-jg9c](https://github.com/advisories/GHSA-hw45-xf9v-jg9c)): default/hard-coded JWT HMAC secrets (researcher PoC: forged admin tokens).
- **[CVE-2026-105148](https://nvd.nist.gov/vuln/detail/CVE-2026-105148)** ([GHSA-2j4q-255p-4658](https://github.com/advisories/GHSA-2j4q-255p-4658)): SSRF via `generation_config.api_base` on `/v3/retrieval/completion` and `/v3/retrieval/agent`; researcher says it **forwards the OpenAI API key**.

**Scores conflict:** researcher gists rate JWT **9.8** (v4 9.3) and SSRF **8.6** (v4 9.2); CNA (VulDB) scores both **7.3** v3.1 / **5.5** v4.0. VulDB: vendor non-response. PoC gists ([JWT](https://gist.github.com/DReazer/6bc4f88053ec35f8358395bcc0d1a0bb), [SSRF](https://gist.github.com/DReazer/6c1fd0ef98900fbbfa383faa20f731f6)) date to **Aug 26** (background) — Oct 4 is formalization, not discovery.

**Evidence type:** official advisory (NVD/GHSA). **Limits:** unreviewed GHSAs; NVD Deferred; **no fixed release found** (PyPI 3.6.6, Aug 2025, still affected; GH tag v3.6.5; last push Nov 2025); no exploitation reported.

**Action:** Inventory R2R for default secrets / exposed `/v3/retrieval/*`; rotate secrets; restrict egress.

## Take into the day / Worth keeping

1. **Agent fleets may not coordinate — cluster by shared egress.** Swarmchasers saw no inter-agent coordination; the link was one cloud (inboxes created from Tencent Cloud), a self-labeled proxy (`hysandbox-ats`), and one proxy process serving both campaigns. Each inbox served one place. **Use:** detection idea / workshop question. **Source:** [Swarmchasers](https://swarmcha.se/posts/chinese-agent-fleet), Oct 4–5. **Limits:** preliminary; `Via` spoofable; not validated detection. **Tags:** `agent-fleet`, `egress-attribution`.
2. **Model self-labels ≠ attribution.** 211 "claude"-labeled reports were, per authors, another model family. **Use:** presentation / IR-triage check. **Source:** Swarmchasers Oct 4–5. **Limits:** authors' own stylometry = inference on small tests. **Tags:** `ai-attribution`, `ir-triage`.
3. **User-controllable LLM base URL = credential-forwarding SSRF.** R2R `api_base` + NextChat `x-base-url` formalized same window. **Use:** assessment check — can a request override the provider endpoint while the gateway attaches its key? **Source:** NVD Oct 4–5. **Limits:** R2R key-forwarding = researcher PoC claim; no exploitation reported. **Tags:** `llm-gateway-ssrf`, `api-key-exfil`.
4. **Delegated lookup access needs volume limits + anomaly alerts.** Denmark CPR: one company's lawful access misused at national scale. **Use:** workshop question — "If one partner/agent credential were abused, how many records before anyone noticed?" **Source:** CPR/UFM/Datatilsynet Oct 5. **Limits:** method details not public; agent-identity mapping = analyst inference. **Tags:** `third-party-access`, `rate-limits`.
