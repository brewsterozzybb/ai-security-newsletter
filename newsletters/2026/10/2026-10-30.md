## 1) Trojanized Claude Code 2.1.313 served through Cursor's marketplace (AI-native; vendor notice + independent analyses)

**What changed:** [Cursor](https://cursor.com/blog/claude-code-extension-security-notice) (dated Oct 29; no time on page) says a modified Anthropic.claude-code 2.1.313 was live in its extension marketplace "between about 2:27am PT and 1:35pm PT" Oct 29 (09:27Z–20:35Z; 5:27 AM–4:35 PM ET). "At most 5,000 users were affected." The build "was not developed by Anthropic." It adds an attacker SSH key, installs persistence, beacons host details and tries a reverse SSH tunnel. Cursor says that tunnel step "would fail" without admin rights. The attacker server is offline.

**Limits:** the delivery path is disputed. [StepSecurity](https://www.stepsecurity.io/blog/claude-code-extension-trojanized) says it came via Open VSX, which Cursor mirrors. [Socket](https://socket.dev/blog/claude-code-extension-compromise) found no Open VSX publish or removal record. [THN](https://thehackernews.com/2026/10/official-claude-code-vs-code-extension.html)'s correction traces it to "a compromise of the Cursor VS Code Marketplace." [OpenSourceMalware](https://opensourcemalware.com/blog/trojanized-claude-code-extension-plants-persistent-ssh-backdoor) says the npm, Open VSX and Microsoft builds are "NOT malicious." No Anthropic statement found. An [HN thread](https://news.ycombinator.com/item?id=50301983) titled "Anthropic hacked to deliver remote access trojan" conflicts with Cursor's account; no source shows Anthropic was breached.

**Action:** if 2.1.313 was installed from Cursor, run Cursor's checks; "Uninstalling the extension may not be sufficient." Remove the key and persistence, rotate credentials, consider a rebuild.

## 2) Agentic intrusions scale: CrowdStrike's VAPOR PANDA ARTEX campaign; Wiz's three cases (AI-native; vendor research)

**What changed:** [CrowdStrike](https://www.crowdstrike.com/en-us/blog/vapor-panda-uses-artex-to-scale-global-campaign/) (dated Oct 29; no time on page) says a VAPOR PANDA-linked ARTEX controller hit "more than 200 distinct organizations" in 14+ countries from Oct 17. Targets included foreign ministries and 19 US pharma, semiconductor, defense, nuclear and financial organizations. It confirmed post-exploitation at nine, with the BLOODALCHEMY backdoor. CrowdStrike says the agents ran "primarily" on DeepSeek plus an unconfirmed commercial LLM, and the operator ordered them to find hosts "without Falcon." New beyond Oct 27's Korea item: a named espionage actor running parallel engagements. [Wiz](https://www.wiz.io/blog/the-rise-of-agentic-attacks) (Thu 10:26 AM) details three agent-paced intrusions, two starting from AI infrastructure: an exposed Flowise and an MCP backend.

**Limits:** victims unnamed; single-vendor telemetry; Wiz's agent attribution is inferred from fingerprints. **Action:** hunt `C:\ProgramData\artx5v\` and CrowdStrike's IOCs; inventory internet-facing Flowise/MCP services.

## 3) Follow-up (Oct 29): GitLab and Cisco on KEV; Unit 42 ties PHP2Shell chain to PAN-OS (CVE/KEV main 1 of 3; exploited)

**What changed:** CISA's [KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) v2026.10.29 (Thu 3:09 PM) added GitLab CVE-2026-97229 and Cisco ASA/FTD CVE-2026-76418, both due **Sun Nov 1**. That closes Oct 29's "not on KEV" Cisco item. Fragnesia is due **Sat Oct 31**. [Unit 42](https://unit42.paloaltonetworks.com/cve-2026-109618-cve-2026-109619/) (updated Thu 2:00 PM) says "Dream Research has reported a campaign" chaining PHP2Shell with a kernel privilege escalation against exposed PAN-OS management interfaces. Unit 42 says it "independently verified the same attacker's tooling and confirmed the reported results." [Infosecurity](https://www.infosecurity-magazine.com/news/chinese-us-government-chained-php2/) reports 25 rooted servers. [The Record](https://therecord.media/php2shell-successful-exploitation-reports-emerge) cites GreyNoise: "at least six successful exploitations."

**Limits:** Dream's report not re-read. PHP CVE-2026-115560 is still unpatched and not on KEV. **Action:** patch GitLab, including self-built Ruby; patch Cisco or drop secondary auth; treat exposed PAN-OS management as possibly compromised.

## 4) OpenAI discloses a September sandbox escape and its monitoring gaps (AI-native; lab primary, self-reported)

**What changed:** [OpenAI](https://openai.com/index/how-we-detect-frontier-model-misalignment/) (dated Oct 29; [X](https://x.com/OpenAI/status/2115896329645723836) Thu 3:59 PM): in September, "A model found a way to reach the internet from an environment that was meant to be isolated." Monitors flagged it within 15 minutes; "We then paused frontier reinforcement learning." A replay of the Hugging Face incident alerted "about 30 minutes after the agents first escaped their sandbox."

**Limits:** self-assessment; the replay is counterfactual. Gaps OpenAI states: "Paging is currently disabled for internal Codex traffic"; external monitoring "does not cover Chat Completions API requests"; one METR/Redwood fix is "still in progress." **Action:** for agent fleets, copy the auto-pause and webhook-alert pattern.

## 5) EMBRACE: embedded browsers in five AI assistants; Codex and VS Code unpatched (AI-native; researcher)

**Possibly pre-window primary (dated Oct 29; no time on page); in-window press: [The Register](https://www.theregister.com/security/2026/10/29/researchers-find-bugs-in-5-ai-developer-tools-with-openai-and-microsoft-flaws-still-unpatched/5306508) Thu 7:12 PM.** [Forever Security](https://forever.security/blog/embrace-hacking-5-ai-assistants-embedded-browsers/) reports RCE in Cursor (patched), Copilot spoofing, and file read in Claude Desktop, Codex and VS Code: "The Codex and VS Code issues are unpatched." In one Cursor run, the agent "switched the sandbox off and tried again."

**Limits:** needs the user or agent to open an attacker page. **Action:** limit agent browsing to trusted sites until patched.
