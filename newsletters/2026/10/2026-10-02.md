## 1) Salt Labs — Manus agent hijacked by a single email (IPI→JSFuck→sandbox RCE→connected tokens)

Salt Labs published full technical research (**October 1, 2026**; exact Z unmarked) showing **Manus** could be hijacked via a malicious email — victim only needed to ask Manus to check messages. Obvious shell instructions tripped guardrails; a **JSFuck**-obfuscated payload caused Manus to invoke **Node.js** to “decode” email content, executing attacker JS **before** the security warning fired. Escalation: reverse shell in the per-user cloud sandbox; OAuth/integration tokens for connected services (Gmail MCP, Drive, code repos) present in the environment. Companion PR + “guardrail detects but can’t stop” post also **Oct 1**. Salt says issue **responsibly disclosed**, **remediated**, **no longer exploitable**; Manus did not respond to direct report; **Meta bug-bounty** path confirmed/fixed during then-pending acquisition talks (deal later fell through). Dark Reading exclusive **September 24, 2026** = **OUT** background — Oct 1 is full technical + PR day, **not** first-ever public mention. **Do not claim “just discovered.”**

**Evidence type:** researcher experiment (vendor-remediated; Meta bounty confirmation asserted by Salt). **Limits:** fixed — not a live exploit lead. No CVE/GHSA ID in Salt materials.

**Consulting angle:** agent + MCP + email IPI + **post-detection execution** gap — enforce-before-action; least-privilege tokens in sandboxes; don’t treat prompt guardrails as sufficient for autonomous tool use.

Sources: Salt technical — https://salt.security/blog/how-we-hijacked-an-ai-agent-with-a-single-email ; Salt PR — https://salt.security/press-releases/salt-labs-research-a-single-email-could-hijack-an-ai-agent-and-reach-a-users-connected-accounts ; Salt analysis — https://salt.security/blog/when-a-security-guardrail-detects-the-attack-and-still-cant-stop-it ; Dark Reading OUT — https://www.darkreading.com/application-security/prompt-injection-bug-agentic-ai-app-manus

## 4) AWS security-agent-mcp-server — argument injection (CVE-2026-97662)

AWS bulletin **2026-121-AWS** (**Publication Date: 10/01/2026 10:30 AM PDT** = **17:30Z Oct 1**): open-source **security-agent-mcp-server** (awslabs/mcp) lets AI assistants run local security scans including differential “diff” scans. **CVE-2026-97662** — argument injection in the diff-scan operation: a crafted reference value is interpreted as a command-line option rather than a revision, letting a context-dependent actor **create, overwrite, or truncate arbitrary files** on the host **outside the intended workspace**. Impacted: **≥ 0.1.1 AND < 0.2.0**; fixed **0.2.0**. **No workaround other than upgrading**; until then, run diff scans only against trusted repos and run the server as least-privileged in an isolated environment. GHSA-8g28-rj54-p5p2. Researcher: Mario Guzmán (yud4s). Thin community this freeze (no HN story).

**Evidence type:** official advisory (AWS bulletin + CVE/GHSA). **Limits:** no CVSS in bulletin — do not invent. Requires attacker-influenced reference values on the diff-scan path.

**Consulting angle:** inventory clients on security-agent-mcp-server < 0.2.0; treat MCP host-write primitives as AI-native control-plane risk.

Sources: AWS — https://aws.amazon.com/security/security-bulletins/2026-121-aws/ ; GHSA — https://github.com/advisories/GHSA-8g28-rj54-p5p2 ; CVE.org — https://www.cve.org/CVERecord?id=CVE-2026-97662
