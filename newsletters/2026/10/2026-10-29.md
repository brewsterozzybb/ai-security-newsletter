## 1) Symantec: an unauthorized AI relay disables Codex and Claude Code sandboxes (AI-native; vendor research, single source)

**What changed:** [Symantec](https://www.security.com/threat-intelligence/openai-claude-unauthorized-relays) (dated Oct 29; no time on page) says a relay service installs the genuine CLIs, then a fileless script sets Codex to "danger-full-access," enables network access for the write sandbox, disables telemetry and swaps in relay-issued credentials. It hit "a dozen organizations" since early 2026, mostly in mainland China. Symantec: "This is not a vulnerability in Codex or Claude Code." An analyst told [Dark Reading](https://www.darkreading.com/threat-intelligence/ai-relay-service-openai-codex-claude-code-sandboxes) such a relay "can see every prompt, file, and secret."

**Limits:** "There is no evidence so far that the relay operator has abused this level of access"; operator unnamed. **Action:** hunt for agent configs with sandboxing off and non-vendor API endpoints; IoCs are in the report.

## 2) Refusals as signal, both ways: CrowdStrike reads them; a script weaponizes them (AI-native; vendor research + single researcher)

**What changed:** [CrowdStrike](https://www.crowdstrike.com/en-us/blog/when-ai-guardrails-expose-vulnerabilities/) (Wed 10:05 AM) treats model refusals as "close to a one-bit oracle" for locating bugs; it says the method "was correct in 73 of 86 test scenarios" across five classes. A [nullpt.rs](https://nullpt.rs/fingerprinting-bioweapons) researcher (dated Oct 28; HN Wed 1:13 PM) found a fingerprinting script stuffed with bioweapon-named functions and a hidden jailbreak string. Astra refused to deobfuscate it; GLM-5.3 complied.

**Limits:** CrowdStrike's figure is its own small, controlled test. The script is one researcher's find; the researcher ties it to Russian anti-DDoS firm servicepipe.ru only because a urlscan lookup turned up that similarly named domain. **Action:** if you deobfuscate with LLMs, keep a fallback and treat sudden refusals as possible anti-analysis.

## 3) Talos: NIK C2 implant calls OpenAI's API from the victim host (AI-native; vendor malware analysis)

**What changed:** [Talos](https://blog.talosintelligence.com/nik-c2-new-ai-enabled-framework/) (Thu 6:00 AM) says the Go implant's `ai_generate` command routes "arbitrary prompts to the OpenAI Chat Completions API directly through the infected host." If no key is supplied, it reads the victim's `OPENAI_API_KEY`. It also steals credentials, hijacks RDP sessions and can screen-lock hosts for ransom.

**Limits:** no victim count or attribution. **Action:** alert on LLM API calls from hosts or processes that don't normally make them.

## 5) Cisco: ASA/FTD SSL VPN DoS exploited in the wild, not yet on KEV (CVE main 2 of 3; exploited)

**What changed:** Cisco's [advisory](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-asaftd-tunnel-dos-s6mgkb75) (Wed 3:15 PM) for CVE-2026-76418 (CVSS 8.6) says: "In October 2026, the Cisco PSIRT became aware of active exploitation." An unauthenticated SSL VPN request reloads devices where a tunnel group uses secondary authentication. [BleepingComputer](https://www.bleepingcomputer.com/news/security/cisco-warns-of-firewall-zero-day-exploited-to-crash-ssl-vpn-devices/) cites Shadowserver's 51,000+ exposed ASA SSL VPN devices.

**Context:** [Talos](https://blog.talosintelligence.com/uat-11473-keydrift/) (Wed 5:32 PM) separately describes "historical" UAT-11473 activity using SD-WAN CVE-2026-20127 (on KEV since Feb) to collect data-plane key material. Talos assesses its infrastructure "overlaps considerably" with Volt Typhoon's Silent Train.

**Limits:** DoS only; no actor named. **Action:** patch, or remove secondary auth from tunnel groups and DefaultWEBVPNGroup.
