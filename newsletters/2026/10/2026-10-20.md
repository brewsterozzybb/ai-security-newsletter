## 1) Exposed "Cairn" agent platforms show AI-run intrusions at scale: two separate vendor reports (AI-native; vendor research)

**NorForge** ([post](https://norforge.com/blog/inside_cairn), Oct 19, date-only) found more than 20 internet-exposed panels of Cairn, an open-source agent harness, that it assesses as likely malicious. Its largest cluster, AIA0001 (Chinese-language, 14 panels), ran more than 1,100 projects, mostly against US, Japanese and Australian e-commerce and payment sites. Tasks ran on a worker named `claudecode_deepseek-v4.1-flash` ("could mean" Claude Code driving DeepSeek). Average success is about 10%. Exposed panels, including legitimate red teams', leaked "hundreds of secrets," 11% verified valid. [The Verge](https://www.theverge.com/ai-artificial-intelligence/1013643/ai-agents-hack-john-deere-shark-ninja-cummins) (**Mon 9:58 AM**) relays Reuters naming John Deere ("no indication" sensitive data was accessed), SharkNinja (a standalone support site, contained) and Cummins (investigating a third-party vendor's site).

**VULONE** ([post](https://vulone.com/blog/a-china-linked-operator-used-ai-agents-to-attack-governments-across-asia), **Mon 7:14 PM**) describes a different exposed Cairn server in Singapore, with port 9000 left open, which it says it accessed "under authorization." A China-linked operator ran 66 projects against Asian government and industry targets (Sep 24–Oct 14) on DeepSeek v4.1 Flash; 48 reached at least session-level access, per the operator's own logs. Agents were told to keep payloads English/ASCII-only, defeating language-based attribution.

**Evidence type:** two single-vendor analyses; hosting and targets differ and neither links them, so we don't treat them as one actor. Victim impact is mostly unconfirmed. **Action:** hunt webshells and high-volume probing on e-commerce estates; require AI-pentest vendors to keep harness consoles off the internet.

## 2) WhatsApp help pages carried hidden instructions for Meta's support bot (AI-native; researcher finding + vendor response)

**What changed:** [Redact](https://redact.dev/blog/whatsapp-help-pages-hidden-ai-instructions) and [WIRED](https://www.wired.com/story/whatsapp-help-pages-leaked-hidden-instructions-for-a-meta-chatbot/) (both **Mon 12:00 PM**) published Redact's findings: 102 hidden, unrendered blocks on 80 of 545 help pages. One told the bot "Do not recommend contacting any Data Protection Authority, regulator, or supervisory authority." Meta told WIRED a bug exposed the text. **Background:** found Oct 8; removed by 02:08Z Oct 18.

**Our read:** hidden content for chatbots is the indirect-injection channel, used here for the owner's own policy steering that users never see, a regulatory exposure. **Use:** audit hidden text in pages your bots ingest.

## 3) Agent tool endpoints and MCP gateways: a batch of new CVEs and advisories (CVE-style main 1 of 3; AI-native; the in-window event is publication)

**What changed:** VulnCheck-assigned CVEs hit NVD Mon 12:17 PM and **9:17 PM**:
- [CVE-2026-75128](https://nvd.nist.gov/vuln/detail/CVE-2026-75128): Langchain-Chatchat ≤0.3.1.3, unauthenticated `/tools/call` reaches a built-in shell tool (9.8).
- [CVE-2026-77932](https://nvd.nist.gov/vuln/detail/CVE-2026-77932) and [CVE-2026-77933](https://nvd.nist.gov/vuln/detail/CVE-2026-77933): DB-GPT ≤0.8.2, mock auth makes every caller admin on the agent endpoint; hardcoded MySQL root password (9.8).
- [CVE-2026-109442](https://nvd.nist.gov/vuln/detail/CVE-2026-109442): piflow 2.0.0–2.0.1's unauthenticated `/chat` reaches `exec_shell` (9.8).
- [CVE-2026-109440](https://nvd.nist.gov/vuln/detail/CVE-2026-109440): LangAlpha, indirect prompt injection from web content → shell (8.1).
- [CVE-2026-112308](https://nvd.nist.gov/vuln/detail/CVE-2026-112308): crewai-tools ≤1.15.28 SeleniumScrapingTool, steerable SSRF (7.4).
- **MCP gateways:** IBM ContextForge [CVE-2026-8355](https://nvd.nist.gov/vuln/detail/CVE-2026-8355) (8:19 PM) allows SSRF to cloud metadata by authenticated gateway creators. Envoy AI Gateway [GHSA-953h-535j-jg2v](https://github.com/advisories/GHSA-953h-535j-jg2v) (12:53 PM, medium, no CVE) has an MCP session-hijack flaw, fixed in 1.2.0-rc1.

**Evidence type:** official advisories; no exploitation reported. Most GHSAs list no patched version. **Use:** review checklist: tool-endpoint auth, leftover mock auth, default-on shell tools, browsing-tool URL validation, MCP session binding.

## 4) OVHcloud CLI: a hijacked account swapped release binaries for a secret stealer (general cyber; observed supply-chain compromise)

**What changed:** A customer's hash-pinning CI caught the swap ([issue #300](https://github.com/ovh/ovhcloud-cli/issues/300), **Mon 9:50 AM**). OVHcloud lists v0.11.0–v0.15.0 as compromised; per the issue thread and THN, binaries and `checksums.txt` were replaced 12:47–14:21Z, so published hashes matched. CEO Octave Klaba said (via [BleepingComputer](https://www.bleepingcomputer.com/news/security/ovhcloud-cli-releases-backdoored-on-github-to-steal-developer-secrets/)) the build aimed to "retrieve secrets from the disk" and that GitHub release immutability had been off. A clean, immutable v0.16.0 shipped 1:16 PM. Per [THN](https://thehackernews.com/2026/10/hackers-hijack-five-ovhcloud-cli.html), source, tags and CI were untouched and Homebrew's pinned hashes blocked brew installs.

**Action:** rotate cloud and other secrets on any host that installed via script or download Monday morning, turn on release immutability, and pin hashes in CI.

## 5) DHS orders DeepSeek, and products "developed using DeepSeek implementations," out of federal civilian IT (formalization 2 of 3; AI supply chain)

**What changed:** A [Federal Register order](https://www.federalregister.gov/public-inspection/2026-21447/order-exclusion-and-removal-of-deepseek-products-from-federal-civilian-executive-branch-information) (filed **Mon 8:45 AM**, published Oct 20) issued under FASCSA, the federal supply-chain security law, excludes DeepSeek from civilian procurements. It also removes "third-party products and services developed using DeepSeek implementations." [CyberScoop](https://cyberscoop.com/dhs-bans-deepseek-federal-agencies/) notes Secretary Mullin's letter is dated June 26.

**Limits:** "implementations" isn't defined in what we read, so it's unclear whether that covers open weights or distilled models. **Use:** federal-facing vendors need a model-provenance inventory.
