## Main stories

### 1. Agno agent framework: five CVEs, auth-off default and code-executing tools (AI-native slot)
**What changed:** Between 09:16Z and 10:16Z Oct 12 (05:16–06:16 EDT), NVD published five VulDB-sourced CVEs (GHSA-h3xp-h9j5-qrcr followed at 09:31Z) against Agno, including CVE-2026-108818 (GHSA-h3xp-h9j5-qrcr, medium: AgentOS has no authentication unless `security_key` is set; up to 2.7.3/3.0.6), CVE-2026-108816 (code injection via PythonTools `run_python_code`), CVE-2026-108817 (OS command injection via CodingTools `run_shell`, up to 3.0.9), CVE-2026-108819 (orchestration-layer `exec`) and CVE-2026-108820 (team-delegation over-privilege). The advisory text says the exploit is public and the project "has not responded yet" to an early issue report (Agno-agi/Agno#10051). No patch or vendor statement found.
**Evidence type:** official advisory + researcher disclosure. Severities are low–medium.
**Read it carefully:** several "injections" are tools doing what they are designed to do. The real finding (analyst interpretation) is the combination: an agent server reachable without auth, exposing tools that execute code, with delegation that can widen privilege.
**For JT's work:** in agent-platform assessments ask (1) is the agent runtime/API authenticated by default or only when configured, (2) which tools execute code or shell, and are they behind sandboxing and human approval, (3) can a delegated sub-agent use tools its caller couldn't. Clients on Agno: confirm `security_key` is set and AgentOS is not internet-reachable.
