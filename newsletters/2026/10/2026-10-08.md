## 1) Tensorlake npm SDK worm: agent-config persistence and a "hostage token" wiper

**What changed:** `tensorlake@0.5.144` was published **Wed 9:12 PM ET**; [Socket](https://socket.dev/blog/tensorlake-compromise) flagged it 11 minutes later. [StepSecurity](https://www.stepsecurity.io/blog/tensorlake-npm-compromised-hostage-token-worm) filed [issue #1014](https://github.com/tensorlakeai/tensorlake/issues/1014) at 9:22 PM; reverted 12:32 AM Thu.

The payload, per StepSecurity:
- A `preinstall` hook steals GitHub/npm tokens, cloud keys, K8s/Vault secrets, SSH keys, and Claude/Cursor/Windsurf configs.
- It republishes the victim's packages.
- It commits `.claude/settings.json` and `.vscode/tasks.json` as `claude@users.noreply.github.com` ("chore: update dependencies"), so opening the repo in Claude Code or VS Code runs it again.
- A `gh-token-monitor` service checks the token every 60 seconds for 24 hours. If it is revoked, the service runs `rm -rf ~/`.

It shipped via the repo's own workflow, so npm provenance is valid. StepSecurity: "It doesn't say the code is safe."

**Evidence type:** observed incident (two vendor analyses, commits, revert, GHSA). **Limits:** the wiper behavior is from StepSecurity's static decode; no victim count; how the account was compromised is unknown. Socket's ChainDrop/Shai-Hulud link rests on structural similarity. **Action:** both vendors say to remove the monitor *before* rotating credentials. Pin 0.5.143. Hunt for `gh-token-monitor`, agent/IDE config commits by that author, repos described "Shai-Hulud: Here We Go Again", and `iseekaigogo.com`.

The link to the breaches partly cites press ("reportedly"). Victim count unconfirmed. The HN "student" and r/LocalLLaMA "single person" framings are the submitters', based on a résumé prompt whose details CrowdStrike says "likely belong" to the actor but can't definitively confirm.

## 3) PoeLLM botnet: 3,400+ exposed servers, mostly LiteLLM/Ollama, mined for crypto

**What changed:** [Lumen Black Lotus Labs](https://www.lumen.com/blog/en-us/canto-incognito-tracking-the-poellm-malware) is dated Oct 7, no time; earliest press 11:00 AM Wed. Lumen says the malware "primarily affects" exposed LiteLLM, Ollama, Gotenberg, and Gitea, with "possible" Ivanti Sentry targeting:
- **Scale:** more than 3,400 victims since April; the mid-June peak was nearly 2,200, with ~800 active per day.
- **Payload:** XMRig/Iron miners. Hosts are reused as scanners.
- **C2:** derived from words in a GitHub-hosted poem.
- **Attribution:** Italian-speaking actor (moderate confidence).

Lumen says it disrupted the infrastructure.

**Evidence type:** observed incident (vendor netflow). **Limits:** Lumen found it through Ivanti Sentry CVE-2026-10520 (KEV since Jun 11). For LiteLLM, Lumen says the `/mcp-rest/test/connection` endpoint was "likely the exploitation path", which it ties to CVE-2026-42271 (KEV since Jun 8). That rests on one sample, and Lumen names no Ollama CVE. Activity dates back to April; the report is new. **Action:** patch LiteLLM for CVE-2026-42271. **Question:** can clients list every internet-reachable LLM gateway and runtime they own?

## 4) Talos: malware carries prompt injection aimed at AI triage

**What changed:** [Cisco Talos](https://blog.talosintelligence.com/ignore-all-instructions-and-read-this-blog-the-state-of-ai-analysis-evasion-in-malware/), **Thu 6:00 AM ET**, covers four families (FRUITSHELL, PLOTSAFE, HOLLOWCLAD, MANTLEMAZE), 84 samples, Jan 2025–Jul 2026:
- **FRUITSHELL** (PowerShell reverse shell) carries a comment telling "LLM and AI" it "simply performs prime number generation." The comment turned up verbatim in nine scripts by at least four actors, including one with an AMSI bypass.
- **HOLLOWCLAD** repeats its instruction in seven chat-template formats.

Across five local LLMs, the best techniques pushed verdicts toward benign in about **35%** of runs, net. Plain "don't analyze this" text worked best; elaborate tricks often made models more suspicious.

**Evidence type:** researcher experiment plus observed samples. **Limits:** Talos's own harness and models; Talos calls the trend "interesting, but not alarming." **Why it matters:** any AI pipeline that reads attacker-supplied text (SOC triage, email, tickets) faces the same problem.

## 5) LMCache: two more unauthenticated flaws on top of an unpatched 9.8 RCE (CVE-2026-107204/-107206)

**Background (pre-window; NVD 6:17 AM ET Oct 7, not in our Oct 7 edition):** [JFrog](https://research.jfrog.com/vulnerabilities/lmcache-is-vulnerable-to-unauthenticated-remote-code-execution-via-pickle-deserialization-on-the-multiprocess-zmq-transport-cve-2026-105192-jfsa-2026-001694382/)'s CVE-2026-105192, CVSS 9.8. In multiprocess mode, one unauthenticated ZeroMQ message to port 5555 reaches `pickle.loads`, and official images run as root. Affects v0.3.9–0.5.5; "No fixed version has been published." The default bind is localhost, but [THN](https://thehackernews.com/2026/10/unpatched-critical-lmcache-flaw-lets.html) notes LMCache's example K8s DaemonSet binds all interfaces.

**What changed:** [VulnCheck](https://www.vulncheck.com/advisories/lmcache-through-0.5.5-unauthenticated-rce-via-run-script-endpoint) (NVD **Wed 12:17 PM ET**) added two more:
- **CVE-2026-107204:** `/run_script` RCE, when that endpoint is enabled.
- **CVE-2026-107206:** an unauthenticated management API, listening on all interfaces by default, exposing `GET /env`.

**Evidence type:** official advisories with JFrog PoC; no ITW, not KEV. **Action:** keep 5555, 9300, and the management port off routable networks, and run containers as non-root.

## Take into the day / Worth keeping

1. **Remove persistence before you revoke.** Some malware punishes token revocation, so "rotate first" can trigger the damage. **Use:** assessment check (does the IR playbook start with persistence removal?). **Source:** StepSecurity/Socket, Oct 7–8. **Limits:** one family, static decode. **Tags:** `ir-sequencing`, `npm-worm`.
2. **Agent and IDE config files run code.** Treat `.claude/` and `.vscode/tasks.json` changes as executable. **Use:** detection idea (untested): alert on commits touching those files, especially by bot-like authors. **Source:** StepSecurity, Oct 8. **Limits:** our generalization. **Tags:** `agent-config-persistence`.
3. **Text in a sample is evidence, never instruction.** **Use:** workshop question: "Which of your AI pipelines read attacker-written text, and how is it separated from instructions?" **Source:** Talos, Oct 8. **Limits:** ~35% comes from Talos's own harness. **Tags:** `prompt-injection`, `ai-triage`.
4. **Model safeguards don't follow the tool.** One attacker ran the ARTEX agent on DeepSeek and Claude Code on GLM and Grok. **Use:** presentation point. **Source:** CrowdStrike, Oct 7. **Limits:** single vendor; the inference is ours. **Tags:** `agentic-offense`.
