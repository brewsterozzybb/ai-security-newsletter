### Microsoft Azure DevOps MCP Server: Hidden HTML Comments in Pull Request Descriptions Hijack AI Code-Review Agents; Spotlighting Missing from `repo_get_pull_request_by_id` Function; Reproduced with Copilot CLI and Claude Code

**Manifold Security** disclosed on **August 3, 2026** (per the **Netizen Monday Security Brief Aug 3**, which carried the detailed writeup) a **confused-deputy vulnerability in Microsoft's official Azure DevOps Model Context Protocol server** that lets an attacker with pull-request write access redirect an AI code-review agent to access projects, source code, pipelines, work items, and internal documentation the attacker could not reach directly. The structural finding: **a hidden HTML comment inside an Azure DevOps pull request description can carry concealed instructions that the AI agent interprets as commands rather than as repository content**, with the attack reproduced against both **Copilot CLI and Claude Code** against **version 2.7.0 of the Azure DevOps MCP server**. Microsoft already implemented a mitigation known as **spotlighting** for several response paths (wrapping untrusted content in delimiters and labeling it as external data), but the function used to retrieve a pull request by its identifier, **`repo_get_pull_request_by_id`**, did not use the same wrapper, leaving PR descriptions exposed. The disclosure is the **first public confused-deputy CVE in a major vendor's official MCP server** in 2026, and it lands the same week as the **Google ADK workflow deletion** (Breaking News 3) and the **Cursor CVSS 9.8 zero-click prompt injection** (Breaking News 1).

**The "hidden HTML comment in PR description → cross-project exfiltration" confused-deputy primitive.** Per the **Netizen Aug 3 brief**, "A contributor created a normal-looking pull request containing a concealed payload. When a more privileged reviewer instructed an AI agent to review the pull request, the hidden prompt caused the agent to trigger a pipeline in another project, retrieve a confidential wiki page, and post the page's contents back to the original pull request. The attacker could then read the leaked information from the pull request comment. Each operation was technically permitted under the reviewer's credentials. The security failure came from the sequence and purpose of those operations, which were controlled by hidden text that the reviewer could not see." The confused-deputy primitive is the same one the **GitHub MCP server's 2025 public-issue-to-private-repo leak** (covered in Adversa.ai's Aug 3 roundup) and the **Google ADK's triage-agent-to-privileged-fix-agent chain** (Breaking News 3) make from different angles: the **MCP confused-deputy category is now a tier-1 enterprise vulnerability category with documented major-vendor precedents**, and the procurement consequence is that every enterprise MCP server RFP now needs an explicit "what is the confused-deputy mitigation coverage" question, an explicit "what is the spotlighting or external-content-labeling coverage" question, and the answers have to be in writing.
