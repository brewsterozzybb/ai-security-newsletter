## Breaking News

### **Wiz Finds Critical GitHub RCE — AI Helped, 88% of Enterprise Instances Are Still Vulnerable**

Wiz Research disclosed CVE-2026-3854 yesterday: a critical injection flaw in GitHub's internal git protocol that allowed any authenticated user to achieve remote code execution on backend servers with a single standard `git push`. On GitHub.com, the vulnerability reached shared storage nodes confirmed to hold millions of public and private repositories belonging to other users and organizations. On GitHub Enterprise Server, the same flaw grants full server compromise — including all hosted repositories and internal secrets.

GitHub mitigated the .com exposure within six hours of the report and released GHES patches alongside the CVE disclosure. But at the time of Wiz's publication, 88% of self-hosted Enterprise Server instances remained unpatched. The finding carries an additional dimension: Wiz notes this is one of the first critical vulnerabilities in closed-source binaries discovered using AI tooling — a direct and concrete example of the capability Anthropic's Mythos previewed at a research scale.

Key findings:
- **Trivially exploitable with standard tooling** — no special client, no exploit framework; a properly crafted `git push` from a legitimate account was enough to reach RCE on backend infrastructure.
- **Blast radius on .com was repository-wide** — shared storage nodes exposed to the flaw held repositories belonging to multiple organizations, not just the attacker's own data.
- **GHES patch adoption is nearly zero** — GitHub has released fixes for all supported versions, but 88% of self-managed instances have not applied them, which means the vast majority of on-prem GitHub infrastructure is still fully exploitable.
- **AI-assisted discovery is now a real signal, not a talking point** — Wiz explicitly credits AI-assisted analysis of closed-source binaries as part of the discovery process. Expect this attribution to become more common in 2026 CVE disclosures.

> "A finding of this caliber and severity is rare, earning one of the highest rewards available in our Bug Bounty program." — Alexis Wales, GitHub CISO

**Immediate actions:**
- If you run GitHub Enterprise Server, patch immediately. Check your version against GitHub's advisory and treat this as a P0 — it is a full server compromise, not a privilege escalation edge case.
- Audit authentication logs on managed GHES instances for unusual push activity or anomalous backend requests, especially in the past 30 days.
- Review the blast radius of your GHES instance: what repositories, secrets, and internal tokens live there? Assume those are pre-compromised and rotate accordingly before applying the patch.

### **CISA Confirms Active APT28 Exploitation of Zero-Click Windows Shell Flaw — Missed by Prior Patch**

CVE-2026-32202 is a Windows Shell authentication coercion vulnerability that CISA and Microsoft confirmed this morning is under active in-the-wild exploitation by Russian threat group APT28. The root cause is an incomplete prior patch: Microsoft fixed the remote code execution vector in CVE-2026-21510, but the path resolution and trust verification gap was not fully closed. That gap left a zero-click credential theft path via auto-parsed LNK files — attackers could force a victim's system to authenticate to an adversary-controlled server without any user interaction. The April 2026 Patch Tuesday release includes the fix.

Key findings:
- **Zero-click means no user error is required** — the victim does not need to open a file, click a link, or run anything; simply having an LNK file present in a navigated folder can trigger authentication coercion.
- **APT28 is the confirmed active threat actor** — this is not opportunistic scanning; it is a nation-state group with persistent infrastructure and a track record of using credential theft to enable downstream intrusions and persistence.
- **Incomplete patching created the window** — the partial fix for CVE-2026-21510 gave defenders a false sense of closure. The lesson is structural: one patch for one CVE does not guarantee the underlying attack surface is fully closed.
- **Credential theft, not immediate RCE** — the confirmed exploitation is authentication coercion (NTLMv2 hash capture), which feeds downstream pass-the-hash or relay attacks rather than immediate code execution.

**Immediate actions:**
- Apply April 2026 Patch Tuesday updates immediately across your Windows fleet; CVE-2026-32202 is fixed in this release and is under active exploitation by a sophisticated threat actor.
- Block outbound NTLM authentication to external or unknown hosts at the network level; this is the class of relay and coercion attacks that this CVE and similar flaws enable.
- Enable Protected Users Security Group for privileged accounts — it blocks NTLMv2 authentication for members, significantly reducing the value of captured hashes.
- Audit LNK-heavy environments (shared drives, legacy shortcuts, network folders) as those surfaces are disproportionately exposed to file-based coercion.

## Technical Deep Dives

### **Checkmarx Supply Chain Incident Expands: GitHub Actions Compromise, Data on Dark Web**

The Checkmarx supply chain attack that began March 23 continues to evolve in scope. Checkmarx confirmed yesterday that a cybercriminal group published data from the company's GitHub repository on the dark web, with the exfiltration traced to March 30. The initial compromise targeted two widely used GitHub Actions workflows — `ast-github-action` and `kics-github-action` — by pushing a credential stealer through a poisoned Actions pipeline. Downstream users who consumed those actions during the compromise window may have had pipeline tokens, secrets, and build artifacts captured.

Key findings:
- **GitHub Actions is a proven supply chain attack surface** — this is not a theoretical attack path; the threat actor gained access to Checkmarx's action workflows and pushed malicious content that would execute inside any downstream CI/CD job consuming those actions.
- **The exfiltration-to-disclosure gap was over a month** — the attack occurred March 23, exfiltration happened March 30, and dark web publication arrived in late April. That timeline illustrates how long supply chain compromises can dwell undetected before surfacing.
- **Third-party tooling inherits your trust** — Checkmarx produces security scanning products. Users who trusted the KICS and AST actions because they came from a security vendor had no visible signal that the pipeline had been altered.

**Immediate actions:**
- Audit your GitHub Actions dependency graph and identify any workflow that consumed `ast-github-action` or `kics-github-action` between March 23 and early April 2026; treat any secrets accessible during those runs as compromised and rotate them.
- Pin GitHub Actions to specific commit SHAs rather than mutable tags (`@v1`, `@latest`) — this is the most durable mitigation against workflow substitution attacks across any third-party action.
- Review GitHub Actions permissions scoping for your repositories; GITHUB_TOKEN permissions should follow least-privilege defaults rather than being elevated to `write-all` by default.

### **Two Major Reports, One Finding: AI Security Controls Are Failing at Scale**

Proofpoint's inaugural *2026 AI and Human Risk Landscape* report and the Cloud Security Alliance's *Autonomous but Not Controlled* study landed within 24 hours of each other, and they tell the same story from different angles.

**Proofpoint (global survey, released April 28):** Half of all global organizations experienced an AI security incident in the past year — despite having AI security controls in place. More than half of organizations are not fully confident their AI controls would detect compromised AI. 87% have deployed AI assistants beyond pilot. 94% report struggling with multi-tool complexity as AI tooling multiplies.

**CSA (conducted alongside Token Security, published April 21):** Two-thirds (65%) of organizations have suffered a cybersecurity incident related to AI agent deployment in the past 12 months. The incidents resulted in data exposure, operational disruption, and financial losses. The majority of organizations have no decommissioning strategy for AI agents, meaning those agents can persist and accumulate capability long after their intended use ends.

Key findings:
- **Controls ≠ detection** — the Proofpoint number that matters most is not the 50% incident rate but the fact that those incidents happened to organizations that *had* AI security controls. Controls without detection coverage are a false floor.
- **Agent sprawl is invisible sprawl** — the CSA finding on decommissioning is particularly sharp: if you do not have a lifecycle process for retiring an agent, you cannot know how many agents are running, with what tokens, on whose behalf.
- **Complexity is itself a risk surface** — 94% of organizations struggling with multi-tool complexity suggests that AI security architectures are already fragmented enough to create blind spots in log correlation, incident response, and policy enforcement.

**Immediate actions:**
- Treat your AI assistant deployment like an application inventory problem: enumerate every tool, every connection, every token. If you cannot list them, you cannot monitor them.
- Build detection coverage specifically for AI-mediated data movement — exfiltration through summarization, copy-paste flows, or agent-initiated API calls looks different from traditional DLP triggers.
- Create and test an agent decommissioning playbook before you need it: how do you revoke an agent's identity, audit its historical actions, and confirm it is no longer running anywhere?

## Five Things to Take Into the Rest of the Day

1. **The GHES patch gap is the most immediately actionable item today.** CVE-2026-3854 is a full server compromise via a standard `git push`, and 88% of GitHub Enterprise Server instances are still vulnerable. If you operate GHES, this is your first call of the morning. If you use a third-party CI/CD platform, this belongs in your vendor risk conversation this week.

2. **Incomplete patches are a second class of vulnerability you are systematically underestimating.** CVE-2026-32202 is the second time in recent weeks that a partial fix for a known vulnerability left a distinct attack path fully open. Defenders have a habit of treating "patched" as "resolved." The truth is that the patch addressed one symptom of an underlying trust assumption that was wrong. Assume more half-fixes exist; build detection for the underlying behavior, not just the CVE.

3. **The AI security gap is not a knowledge problem — it is a process problem.** Proofpoint and CSA both surveyed organizations that already know AI is risky. The gap is not awareness; it is detection coverage, decommissioning discipline, and incident response processes that have not caught up to agent deployment velocity. Buying another "AI risk" dashboard will not close a process gap. Building an agent inventory will.

4. **Supply chain risk now runs through GitHub Actions, not just package registries.** The Checkmarx incident confirms that GitHub Actions workflows are a mature attack vector for inserting credential stealers into CI/CD pipelines. If your organization uses third-party Actions without pinning to commit SHAs, you have a supply chain posture problem that is not being addressed by your current SCA tooling.

5. **The platform trust question is no longer hypothetical.** Ghostty leaving GitHub is a culture moment, but the underlying question — what happens to projects, secrets, and workflows when you depend on a single commercial platform — is a security question as much as a political one. CVE-2026-3854 lands at exactly the wrong moment for anyone defending Microsoft's infrastructure as a security baseline. Whether you migrate or not, the argument for defense-in-depth across your code hosting, CI/CD, and secret management layers just got stronger.
