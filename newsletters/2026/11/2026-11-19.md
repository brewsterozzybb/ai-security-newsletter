## 1) LiteLLM CVE-2026-40217 goes onto KEV, due Dec 2; a same-day ZDI advisory covers MCP stdio (CVE; KEV)

**What changed:** CISA's KEV catalog **v2026.11.18**, released Wed 2:17 PM EST, has **1,786** entries (+4). CISA's alert (dated Nov 18; no time on the page) lists the adds as **CVE-2026-40217** in BerriAI LiteLLM (unprotected alternate channel), **CVE-2024-10441** in Synology DiskStation Manager, **CVE-2026-90436** in Apache Axis, and **CVE-2026-90817** in Vanderbilt REDCap. The KEV short description is an unprotected alternate channel that can allow remote code execution via bytecode rewriting at `/guardrails/test_custom_code`; the KEV due date is **Dec 2**. GitHub advisory GHSA-wxxx-gvqv-xp7p (originally published May 7) says that endpoint runs user-supplied Python in a hand-rolled sandbox that can be escaped to code execution in the proxy process — which "runs as root in the default Docker image" — and that reaching it "requires a proxy-admin credential in default configurations." The advisory lists affected versions as **>= 1.81.8, < 1.83.10** and patched versions as **>= 1.83.10**, and tells operators to upgrade to **1.83.11 or later** after the sandbox was replaced with RestrictedPython. Separately, Trend Micro's Zero Day Initiative published **ZDI-26-1031** (dated Nov 18; no time on the page): an authenticated command-injection bug in LiteLLM's handling of MCP stdio configurations, scored **7.2**. ZDI's timeline says that on Nov 17 the vendor "clarified no separate patch is coming, and disputed that the report describes a vulnerability." The mitigation ZDI attributes to the vendor is to upgrade to **1.104.0 or later** and leave `LITELLM_ENABLE_MCP_STDIO` unset, and to replace default or example master keys. This is a different bug from CVE-2026-40217 and from the older **CVE-2026-42271**.

**Limits:** A KEV listing is CISA's determination of known exploitation; the original GHSA still requires a proxy-admin credential in default configurations. ZDI-26-1031 requires authentication, and the vendor disputes that it is a vulnerability.

**Action:** If you run LiteLLM, upgrade the guardrail bug to **1.83.11 or later**, and apply the ZDI-stated MCP stdio mitigation (**1.104.0+**, leave `LITELLM_ENABLE_MCP_STDIO` unset, rotate default master keys). Federal civilian agencies: LiteLLM by Dec 2; Synology, Axis, and REDCap by **Nov 21**.

## 2) NGINX2Root: unauthenticated HTTP/2 RCE, CVE-2026-123633 and CVE-2026-123007 (CVE; AI-assisted find)

**What changed:** Wiz (dated Nov 18; no time on the page) and Rapid7 (dated Nov 18; no time on the page) disclosed two HTTP/2 memory-safety bugs in NGINX that can allow unauthenticated remote code execution when HTTP/2 is enabled. Wiz, writing with Ikotas Labs, Metnir, Rapid7, and Xint, rates both **CVE-2026-123633** (use-after-free) and **CVE-2026-123007** (HTTP/2 flow-control integer underflow) as CVSS 4.0 **9.2**. Wiz says CVE-2026-123007 affects versions dating back to NGINX **1.9.5** in 2015, that it demonstrated code execution on NGINX serving ordinary static files, and that NGINX "powers more than **225 million** websites." Wiz says it used **Wiz Atlas** to discover both bugs and **Gemini 4 Carbon** and **ChatGPT 5.6 Sol** to validate impact. nginx.org lists OSS fixes at **1.31.9+** and **1.30.7+**; it rates CVE-2026-123007 as major (vulnerable **1.9.5–1.31.8**) and CVE-2026-123633 as medium (vulnerable **1.19.7–1.31.8**). Wiz's NGINX Plus table differs by CVE: **37.0.7.1 / 37.2.0.1** for CVE-2026-123633 and **37.0.8.1 / 37.3.0.1** for CVE-2026-123007; Rapid7's CVE-2026-123007 table matches those later Plus builds. Rapid7 published a working RCE proof-of-concept that it says needs about **128 GB** of HTTP/2 traffic and will not succeed against nginx's default one-hour connection lifetime on networks slower than about **300 Mbit/s**. If you cannot upgrade immediately, Wiz says to temporarily disable HTTP/2. Neither CVE is on KEV. Wiz's and Rapid7's write-ups do not claim confirmed use in the wild.

**Limits:** The 9.2 scores, 225 million websites, and AI-discovery claims are Wiz's; Rapid7 does not claim AI discovery, and nginx.org's severity for CVE-2026-123633 is medium. The 128 GB and 300 Mbit/s figures are Rapid7's, for its proof-of-concept.

**Action:** Move OSS to **1.30.7** or **1.31.9**, or to the matching Plus builds, or temporarily disable HTTP/2 and confirm old workers have exited.

## 3) CrowdStrike Falcon Complete and OverWatch join Guardian AI Detection and Response (AI-native)

**What changed:** CrowdStrike (dated Nov 18; no time on the page) says Falcon Complete analysts and Falcon Adversary OverWatch threat hunters correlate Falcon Guardian AI-runtime context — human prompts, system instructions, agent activity, MCP servers, skills, and Agent Graph — with endpoint, identity, cloud, and SaaS telemetry. The post cites CrowdStrike's 2026 Threat Hunting Report: "AI agent-triggered detection leads surfaced at **2.5 times** the rate of human-triggered leads." It also says CrowdStrike has observed DPRK-nexus adversaries poisoning trusted AI framework packages. This is a product announcement, not an incident report.

**Limits:** The 2.5× figure and the DPRK-nexus observation are CrowdStrike's.

**Action:** If you run Falcon Guardian, review how Complete and OverWatch will use agent-graph and MCP context.

## Follow-ups

- **Microsoft `agent-framework`:** Wiz updated the same post at 14:00 UTC Nov 18 (9:00 AM EST Wednesday) with a root-cause section. Wiz says the attacker appears to have compromised a Microsoft **ESRP** (Engineering System Release Pipeline) client certificate and private key; a first publish from AWS was rejected by IP filtering, and a second from Microsoft-owned IP space succeeded. "How the credentials were obtained is not yet known." Wiz says the tooling identified itself as **Cairn**, staging the package at `/tmp/cairn_pkg` and sending a `CAIRN_ESRP_PROBE2` probe. Of the **50** free-tier webhook.site requests Wiz analyzed, it says **4** were from the attacker, **29** appeared to be sandboxes or scanners, and the remaining **17** represent **three** unique successful victim-data exfiltrations. A Microsoft spokesperson told The Register (published Wed 12:23 PM EST; updated 1:05 PM EST): "We have made some repositories private while we investigate malicious content." The spokesperson did not name the repositories. The Register notes that the agent-framework GitHub repo and Microsoft's ONNX Runtime repo were offline as of its writing, and that "neither Microsoft nor security researchers have linked the ONNX repo's pull to the malware campaign." The last safe version remains **1.26.0**.
- **Java4Shell CVE-2026-114938:** Still not on KEV. NVD now lists it as **Analyzed**.
