## 1) Malicious PyPI releases of Microsoft `agent-framework` 1.26.1 and 1.26.2 (AI-native; supply chain)

**What changed:** Wiz (dated Nov 17; no time on the page) says a malicious version **1.26.1** of Microsoft's official `agent-framework` package was uploaded to PyPI at 20:35 UTC Nov 17 (3:35 PM EST Tuesday), a second version **1.26.2** followed at 21:08 UTC (4:08 PM EST), and both were gone as of 21:30 UTC (4:30 PM EST) — about 55 minutes. Wiz says the package gets about **41,000** downloads a week and that the last safe version is **1.26.0**. Once installed, Wiz says, a `.pth` hook runs at every Python start — even if `agent-framework` is never imported — and steals environment variables, Azure IMDS and OIDC tokens, and, in 1.26.2, GitHub Actions OIDC tokens, posting them to a webhook.site URL. Wiz says the attackers' token was on the free tier, that a maximum of **50** requests were captured, and that 1.26.1 was a wheel only with no matching git tag; "the root cause hasn't been confirmed." SecurityWeek (Wed 6:05 AM ET) reports that an Agent Framework maintainer, in a GitHub discussion, confirmed the releases were removed and that an investigation was underway.

**Limits:** All of the download, duration, and request-count figures above are Wiz's except the maintainer confirmation, which is via SecurityWeek. Root cause is unconfirmed.

**Action:** Pin or reinstall **1.26.0**, rebuild anything that installed 1.26.1 or 1.26.2, and rotate cloud, CI, and OIDC credentials from those environments. Check egress for webhook.site.

## 2) Java4Shell CVE-2026-114938: AI-found OpenJDK Base64 bug, CISA urges immediate patching (CVE)

**What changed:** OpenJDK's Nov 17 advisory (last update on the page 12:44 PM EST Tuesday) assigns CVE-2026-114938 a CVSS 3.1 score of **8.1** and marks the 17, 21, 25, and 27 version lines in its risk matrix. CISA says the memory-corruption bug in the x86-64 HotSpot JVM's Base64 decoder could crash the JVM and allow unauthenticated RCE; OX says only CPUs with AVX-512 VBMI run the vulnerable code. Calif says its researcher found the bug in about an hour, had a working exploit in two more, and that "the total token cost was less than $200," with later chains "built almost autonomously with AI"; Calif also cites a CVSS 4.0 score of **9.2** and lists demos including Jira and Jenkins. CISA (dated Nov 17; no time on the page) "strongly urges organizations to immediately patch" it. The CVE is **not on KEV**. OX (dated Nov 18; no time on the page) estimates that **less than 0.12%** of JVMs are realistic RCE targets, says ARM64, Java 8, and Java 11 are not on that path, and says there is "no publicly available RCE exploit or confirmed exploitation in the wild as of November 18, 2026." If you cannot patch yet, OX recommends **`-XX:-UseBASE64Intrinsics`**. First reports arrived about 23 minutes before this window (r/msp, Tue 7:59 AM EST); the advisory, patches, and CISA alert are in-window. Users asked Adoptium (Temurin) and BellSoft (Liberica) for patched-build ETAs.

**Limits:** Calif's token-cost, timing, and demo claims are Calif's; OX's exposure estimate and "no public RCE exploit / no confirmed wild use" wording are OX's. The two CVSS scores use different versions and should not be collapsed.

**Action:** Move to the Nov 17 OpenJDK (or vendor) builds for affected 17/21/25/27 lines, including bundled runtimes, or set `-XX:-UseBASE64Intrinsics` until you can.

## 3) KEV v2026.11.17 adds Puppet Enterprise CVE-2026-115731, due Dec 1 (CVE; KEV)

**What changed:** CISA's KEV catalog **v2026.11.17**, released Tue 12:53 PM EST, has **1,782** entries (+1). The add is **CVE-2026-115731**, a deserialization bug in Perforce Puppet Enterprise: a client with any CA-signed agent certificate can execute code on the Puppet Server by submitting a crafted report; if the CA autosigns, CISA says, an unauthenticated attacker can obtain a certificate and exploit it. NVD lists CVSS 4.0 **9.4** and CVSS 3.1 **9.9**. SecurityWeek (Wed 5:37 AM ET) says the bug was "flagged as exploited on November 4," that patches are in Puppet Enterprise / Enterprise Advanced **2026.0.1, 2025.12.1, and 2023.8.13** and Puppet Core **9.1.3 and 8.22.2**, and that OpenVox is also affected — a point that is in SecurityWeek, not in the CISA alert text. Federal civilian agencies have until **Dec 1**.

**Limits:** "Exploited as of Nov 4," the patch list, and OpenVox are given as SecurityWeek reports them. The official Perforce portal did not yield usable text.

**Action:** If you run Puppet Enterprise, Core, or OpenVox, apply the patched builds SecurityWeek lists, and review autosign.

## 4) Microsoft: device-code phishing aimed at AI coding agents (AI-native; controlled simulation)

**What changed:** Microsoft Security (dated Nov 17; no time on the page) describes a controlled lab simulation, using GitHub Copilot CLI as the example, of what can follow a phished OAuth device-code approval: steering an active session (if remote control is enabled and policy allows it), adding misleading entries to the agent's memory, reading cloud-synced sessions, or reaching private repositories. Microsoft calls these "proof-of-concept results showing how existing features, working as designed, could be abused after a phished authorization; they are not attacks we have observed in the wild." Each outcome still requires the user to approve a device-code request started by the attacker.

**Limits:** Lab demonstration only; not seen in the wild. Copilot CLI is an example, not a unique flaw.

**Action:** Treat unexpected device-code prompts as a security event, especially on accounts that can steer coding agents or reach private repos. Prefer phishing-resistant sign-in where you can.
