**Top item:** ChatGPT Desktop / Codex can forward your local SSH agent to a remote coding host — designed behavior visible in shipping bootstrap code, not a newly disclosed 0-day. Keep production keys off those sessions.

## 1) ChatGPT Desktop / Codex forwards the local SSH agent to remote hosts (community + shipping code)
**What changed:** An HN post (Mon 3:17 AM EST, 75 points) warned that a remote coding agent can authenticate with the user's local SSH credentials and, for example, push to private GitHub repos. The post cites openai/codex PR #28131; that PR (June 2026) describes an opt-in `--forward-ssh-agent` mode but was **closed without merging**. Stronger evidence is openai/codex issue #59694 (opened Nov 5; pre-window), which quotes shipping Desktop bootstrap (app 26.1023.6123.0) that symlinks `$SSH_AUTH_SOCK` to `forwarded-ssh-agent.sock` for the shared remote server. OpenAI has not commented in-thread.
**Limits:** Designed agent-forwarding, not a remote 0-day. Default-on scope for every remote session is not independently confirmed. No demonstrated third-party abuse in the reports reviewed.
**Action:** Prefer touch-to-sign / hardware-backed SSH keys; avoid loading production identities into Desktop remotes; use per-repo deploy keys where practical.

## 2) npm `@ethersphere/bee-js@13.3.0` ships install-time malware (vendor study)
**What changed:** StepSecurity (dated Nov 8; no time on page; malicious package published to npm Sun 7:09 PM EST / 00:09:50 UTC Nov 9) reports that `@ethersphere/bee-js` **13.3.0** runs attacker-controlled JavaScript on install, targeting Swarm Desktop wallet data and attempting persistence on Linux, macOS, and Windows. An unsigned `bee-worker` commit still produced a package with valid SLSA provenance via GitHub trusted publishing. OX Security (Mon 4:29 AM EST) says the same compromise also hit the official ethersphere/swarm-desktop GitHub release **0.56.2** (fix 0.56.1; 44 downloads before OX published, listed as still live at that time); npm has since reverted bee-js to 13.2.0. StepSecurity's Nov 1–7 download count (3,560 across versions) **predates** the bad release and is not a victim count.
**Limits:** How many systems pulled 13.3.0 specifically is unknown. The macOS executable payload was not retrieved in StepSecurity's write-up.
**Action:** Do not install bee-js 13.3.0 or Swarm Desktop 0.56.2. If you did with lifecycle scripts enabled, treat the host as potentially compromised, hunt persistence paths, rebuild if needed, and rotate credentials and Swarm wallet material from a clean environment.

## 3) SonicWall SSL-VPN SAML MFA bypass exploited; KEV due Nov 20 (exploited / KEV)
**What changed:** Help Net (Mon 5:30 AM EST) covers CVE-**2026-19868**: with SAML enabled for SSL-VPN, valid credentials for an alternate authentication method may bypass SAML-enforced MFA. Fixes: SonicOS **≥7.3.4-7013** and **≥8.2.3-8015**. SonicWall says its PSIRT "has investigated a report indicating potential exploitation" and has shared no attack details; neither SonicWall nor CISA has published IoCs (per Help Net). CISA added the CVE to KEV in catalog **v2026.11.06** (Fri 2:44 PM EST — **Missed, weekend gap**); federal due date **Nov 20**. Not an unauthenticated bypass — stolen or known alternate-auth passwords are required.
**Limits:** KEV add itself is outside this window; Monday coverage is the exploitation amp. No public IoCs.
**Action:** Patch Gen7/Gen8 SSL-VPN appliances now; review alternate-auth methods and recent VPN logins that skipped the IdP.
