## 1) GitBook revokes all customer API tokens after attack it says used AI agents (vendor statement)
**What changed:** GitBook's status page says that at 19:00 CET on Nov 2 (Mon 1:00 PM EST) an attacker "gained unauthorized access to some of our infrastructure credentials." Its first notice (Tue 7:15 AM EST) predates this window. The Tue 10:21 AM EST update calls it "a sophisticated, highly targeted attack using AI agents." Integration tokens, Git Sync secrets, API tokens and GitBook Assistant visitor questions may have been accessed; it found "no evidence" content was modified. Wed 5:36 AM EST: resolved; Git Sync "remains affected" because of what GitBook calls an unrelated GitHub outage; a postmortem is promised "within the next 24 hours."
**Limits:** "Using AI agents" is GitBook's claim, unexplained. No entry vector, tool or customer count. GitBook links it to no other incident.
**Action:** Rotate GitBook API tokens and any third-party tokens stored in GitBook, re-authenticate the GitBook MCP server.

## 2) Postman desktop reconfigured users' coding agents; Postman says opt-in will be clearer (community report + vendor statement)
**What changed:** A GitHub issue opened Oct 25 (pre-window) reports that Postman 12.33.4 auto-installed plugins into Claude Code and Codex, added a startup hook steering the agent to Postman skills, pointed Codex at a remote Postman MCP, and that the installer tries to self-approve that hook. It surged on Hacker News Tue 12:22 PM EST (1,363 points). Postman head of product Sarabmeet Kallar told RuntimeWire (Tue 8:11 PM EST) the company will make the opt-in clearer, especially for existing users.
**Limits:** The HN title says Postman "attempts to share all API data"; the reporter says the report "does not claim to establish data exfiltration." A Postman-voiced reply on the issue (Tue 6:36 PM EST) comes from an account with no GitHub Postman affiliation.
**Action:** On Postman machines, inspect Claude Code/Codex/Cursor plugin, hook and MCP configs; remove what users didn't choose.

## 3) Binance: fake job interview, then an internal AI tool used to reach other engineers' machines (follow-up to Oct 30)
**What changed:** Binance's Nov 3 findings (dated Nov 3; no time on page) trace the theft to a September fake job interview that compromised one engineer's computer and an Oct 20 step where the attacker used "an internal AI tool" to gain control of two other engineers' computers. Separately, in June another engineer downloaded a tampered Homebrew installation while installing an AI coding tool; StepSecurity says the report does not establish continuous access from June. Sources: StepSecurity (dated Nov 3; no time on page) and The Hacker News. Binance's estimate is about $6.34B impacted; The Hacker News headline says $6.43B.
**Limits:** Self-reported and not audited. Neither AI tool is named, and how the internal tool was abused is not described.
**Action:** Pin developer-tool installs to verified sources, and scope internal AI assistants so one compromised seat cannot drive actions on colleagues' machines.

## 4) CISA's KEV remediation deadline for exploited WordPress core flaw is Friday (KEV)
**What changed:** CISA added CVE-2026-119977, a WordPress Core time-of-check/time-of-use race, to KEV in catalog 2026.11.03 (Tue 3:00 PM EST); the federal deadline is Fri Nov 6. WordPress fixed it in 7.1.4 on Oct 28. In a weekend advisory update (pre-window), Wordfence said it "blocked 13,095 attacks targeting this vulnerability in the past 24 hours" (per BleepingComputer, Wed 7:11 AM EST).
**Limits:** CISA lists ransomware use as unknown; exploitation details are thin.
**Action:** Confirm every WordPress site, including marketing and agency-hosted ones, is on 7.1.4 or later.

## 5) "Greeter" campaign hid commands in "hello" chats to exploit Flowise (vendor study)
**What changed:** era.security (dated Nov 3; no time on page) logged 4,972 stored "hello" messages on seven Flowise honeypots, July–October, delivering commands through CVE-2024-58351 (overrideConfig code injection). It counted 4,372 internet-exposed Flowise instances; 703 of 3,277 with a known version had no authentication, and 46 matched the vulnerable setup.
**Limits:** Honeypot data; exposure figures are version estimates. The "Chinese-language framework" label is era's description, not an attribution.
**Action:** Put authentication on Flowise, patch, and search chat logs for repeated identical greetings with tool-execution output.
