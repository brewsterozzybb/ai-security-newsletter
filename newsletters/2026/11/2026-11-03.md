## 1) WorkOS breach: CEO says ARTEX was involved (AI-native; follow-up to Oct 27/30 ARTEX; vendor disclosure)

**What changed:** [WorkOS](https://workos.com/security/bulletins/october-30th-2026-data-security-incident) (dated Nov 2; no time on page; not yet posted at Mon 6:30 PM per an [HN poster](https://news.ycombinator.com/item?id=50345712)) is investigating "unauthorized access to an internal tool used by our sales and customer-facing teams" and "identified the use of an AI-assisted offensive security framework." Exposed data includes "Summaries and excerpts from sales calls, support discussions, and customer Slack conversations." It found "no evidence that WorkOS application data was accessed." CEO Michael Grinich [on HN](https://news.ycombinator.com/item?id=50345712) (Mon 7:26 PM): "The attack involved ARTEX, an autonomous AI agent framework." Separately, [BleepingComputer](https://www.bleepingcomputer.com/news/security/chinese-hackers-use-artex-ai-in-automated-attacks-against-200-orgs/) (Mon 4:40 PM) reports DIVD now attributes its September breach to ARTEX, which went from "initial access to root privileges in 12 minutes."

**Limits:** the bulletin itself doesn't name ARTEX. Vector and customer count undisclosed. ARTEX is widely forked; nothing links WorkOS to VAPOR PANDA.

**Action:** WorkOS customers: expect convincing follow-on phishing (the bulletin warns of it); review what you shared with WorkOS in support and Slack threads.

## 2) Google: LLMJacking charges top $100K in a day, resold via "LLM Mixers" (AI-native; vendor IR report)

**What changed:** [GTIG/Mandiant](https://cloud.google.com/blog/topics/threat-intelligence/llmjacking-monetizing-compromised-cloud-models/) (dated Nov 2; no time on page; earliest coverage [The Register](https://www.theregister.com/security/2026/11/02/token-thieves-costing-companies-100k-per-day-in-illicit-llm-charges/5306967) Mon 11:00 AM) saw charges "exceeding $100,000 USD in a single day, with cumulative charges at some organizations reaching $1 million USD before access was revoked." "LLM Mixers" "proxy, aggregate, and resell unauthorized LLM access." UNC6993 entered via "a misconfigured Service Account key." One actor made "more than 500,000 LLM API calls in less than eight hours" for the Jet Night service. Others probe exposed Ollama endpoints.

**Limits:** GTIG's figures; no victim count. **Action:** set billing alerts and quotas on model APIs; audit service-account keys; don't expose Ollama or model gateways unauthenticated.

## 3) MCPhantom: coding agents install archived, unpatched MCP servers from memory (AI-native; vendor study)

**What changed:** [Glow Labs](https://www.glow.io/blogs/mcphantom-ai-coding-agents-are-installing-vulnerable-deprecated-mcp-servers-from-training-data) (dated Nov 2 and Nov 3 on page; no time on page; [Help Net](https://www.helpnetsecurity.com/2026/11/03/mcphantom-deprecated-mcp-servers/) Tue 12:45 AM) says in "98% of the sessions where an agent set up a deprecated MCP server," the choice appears to come from training data. Seen across Claude Code, Cursor and Codex CLI, with Anthropic, OpenAI and xAI models. It found four high-severity flaws in the archived reference servers, including Puppeteer RCE via prompt injection; the servers have 17.35M npm downloads since July 2025 (Glow). "No CVE exists," and maintainers "will not be involved moving forward."

**Limits:** sample covers only sessions that installed a deprecated server; no exploitation reported. **Action:** pin approved MCP servers in agent configs; block npx-launched archived `@modelcontextprotocol/server-*` packages.

## 4) UK NCSC: AI-powered malware in a ransomware attack on UK infrastructure "highly likely" by 2028 (AI; government assessment)

**What changed:** [NCSC](https://www.ncsc.gov.uk/report/artificial-intelligence-and-cyber-intrusion) (dated Nov 3; no time on page) sets out three scenarios to 2028, "not predictions." It judges it "highly likely that between now and 2028, AI-powered malware will have been used in a ransomware attack on UK CNI," and that Russia, China and other states "will routinely use AI-cyber" by then.

**Limits:** probabilistic judgments, not incident data. **Action:** for UK CNI clients, prioritize known vulnerabilities in legacy technology, which the report expects AI-cyber tools to target.

## 5) Node-RED CVE-2026-58115 exploited in opportunistic scanning; the tool ships inside ICS products (CVE main 1 of 3; exploited; not on CISA KEV)

**What changed:** Likely missed Nov 2: [VulnCheck](https://www.vulncheck.com/blog/exploitation-targeting-node-red) is dated Nov 2 (no time on page) but includes a Nov 1 update, and [SecurityWeek](https://www.securityweek.com/critical-node-red-flaw-exploited-in-attacks/) (Tue 7:10 AM) says it warned "On Sunday." In-window press: [The Register](https://www.theregister.com/security/2026/11/02/max-severity-bug-in-widely-used-ot-programming-tool-exploited-to-deliver-linux-malware/5307086) Mon 5:55 PM. A canary caught one `POST /flows` on Oct 30 deploying a flow that drops a Linux bot to `/dev/shm/.b`; VulnCheck saw "16 times between October 30 and November 1," from one Microsoft-ASN IP ("opportunistic mass scanning"). CVSS 10 (SecurityWeek); Siemens assigned the CVE in August for its SIMATIC IoT2050 (The Register).

**Limits:** one source IP; canary data, not victims. **Action:** never expose the Node-RED admin API without auth; check OT products embedding Node-RED.
