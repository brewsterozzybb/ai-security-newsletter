## 🚀 Headliners

### MCP CVE Explosion: 30 Vulnerabilities Filed in 60 Days as Attack Surface Expands
**URL:** https://adversa.ai/blog/top-mcp-security-resources-march-2026/

The Model Context Protocol (MCP) — the open standard enabling AI agents to seamlessly integrate with external tools and data sources — has become the fastest-growing attack surface in AI security. According to research from Adversa AI, **30 CVEs have been filed against MCP implementations in just 60 days**, marking a watershed moment in agentic security. This rapid vulnerability discovery reveals a fundamental tension: MCP was designed for interoperability, not security boundaries.

The core issue is architectural. MCP servers execute with the privileges of the host application, meaning a compromised MCP server effectively becomes a privilege escalation vector. Checkmarx's analysis identifies the top risks as broken authorization, excessive data exposure, and improper asset management — the familiar OWASP Top 10 patterns, now recontextualized for agent-to-tool communication. The attack surface spans credential theft via malicious MCP servers, prompt injection through tool descriptions, and supply chain compromises where poisoned tools propagate across agent ecosystems.

For security teams, this means MCP can no longer be treated as a developer convenience. Organizations must implement MCP server allowlisting, runtime monitoring of tool invocations, and mandatory authentication for MCP endpoints. The 60-day CVE count is a leading indicator: as enterprise adoption accelerates, expect this attack surface to rival traditional API security in complexity and exploitability.

### CVE-2026-22200: Agentic Collapse Exposes Critical RAG Tool Vulnerabilities
**URL:** https://www.penligent.ai/hackinglabs/agentic-collapse-why-cve-2026-22200-is-a-wakeup-call-for-rag-tool-security/

Penligent's disclosure of CVE-2026-22200 reveals a critical vulnerability class in Retrieval-Augmented Generation (RAG) implementations: **adversarial prompt injection designed to bypass LLM safety guardrails and execute tool exploits**. The vulnerability demonstrates how attackers can craft natural language prompts that, when processed by the LLM, generate adversarial outputs instructing the model to inject PHP filter payloads and leak sensitive file contents.

The attack chain is elegant and dangerous. An attacker submits a request with a files section specifying sensitive system paths — including configuration files containing credentials and tokens. When these files are added to an LLM-powered chatbot node's context, the attacker can then query the chat interface to exfiltrate the file contents. The LLM becomes an unwitting accomplice, its reasoning capabilities weaponized against the very system it serves.

This vulnerability class represents a fundamental shift in how we must approach AI system penetration testing. Traditional security assessments treat the LLM as a black box; CVE-2026-22200 demonstrates that the interaction between AI reasoning and tool execution is itself a critical attack surface. Security teams must adopt holistic testing approaches that evaluate the full agent-tool-reasoning chain, not just isolated components. The "agentic collapse" moniker is apt — without explicit safeguards, the autonomy that makes AI agents powerful also makes them exploitable.

### CVE-2026-2256: MS-Agent Critical Flaw Enables Full System Takeover via Prompt Injection
**URL:** https://cyberpress.org/critical-ms-agent-vulnerability-allows-attackers-to-hijack-ai-agents-and-gain-full-system-control/

A critical vulnerability in Microsoft Agent (MS-Agent) demonstrates the devastating potential of prompt injection when combined with unsanitized command execution. Tracked as **CVE-2026-2256** and assigned Vulnerability Note VU#431821, the flaw allows attackers to hijack AI agents and gain full system control through carefully crafted prompts that escape intended constraints.

The technical root cause is unsanitized shell command execution within the agent's tool invocation layer. When an attacker provides a malicious prompt, the agent's natural language understanding is manipulated into generating shell commands that escalate privileges on affected installations. This is prompt injection elevated to its most dangerous expression: not merely jailbreaking the model, but weaponizing it as a remote access trojan.

The broader implication is stark: every AI agent with system-level tool access is a potential privilege escalation vector. Microsoft's disclosure follows the pattern established by CVE-2026-0628 (Chrome Gemini panel hijack) and the n8n RCE disclosure from January — browser-native and workflow-native AI agents are emerging as prime targets. Organizations deploying agents with elevated permissions must implement strict input validation, command allowlisting, and privilege separation. The assumption that "the LLM will understand context" is provably false; explicit security boundaries at the tool layer are mandatory.

### Invariant Labs Discloses GitHub MCP Server Prompt Injection Attack
**URL:** https://authzed.com/blog/timeline-mcp-breaches

Invariant Labs has uncovered a **prompt-injection attack against the official GitHub MCP server** that demonstrates how malicious public content can hijack AI assistants and exfiltrate private data. The attack vector relies on a malicious public GitHub issue containing poisoned instructions. When an AI assistant with MCP access reads the issue, the injected prompts override the agent's intended behavior, causing it to pull data from private repositories and leak it back to public channels.

This attack exemplifies the "indirect prompt injection" class — where the malicious payload is not delivered directly to the LLM, but arrives via a trusted data source. The GitHub MCP server's design assumes that public repository content is safe to process, but this trust boundary collapses when AI agents act upon the content rather than merely displaying it. The attack is particularly insidious because it exploits legitimate MCP functionality: the agent is doing exactly what it was designed to do, but under attacker control.

The disclosure, documented in AuthZed's MCP breach timeline, joins a growing list of real-world MCP exploits including GitHub token leaks and RCE bugs. For enterprises using MCP-enabled agents with access to sensitive repositories, this is a wake-up call: **trust boundaries must be enforced at the MCP server level, not assumed from content provenance**. Implementing content sanitization, prompt injection detection, and least-privilege access for MCP-connected agents is no longer optional.
