# AI Security Newsletter — March 25, 2026

## Headliners

The Trivy supply chain attack from last week just detonated downstream — TeamPCP used the credentials stolen from Trivy's CI/CD compromise to publish backdoored LiteLLM packages to PyPI, poisoning a library with 97 million monthly downloads and the credentials of every developer who pip-installed it. Simultaneously, North Korean hackers pivoted their Contagious Interview campaign from fake job sites to malicious VS Code projects, Checkmarx's GitHub Actions got swept up in the same TeamPCP campaign, and Oracle shipped an emergency patch for a pre-auth RCE in Identity Manager. Today's macro theme: the blast radius from a single compromised security scanner now extends across the entire Python AI ecosystem — and the developer tools you trust are the attack surface.

## Breaking News & Phase Shifts

**[TeamPCP's Five-Day Siege: LiteLLM PyPI Compromise Exposes 97 Million Downloads — Trivy Cascade Reaches the AI Stack](https://snyk.io/articles/poisoned-security-scanner-backdooring-litellm/)**

On March 24, 2026, threat actor TeamPCP published malicious versions of LiteLLM (1.82.7 and 1.82.8) to PyPI after stealing the maintainer's PyPI publish credential from LiteLLM's CI/CD pipeline — which used the Trivy GitHub Action compromised in last week's supply chain attack. The malicious packages contained a `.pth` file (`litellm_init.pth`) that executes a credential-stealing payload automatically every time the Python interpreter starts, with no `import litellm` required. The payload exfiltrates SSH keys, cloud credentials (AWS, GCP, Azure), Kubernetes configs, Docker auth, CI/CD secrets, shell history, crypto wallets, and all environment variables to `models.litellm.cloud` (a typosquatted exfil domain) encrypted with a 4096-bit RSA key. LiteLLM confirmed the root cause as the Trivy CI compromise; the impacted versions have been pulled from PyPI. BerriAI has engaged Google's Mandiant team and paused all new releases pending supply chain audit. The Wiz blog documented that TeamPCP also compromised Checkmarx GitHub Actions in the same campaign window — the same stolen Trivy credentials were used to pivot into multiple developer security tools. **Practitioner guidance:** Any environment that ran `pip install litellm` during March 23–24 (specifically versions 1.82.7 or 1.82.8) must be treated as fully compromised — rotate all credentials accessible from that environment immediately: cloud credentials, SSH keys, PyPI tokens, Docker registry auth, Kubernetes service account tokens. The Docker-deployed LiteLLM Proxy is not affected. Pin Python package installs to hashes in `requirements.txt` going forward.

**[North Korean WaterPlum (Contagious Interview) Pivots to VS Code — StoatWaffle Malware Deployed via Auto-Run Tasks](https://thehackernews.com/2026/03/north-korean-hackers-abuse-vs-code-auto.html)**

North Korean threat actor WaterPlum, responsible for the long-running Contagious Interview campaign targeting developers and cryptocurrency firms, has evolved its delivery mechanism from fake npm packages to malicious Visual Studio Code projects. The new technique abuses VS Code's `.vscode/tasks.json` auto-run feature to execute a staged downloader that deploys StoatWaffle — a credential stealer that exfiltrates browser-stored credentials, browser extension data, iCloud Keychain databases on macOS, and a persistent remote access trojan. The campaign is distributed via fake job postings and technical screening processes, with targets tricked into cloning a "coding test" repository and opening it in VS Code. Microsoft, SC Media, and Security Affairs have all attributed this to Lazarus Group's "Team 8" sub-cluster. The vector is particularly dangerous for AI/ML practitioners who routinely clone and open external repositories as part of model evaluation, dataset review, or research. **Practitioner guidance:** Disable VS Code workspace trust bypass for external repositories — ensure VS Code prompts for trust before executing tasks in untrusted workspaces. Never clone a repository and immediately open it in VS Code during an interview or evaluation process without reviewing `.vscode/tasks.json` for unexpected commands. Treat the pattern (fake job + coding test + VS Code) as a confirmed North Korean lure profile.

**[OpenAI Shuts Down Sora — Pivots Video Research to Robotics Simulation](https://www.theguardian.com/technology/2026/mar/24/openai-ai-video-sora)**

OpenAI announced it is shutting down the Sora standalone video-generation application, just three months after signing a $1 billion Disney licensing deal that gave Sora users access to Marvel, Pixar, and Star Wars characters. OpenAI stated it will continue using video-generation technology "behind the scenes" to train robots — framing world-simulation capability as the real strategic value of video models. The shutdown strips public access to a significant generative capability and signals that OpenAI is concentrating compute on coding and robotics workstreams. Security relevance is structural: Sora's closure means that compute intensity for high-quality video generation at scale is economically unsustainable without a specialized, non-consumer use case. The same compute triage logic applies to AI red teaming and security research — frontier-level model access is consolidating toward enterprise and robotics applications, not broad consumer availability. **Practitioner guidance:** Teams that integrated Sora into workflows (deepfake detection testing, synthetic training data generation, red team simulation content) should evaluate alternative video generation APIs now. OpenAI's robotics pivot also signals a future threat surface: world-simulation models will train physical robots, creating new AI-physical world security intersections that have no current threat model.

**[CVE Program at RSAC 2026: "In Danger of Collapsing or Fading Into Irrelevance" — AI Flooding the Pipeline](https://www.cybersecuritydive.com/news/cve-program-ai-vulnerability-reports-funding/815594/)**

At an RSAC 2026 panel featuring representatives from Microsoft, Intel, and GitHub, CVE Program leaders issued a stark warning: the program that underpins the global vulnerability-fixing ecosystem is under severe strain from a combination of funding instability and an AI-driven explosion in vulnerability report volume. The CVE program has historically processed vulnerability disclosures from human security researchers at a manageable rate; AI tools are now generating vulnerability reports at a scale that existing triage and assignment infrastructure cannot absorb. Without structural changes to funding, automation of CVE processing, and governance of AI-generated submissions, the program risks either becoming a backlogged irrelevancy or collapsing entirely. The timing coincides with active exploitation of multiple known CVEs, demonstrating that CVE processing delays have real-world consequences — defenders can't patch what isn't yet assigned. **Practitioner guidance:** Treat CVE lag as a threat multiplier — if a vulnerability you have in your environment hasn't received a CVE number yet, it isn't fixed or mitigated. Maintain internal vulnerability tracking that doesn't depend exclusively on CVE assignment as the trigger for patching workflows. The AI volume problem also raises the signal-to-noise ratio challenge: as AI-generated CVE submissions increase, the quality filter on what gets assigned and prioritized becomes a first-order security concern.

## Technical Deep Dives

**[CVE-2026-21992 (CVSS 9.8): Oracle Identity Manager Pre-Auth RCE — Emergency Out-of-Band Patch, Possible Active Exploitation](https://www.bleepingcomputer.com/news/security/oracle-pushes-emergency-fix-for-critical-identity-manager-rce-flaw/)**

Oracle shipped an emergency out-of-band patch for CVE-2026-21992, a critical unauthenticated remote code execution flaw in Oracle Identity Manager and Oracle Web Services Manager, accessible via HTTP without credentials. The vulnerability allows complete compromise of the Identity Manager server and, by extension, any identity-dependent system it governs. Oracle's advisory notes the vulnerability "may have been exploited in the wild." Security Boulevard separately documented that CVE-2025-61757, an authentication bypass in the same product's REST WebServices component, was described as "somewhat trivial and easily exploitable" and may be related — Oracle has not confirmed. Identity Manager is a high-value target: compromise grants the ability to provision and modify accounts across all connected enterprise systems, making it a natural ransomware precursor and data exfiltration pivot point. **Practitioner guidance:** Apply the Oracle emergency patch immediately — do not wait for the quarterly CPU cycle. If patching cannot be completed in the next 24 hours, isolate the Oracle Identity Manager management interface from internet access and restrict to internal-only access. Review IAM audit logs for anomalous account provisioning activity from the past two weeks.

**[MCP Attack Surface: 30 CVEs in 60 Days — 38% of Public Servers Unauthenticated, 82% Vulnerable to Path Traversal](https://adversa.ai/blog/top-mcp-security-resources-march-2026/)**

A systematic security analysis of the MCP ecosystem published by Adversa AI counted 30 new CVEs filed against MCP implementations in the past 60 days. Scans of over 500 public MCP servers found that 38% have no authentication layer whatsoever — any caller can invoke any tool. 82% of surveyed implementations are vulnerable to path traversal via file system operations, enabling attackers to read or write arbitrary files on the host running the agent. The research also documents a newly characterized class of economic attack: "Overthinking Loops," in which a malicious MCP server returns ambiguous tool outputs that induce the calling agent to enter an infinite reasoning loop, multiplying token consumption by up to 142x and creating a denial-of-wallet attack against pay-per-token deployments. This is distinct from prompt injection — the agent is technically doing "useful" work, making it invisible to token-budget monitoring that checks for a single spike rather than prolonged elevation. **Practitioner guidance:** Three controls close most of this exposure: (1) run MCP servers only from an authenticated network layer — no anonymous MCP endpoints in production; (2) input-validate all file operation parameters for path traversal before execution; (3) implement agent-level reasoning budget limits with automatic circuit-breaker behavior when token consumption exceeds threshold. The 30-CVE-in-60-days rate means your MCP server inventory from two months ago is already stale.

**[HackerOne Formalizes "Agentic Prompt Injection" as a Test Category — Bug Bounty Platform Now Accepts Autonomous Agent Exploit Reports](https://www.cybersecurity-insiders.com/hackerone-introduces-agentic-prompt-injection-testing-as-ai-security-risks-accelerate/)**

HackerOne formally introduced Agentic Prompt Injection Testing as a distinct category within its Penetration Testing as a Service (PTaaS) platform, alongside a new program type that explicitly scopes AI agents — not just static LLM interfaces — for bug bounty testing. The move reflects a shift from testing what a model *says* to testing what an agent *does* when given adversarial inputs through tool interfaces, RAG data pipelines, or chained agent instructions. HackerOne CPO Nidhi Aggarwal noted: "Security teams can't rely on static controls or runtime filters alone. They need validated proof of whether an AI system can be exploited once it's connected to real data and tools." The platform change is a market signal: bug bounty infrastructure now treats autonomous agents as first-class attack surfaces with their own vulnerability taxonomy. **Practitioner guidance:** If your organization operates AI agents with access to production data or systems, consider adding them to a bug bounty scope. The formal HackerOne category means researchers now have structured submission criteria — which also means attackers have a clearer public taxonomy of what to look for. Proactive bug bounty exposure beats reactive incident response for agent vulnerabilities.

## Five Things to Take Into the Rest of the Day

1. **The LiteLLM compromise is the Trivy supply chain attack's second-order detonation, and there's no reason to think TeamPCP has stopped at two targets.** The Wiz blog documented that Checkmarx GitHub Actions were also compromised in the same campaign window. The pattern — steal Trivy CI credentials, use them to access any CI system that used Trivy-action, harvest that CI's secrets, use those credentials to compromise downstream packages or infrastructure — is a systematic campaign, not opportunistic. Every engineering team using Trivy-action before March 22 should treat the CI/CD secrets accessible during that window as compromised and rotate them. The question isn't whether TeamPCP touched your pipeline — it's whether you've confirmed they didn't.

2. **North Korean developer-targeting has reached a new level of operational precision: malicious VS Code projects are now the delivery mechanism, and AI/ML practitioners who clone external repos are a high-value target profile.** The Contagious Interview campaign originally targeted Web3 and cryptocurrency developers. StoatWaffle's deployment via VS Code auto-run tasks is a logical evolution — AI/ML researchers and engineers routinely open external repositories as part of model evaluation, dataset review, and research replication. The `.vscode/tasks.json` vector requires no code review to trigger — just opening the project in VS Code with workspace trust not properly configured. Review your VS Code workspace trust settings today, and add "review `.vscode/tasks.json` before opening" to your external repository intake checklist.

3. **The CVE program's AI-driven volume crisis is a signal that your vulnerability management program cannot be solely reactive to CVE assignment.** If AI tools are flooding the CVE pipeline with machine-generated reports, the average time from disclosure to CVE assignment is increasing while the average time from disclosure to exploit is decreasing. The Oracle Identity Manager emergency patch for CVE-2026-21992 demonstrates that critical vulnerabilities still reach full exploitation risk even when CVEs are processed — but if the backlog grows, you'll be patching on a delayed clock while attackers operate on a real-time one. Build internal vulnerability tracking that captures disclosed-but-unassigned vulnerabilities from trusted sources (vendor advisories, security blogs, NVD pre-CVE notifications) and doesn't wait for the CVE number to trigger your patch workflow.

4. **Google's TurboQuant is a security architecture accelerant: 6x model compression with zero accuracy loss means the inference sovereignty argument for local AI workloads just got dramatically stronger.** Every AI workload running on a cloud API is a potential exfiltration surface — prompt data, context, and model outputs pass through a third-party infrastructure with its own security posture and data policies. Local inference eliminates that surface entirely. TurboQuant's ability to run models that previously required cloud infrastructure on consumer hardware means the "we have to use the cloud because local inference isn't good enough" argument is weakening for a wider class of models. If your organization handles sensitive data and relies on cloud AI APIs, reassess whether local inference is now viable for your workload profile.

5. **The HackerOne formalization of agentic prompt injection as a bug bounty category is a leading indicator: autonomous agent security is transitioning from research taxonomy to operational vulnerability class with monetary incentive.** When bug bounty programs start paying for a category, two things happen: the best offensive researchers focus on it, and the organizations that haven't hardened against it start facing confirmed proof-of-concept exploits. If your AI agents aren't in scope for security testing, they are implicitly assumed to be hardened without evidence. Add your production agents to your bug bounty scope, or run internal red teaming against them, before external researchers do it for you and submit a report — the HackerOne category means they now have structured submission guidance on exactly what to look for.
