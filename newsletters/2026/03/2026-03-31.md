### **The Axios NPM Package Was Poisoned Overnight With a Cross-Platform RAT — 100 Million Weekly Downloads, a Pre-Staged Attack, and Self-Destructing Malware**

Axios — the JavaScript HTTP client installed by virtually every Node.js project on earth — was compromised on npm last night in one of the most operationally sophisticated supply chain attacks ever documented against a top-10 package. StepSecurity identified two malicious versions published to the registry: `axios@1.14.1` and `axios@0.30.4`, both poisoned via the compromised account of lead maintainer Jason Saayman. The attack vector was a fake dependency injected into both versions: `plain-crypto-js@4.2.1`, a package that had been staged 18 hours in advance by a Proton Mail account with no prior npm history. That dependency's sole purpose was to run a postinstall script that drops a cross-platform remote access trojan — targeting macOS, Windows, and Linux — then contacts a live C2 server at `sfrclak.com:8000`, delivers platform-specific second-stage payloads, and self-destructs by deleting itself and replacing its own `package.json` with a clean decoy. A developer who inspects `node_modules` after the fact finds no evidence anything happened. npm pulled both versions by approximately 03:15 UTC; by then, the packages had been live for roughly three hours during peak CI/CD activity windows in Asia-Pacific and early Europe.

Key findings:

- **Affected versions**: `axios@1.14.1` and `axios@0.30.4` — both branches poisoned 39 minutes apart
- **Pre-staging**: malicious dependency `plain-crypto-js@4.2.1` seeded on npm 18 hours before the attack to establish publishing history and avoid "zero-history" scanner flags
- **Self-destruction**: malware deletes itself post-execution; `node_modules` inspection yields no evidence
- **C2 server**: `sfrclak.com:8000` — confirmed live during attack window; flag this domain in your network monitoring
- **Detection path**: StepSecurity Harden-Runner flagged anomalous outbound connection to `sfrclak.com:8000` during a Backstage framework CI run — the connection had never appeared in prior workflow runs
- **Timeline**: `plain-crypto-js@4.2.1` published March 30 23:59 UTC → `axios@1.14.1` published March 31 00:21 UTC → `axios@0.30.4` published March 31 01:00 UTC → both unpublished ~03:15 UTC
- **Payload**: platform-specific second-stage payloads — macOS: AppleScript dropper persisting to `/Library/Caches/com.apple.act.mond`; Windows: VBScript + PowerShell disguised as `wt.exe`; Linux variant also confirmed
- **Impact scope**: any CI/CD pipeline, Docker build, or local dev environment that ran `npm install` (or `npm ci` without a lockfile pin) between 00:21–03:15 UTC on March 31 is potentially compromised

> **"This is among the most operationally sophisticated supply chain attacks ever documented against a top-10 npm package. There are zero lines of malicious code inside axios itself — and that's exactly what makes this attack so dangerous."** — StepSecurity blog, March 31, 2026

The attack exploited a dependency injection vector rather than modifying axios source code directly — meaning code review of axios itself would have caught nothing. The self-destructing dropper mechanism is designed for exactly this environment: CI/CD pipelines that don't retain build artifacts. If your pipeline ran during the attack window and you don't have outbound network monitoring, you may have no forensic evidence that anything happened — even if a RAT was successfully deployed. The StepSecurity Harden-Runner detection worked specifically because it compares every outbound connection against a historical baseline; organizations without similar egress monitoring are effectively flying blind on this attack class.

**Immediate actions:**
- Audit lockfiles (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`) for any reference to `axios@1.14.1`, `axios@0.30.4`, or `plain-crypto-js@4.2.1` — if found, treat the system as compromised and initiate incident response
- Check CI/CD logs for `npm install` runs between 00:21 UTC and 03:15 UTC on March 31; correlate with any outbound connections to `sfrclak.com:8000`
- If compromise is suspected: rotate all secrets accessible from the affected build environment (cloud credentials, API keys, database passwords, deploy tokens)
- Implement outbound network monitoring on CI/CD runners — StepSecurity Harden-Runner (free for public repos) or equivalent; without egress monitoring, this class of attack is undetectable after self-destruction
- Pin axios to a verified safe version in your lockfile (`1.7.x` or `0.29.x`) until this is resolved; do not rely on `latest` tags
- Block `sfrclak.com` at your network perimeter and add to your threat intelligence feeds

### **Anthropic's Claude Code Had Its Entire Source Code Exposed Through an npm Sourcemap — 512,000 Lines, 40 Tools, Agent Architecture Revealed**

Security researcher Chaofan Shou (@shoucccc) discovered this morning that Anthropic shipped Claude Code — their flagship agentic CLI tool — with an unminified JavaScript sourcemap (`cli.js.map`) bundled directly into the npm package. Sourcemaps are meant to be development-only artifacts that map compiled JavaScript back to original source; including them in a production npm release inadvertently ships the original TypeScript source to every developer who installs the package. The leaked codebase clocks in at approximately 1,900 TypeScript files and 512,000+ lines of code, exposing Claude Code's internal architecture in detail: the query engine (46,000 lines handling all LLM API calls, streaming, and orchestration), the tool permission system (~40 discrete tools with `PermissionGate` structures), multi-agent orchestration ("swarm" architecture for parallel sub-agents), the IDE bridge system (JWT-authenticated VS Code and JetBrains communication), and the persistent memory system. Mirrors of the repository appeared on GitHub within hours — `instructkr/claude-code` surpassed 1,100 stars and 1,900 forks before Anthropic could respond publicly. This is not a breach of Anthropic's infrastructure; it is an accidental disclosure via build artifact — but the security implications are material.

Key findings:

- **Disclosure mechanism**: unminified `cli.js.map` sourcemap bundled into the production npm package — present in every install of `@anthropic-ai/claude-code`
- **Scale of exposure**: ~1,900 TypeScript files, 512,000+ lines of code, ~40 built-in tools, ~50 slash commands
- **Architecture exposed**:
  - Query engine: 46,000 lines — all LLM API calls, streaming, caching, orchestration
  - Tool permission system: discrete `PermissionGate` per tool (bash execution, file read/write, web fetch, MCP, LSP)
  - "Swarm" multi-agent orchestration: sub-agents spawned with specific tool permission scopes
  - IDE bridge: JWT-authenticated bidirectional channel to VS Code/JetBrains extensions
  - Memory system: file-based persistent context across sessions
- **Runtime**: Bun (not Node.js) — dead code elimination used for feature flag management
- **Anthropic response**: no public statement at time of publication; mirrors proliferating on GitHub

> **"This isn't a toy project. Claude Code is a production-grade, heavily architected system. The leaked source reveals just how far beyond a 'chat wrapper' this tool really goes."** — Gabriel Anhaia, Dev.to analysis, March 31, 2026

The security implications split into two categories. First, the architectural exposure: understanding Claude Code's tool permission system, safety filter logic, and orchestration mechanisms gives adversarial researchers a detailed roadmap for crafting targeted attacks against Claude Code deployments. The `PermissionGate` architecture and its implementation details are now public knowledge. Second, the intellectual property dimension: Anthropic's most competitively sensitive engineering — the orchestration design, the streaming implementation, the memory architecture — is now readable by every competitor. The incident is a concrete example of why build pipelines need explicit sourcemap stripping for production npm packages — a check that is missing from many engineering organizations' release processes.

**Immediate actions:**
- If you run security tooling or red team AI coding agents: note that Claude Code's internal tool permission and safety filter architecture is now public — adjust your threat model for Claude Code deployments accordingly
- For engineering teams shipping npm packages: audit your build pipeline for accidentally included sourcemap files — add an explicit step to strip `.map` files before publish or configure `package.json` `files` field to exclude them
- Monitor the `instructkr/claude-code` and `Kuberwastaken/claude-code` GitHub mirrors for any security researchers publishing exploits based on the exposed architecture
- Treat Claude Code deployments with elevated scrutiny until Anthropic releases a statement on whether any security-sensitive logic (safety filters, auth mechanisms) needs to be updated following the exposure

### **Mandiant M-Trends 2026: Attacker Handoff Time Collapses to 22 Seconds, Voice Phishing Surges, and AI-Generated Records Enter the Litigation Landscape**

Google's Mandiant released M-Trends 2026 today — the annual frontline incident response report based on 500,000+ hours of investigations conducted globally in 2025 — and the headline number is a gut-punch: the median time between initial access and handoff to a secondary threat group inside a compromised network has collapsed from over 8 hours (2022) to 22 seconds. That is not a typo. The ecosystem has industrialized to the point where access brokers, ransomware operators, and espionage groups are operating with sub-minute handoff protocols. By the time a SOC analyst finishes reading the alert that signals initial access, the network may have already changed hands. Alongside the speed finding, M-Trends 2026 documents the surge of voice phishing (vishing) as a primary initial access vector — attackers are calling employees directly and social-engineering their way past MFA — and flags a new dimension that most security teams haven't addressed: AI-generated records (SOC decision traces, AI meeting transcripts, agentic workflow logs) are now discoverable, holdable, and contestable in litigation.

Key findings:

- **22-second handoff**: median time from initial access to secondary-group handoff — down from 8+ hours in 2022; access brokerage has industrialized at machine speed
- **Voice phishing surge**: vishing is now a primary initial access vector alongside exploitation — attackers are bypassing MFA and endpoint security by calling employees directly
- **Ransomware playbook evolution**: sophisticated crews now destroy backup and recovery infrastructure *before* encrypting, not after — eliminating the recovery option before the ransom demand
- **Edge device persistence**: sophisticated espionage groups are establishing persistence specifically on unmonitored edge devices (routers, VPN concentrators, IoT) using native network functions to evade EDR coverage
- **AI-generated records as evidence**: SOC decision traces, AI meeting transcripts, and agentic workflow logs are now entering the discoverable evidence landscape — a dimension most legal and compliance teams haven't prepared for
- **Grounding**: 500,000+ hours of frontline IR in 2025; this is observed behavior, not projected threat modeling

> **"The vast majority of successful intrusions still stem from fundamental human and systemic failures — but the pace at which those failures are exploited has changed the math for defenders entirely."** — Jurgen Kutscher, VP Mandiant Consulting, Google Cloud

The 22-second handoff number fundamentally invalidates "detect and respond" as a viable primary strategy for organizations that have not also invested in prevention and pre-positioning. If attacker handoff happens in 22 seconds, alert triage times measured in minutes or hours mean you are responding to a fully established multi-group intrusion, not an initial access event. The operational implication: detection is still necessary but no longer sufficient; the response capability that matters is eviction speed and blast radius containment, not detection speed. For organizations still measuring MTTD (mean time to detect) as their primary security KPI, M-Trends 2026 is the argument for shifting that KPI to MTTR (mean time to respond/remediate) and MTBC (mean time to blast radius containment).

**Immediate actions:**
- Implement a voice phishing awareness program specifically addressing MFA bypass scenarios — attackers are calling help desks and employees directly; training needs to cover "what to do when someone calls claiming to be IT"
- Audit your backup and recovery infrastructure for attackers who may already be present — look for unauthorized access to backup systems, shadow copy deletion, and VSS manipulation in your SIEM
- Extend EDR coverage to edge devices — VPN concentrators, routers, and unmanaged IoT that lack traditional EDR agents are explicitly the persistence mechanism M-Trends 2026 documents
- Brief your legal and compliance teams on AI-generated record retention: SOC runbooks, AI assistant conversation logs, and agentic workflow audit trails may be discoverable in litigation — establish a retention policy before it becomes urgent

### **GitHub Copilot Kills PR Ad Injection After 11,400+ Repositories Affected — But the Mechanism That Enabled It Remains**

In a 24-hour whiplash cycle: Monday, developer Zach Manson documented that GitHub Copilot had injected promotional copy for Raycast into his PR description via hidden HTML comments tagged `START COPILOT CODING AGENT TIPS`. By Monday afternoon, GitHub VP of developer relations Martin Woodward confirmed the reversal — Copilot's ability to edit PR descriptions it didn't originally create has been removed. This story was covered in yesterday's newsletter from the discovery angle; today's development is the reversal and its security implications. The critical nuance from Woodward's X post: inserting promotional "tips" into PRs *created by Copilot* was existing, intentional behavior — what changed was extending that capability to any PR where Copilot was *mentioned*. That extension, which ran for an unknown duration, affected 11,400+ repositories before the rollback.

Key findings:

- **CVE**: none; this is behavioral/policy, not a software vulnerability
- **Affected scope**: 11,400+ pull requests across multiple repositories received injected content
- **Mechanism**: hidden HTML comment block (`START COPILOT CODING AGENT TIPS`) allowed Copilot to insert trusted-appearing content into PR descriptions authored by other users
- **The reversal**: GitHub removed the ability for Copilot to edit PR descriptions it didn't originally create — the feature that enabled cross-PR injection
- **What remains**: Copilot can still insert "tips" into PRs *it creates* — the same hidden-comment mechanism remains functional for Copilot-authored PRs
- **Security implication that survived the rollback**: the `START COPILOT CODING AGENT TIPS` hidden comment pattern is now a documented, public injection template — any prompt injection attack that can cause Copilot to process a PR could theoretically use this mechanism to insert content that downstream AI tools will read and act on

> **"I wasn't even aware that the GitHub Copilot Review integration had the ability to edit other users' descriptions and comments. I can't think of a valid use case for that ability."** — Zach Manson, via The Register

The security lesson that outlasts the reversal: the same hidden-HTML-comment injection mechanism that Copilot used for marketing is structurally identical to how indirect prompt injection works in agent contexts. Copilot injected "trusted" content — content that appears inside a PR description that other AI agents will later read and act on — via a mechanism that was invisible to the PR author. That attack surface was proven functional at scale (11,400 PRs). The rollback removed the accidental deployment; it did not remove the fundamental capability or the attack pattern it demonstrated.

**Immediate actions:**
- Search your organization's GitHub repositories for `START COPILOT CODING AGENT TIPS` to identify PRs that received injected content; review for any unexpected or off-policy material
- Review Copilot's permissions in your GitHub organization settings — specifically what actions it can take on PRs it didn't create; verify the rollback is reflected in your enterprise settings
- Treat the incident as a behavioral proof of concept for your AI coding tool threat model: if Copilot can inject hidden HTML comments that downstream tools trust, so can a prompt injection attack that achieves similar document modification

## Five Things to Take Into the Rest of the Day

**1. The axios attack is the supply chain nightmare scenario made real — and the industry's postinstall hook problem finally has a face.**
The `postinstall` script mechanism in npm has been flagged by security researchers for years as a vector for malicious code execution with no user confirmation: `npm install` runs it automatically, and nothing in the default npm CLI warns you that a transitive dependency just executed arbitrary code on your machine. The axios attack exploited this mechanism to within two seconds of install completion, before npm had even finished resolving the dependency tree. The broader industry conversation that needs to follow this incident: should npm disable postinstall scripts by default and require explicit opt-in? The axios attack provides the argument that has been missing from that debate. For now, `--ignore-scripts` in npm install is your mitigation — but it breaks legitimate tools that depend on the same mechanism.

**2. The Claude Code source leak is a security architecture stress test, not just an IP embarrassment.**
The exposed `PermissionGate` system — which governs what tools Claude Code can invoke and under what conditions — is now a public document. Every security researcher who wants to build targeted prompt injection or tool manipulation attacks against Claude Code deployments now has a detailed implementation map to work from. The security implication timeline: expect within weeks to see researchers publishing specific attack patterns against Claude Code's tool permission system based on the leaked architecture. If you run Claude Code in enterprise environments, your threat model just expanded, and Anthropic needs to ship updated safety controls before those attack patterns are operationalized.

**3. Mandiant's 22-second handoff number is the argument for shifting your security KPIs from detection to containment.**
MTTD — mean time to detect — has been the primary security operations metric for a decade. At 22-second initial-access-to-handoff, MTTD is a trailing indicator, not a control. By the time your SIEM fires an alert, investigates, and a human analyst reads it, the network has changed hands multiple times. The metric that matters in 2026 is MTBC: mean time to blast radius containment. How fast can you isolate a compromised system, revoke credentials, and cut off lateral movement — regardless of when you detected the initial access? That operational question requires pre-built playbooks and automated containment capabilities that most organizations don't have.

**4. The ransomware industrialization numbers from CipherCue give M-Trends 2026 its operating context.**
7,655 victim claims in 376 days from 129 groups — that's one new named victim every 71 minutes. Qilin alone is claiming 3.1 victims per day across 74 countries. These are not opportunistic attackers; they're operating at the scale and cadence of a software delivery pipeline. The 22-second handoff time Mandiant documents is the velocity of the *professional* side of this ecosystem. Manufacturing (890 claims) and Technology (843 claims) as the top targeted sectors means if you're in either space, you're not a potential target — you're a statistical certainty over a 12-month planning horizon. Ransomware readiness (tested backups, tested recovery procedures, blast radius containment playbooks) is not a nice-to-have in 2026.

**5. Today is the day npm's trust model visibly cracked — and the fix requires industry-level changes, not just better lockfiles.**
Pinning your lockfile and auditing postinstall scripts are good hygiene — but they don't address the systemic problem the axios attack exposed: a compromised maintainer account can publish malicious versions of any package, and the ecosystem has no mandatory authentication mechanism (like sigstore/npm provenance) that would have flagged the discrepancy between the legitimate jasonsaayman account and the compromised `ifstap@proton.me` email used for the attack. npm provenance (introduced in 2023) can help, but it's opt-in and not yet widely adopted. The axios attack is the argument for making npm package provenance mandatory — the same argument that the XZ Utils backdoor made for the Linux ecosystem. Add sigstore-based npm provenance verification to your supply chain security requirements for critical dependencies today.
