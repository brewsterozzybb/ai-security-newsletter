### **2. Anthropic DXT: Zero-Click RCE, Full System Privileges — Anthropic Reviewed It and Won't Fix the Architecture**

LayerX Security published a critical finding this week: Anthropic's **Claude Desktop Extensions (DXT)** run unsandboxed with full system privileges, and a maliciously crafted Google Calendar invite can trigger arbitrary local code execution without user awareness. The chain: a malicious calendar connector feeds a crafted event to a high-risk local executor DXT — which then runs attacker-controlled code at full system privilege level. No interaction required beyond having Claude Desktop open with calendar integration enabled.

**The architectural decision:** Anthropic reviewed LayerX's findings and **declined to change the DXT architecture**. The framing: deployment configuration is the operator's responsibility, not a product-level flaw. This is not a patch-and-move-on situation. This is a documented architectural choice to run extensions with full system privileges, with the security posture of each deployment delegated entirely to the operator.

**The pattern this fits:** Perplexity Comet's calendar-to-1Password exfiltration (Zenity Labs, March 9), Chrome Gemini's camera/mic/file access via inherited permissions (CVE-2026-0628, March 10), and now DXT's full-system-privilege calendar chain. All three follow the same pattern: AI assistants inheriting ambient system permissions that significantly exceed their core use case, creating attack vectors through the AI integration layer that users never explicitly granted. The AI is not the vulnerability — the permission model is.

**Practitioner guidance — immediate:** Audit which Claude Desktop Extensions are deployed in your enterprise environment. Any DXT with network connectivity, calendar access, or file system write capability and no sandboxing boundary is a zero-click RCE surface if a user receives a malicious calendar invite. Implement allowlisting for DXT installations via your MDM/endpoint policy. Treat DXT deployments with the same security posture as browser extensions with admin privileges — because that is effectively what they are. Consider whether Claude Desktop is appropriate for high-sensitivity environments without explicit sandbox controls.

### **3. Microsoft "AI as Tradecraft": APT Groups Now Use Generative AI Across the Full Kill Chain**

Microsoft Threat Intelligence published the most authoritative public confirmation yet that AI-assisted attacks are standard APT tradecraft across named threat groups. The **"AI as Tradecraft"** report documents generative AI use across every phase of the kill chain: reconnaissance, spear-phishing lure creation, identity fraud, malware development, and post-compromise scripting.

**The North Korea IT worker scheme detail:** Named groups **Jasper Sleet (Storm-0287)** and **Coral Sleet (Storm-1877)** are using generative AI to produce complete fake identity packages — realistic names, resumes, LinkedIn profiles, email formats, and reference letters — to infiltrate organizations as remote IT contractors. The AI component is not a gimmick: it enables identity generation at a scale and quality that human operators couldn't match. Microsoft frames these actors as using AI to "reduce technical friction while humans retain targeting control" — the human-AI collaboration model that CyberStrikeAI pioneered in the FortiGate campaign (covered March 7) is now the described norm for North Korean operators.

**The force multiplication finding:** Across all documented threat groups, Microsoft identifies the consistent pattern: AI doesn't replace human strategic judgment, it removes the technical skill barriers and time costs that previously constrained adversary throughput. An operator who previously needed malware development skills now needs only targeting judgment — AI handles the rest.

**Practitioner guidance:** The IT contractor infiltration scheme is particularly hard to detect with conventional background check processes — AI-generated identities pass document verification, LinkedIn profile checks, and reference checks because the AI produces coherent, contextually accurate supporting material. Organizations with remote IT contractor workflows should implement video verification processes, cross-reference employment history claims against state licensing databases, and audit contractor access patterns for anomalous privilege use patterns in the first 60 days.

### **4. "LeakyLooker": Nine Cross-Tenant SQL Injection Flaws in Google Looker Studio — Including a Denial-of-Wallet Variant**

Tenable disclosed **"LeakyLooker"** — nine cross-tenant vulnerabilities in Google Looker Studio that could have allowed attackers to run arbitrary SQL queries against victim databases across the Google Cloud environment. Affected connectors span BigQuery, Spanner, PostgreSQL, MySQL, Google Sheets, and Cloud Storage. Responsibly disclosed in June 2025, all nine were patched by Google with no evidence of in-the-wild exploitation.

**The denial-of-wallet variant:** Among the nine, one allows attackers to trigger runaway BigQuery queries against victim tenants — accumulating large query costs charged to the victim's Google Cloud billing account without exfiltrating a single byte of data. This introduces financial sabotage as an attack class distinct from data theft — and it is particularly insidious because it passes entirely through authorized API calls, making attribution difficult and traditional data loss detection blind to it.

**The pattern:** This is the second major cloud-native BI/analytics cross-tenant disclosure in recent months. Cloud platforms that aggregate and process multi-tenant enterprise data are high-value targets for cross-tenant attacks — and the attack surface is every data connector and service integration endpoint. The financial DoW variant also connects directly to this week's MCP Overthinking Loop finding (Section 2), which uses a different mechanism but achieves the same financial damage.

**Practitioner guidance:** Review Looker Studio connector configurations for your organization's GCP environment. Audit BigQuery query access controls and billing alert thresholds — even with LeakyLooker patched, financial DoW via runaway queries is a threat class worth detection coverage. If you're using any cloud BI platform that connects to multiple data sources, your cross-tenant isolation model deserves explicit review.

### **1. CVE-2026-30859 — WeKnora Cross-Tenant API Key Theft: Third CVE in the WeKnora Cluster**

Following CVE-2026-30855 and CVE-2026-30856 (the tool name collision CVE covered March 10), Tencent's WeKnora framework has a third fresh disclosure: **CVE-2026-30859**, a broken access control vulnerability enabling cross-tenant data exfiltration. The specific data exposed includes third-party LLM API keys, private message histories, and proprietary model configurations stored by other tenants on the same platform instance.

**Why API key theft is the critical impact here:** LLM API keys grant billing-charged access to frontier models. An attacker who steals your Anthropic, OpenAI, or Gemini API keys can impersonate your AI workloads, drain your API budget, and potentially access model configurations and system prompt content you've treated as proprietary. API key theft from a multi-tenant LLM platform is a direct path into the victim's AI infrastructure — with none of the credential footprint of traditional account compromise.

**The WeKnora CVE cluster pattern:** Three CVEs in rapid succession (tool collision, access control bypass, cross-tenant exfiltration) indicates a platform that hasn't been through serious security review. This is the MCP ecosystem's analog to early npm — fast deployment, minimal security posture, significant vulnerability density. Any production deployment of WeKnora should treat all three CVEs as an active cluster and patch to v0.3.0 immediately.

**Practitioner guidance:** Beyond WeKnora — audit every multi-tenant LLM platform in your stack for cross-tenant isolation controls. If the platform shares infrastructure across tenants and has not explicitly documented its tenant isolation architecture, assume the isolation model has not been adversarially tested. Rotate any LLM API keys that may have been exposed in WeKnora deployments prior to v0.3.0.

### **2. MCP "Overthinking Loop": 142x Token Amplification as Denial-of-Wallet**

Adversa AI (citing new arXiv research) documented a novel MCP attack class this week: the **"Overthinking Loop"** — where a malicious MCP tool server crafts responses to appear perpetually incomplete, inducing the agent to re-call tools recursively until API budget is exhausted. Documented amplification: **142.4x token consumption** and dramatically elevated per-task latency.

**The financial math:** At current GPT-5/Claude API pricing, a single agent session processing a malicious overthinking payload can accumulate costs that would normally represent weeks of normal usage. In enterprise environments where agents run on shared API budgets across teams, a single malicious MCP server interaction can exhaust the entire organization's AI API budget for a billing period.

**The attack surface:** Any agent that connects to third-party MCP servers — whether for tool use, data retrieval, or service integration — is exposed to this attack if the server is malicious or compromised. The attack requires no API key theft, no credential compromise, and no data exfiltration. It is purely a financial sabotage mechanism delivered through normal protocol interaction.

**The cumulative MCP threat picture:** Tool name collision (CVE-2026-30856), cross-tenant API key theft (CVE-2026-30859), 38% of servers lacking auth, CVSS 10.0 RCE in the reference implementation, tool poisoning at 72.8% success, and now a 142x financial amplification attack. MCP in March 2026 is where npm was in 2015 — the attack surface is forming faster than the security controls.

**Practitioner guidance:** Implement API usage rate limits and budget alerts at the agent session level — not just the organization level. Alerting on per-session token consumption spikes (e.g., >10x baseline in a single session) provides early detection for both overthinking loops and tool poisoning attacks. Enforce strict MCP server allowlisting: agents should only connect to explicitly approved, audited MCP servers. Do not allow agents to discover and connect to new MCP servers without human review.

### **3. Microsoft Agent 365 — Enterprise Control Plane for AI Agents, GA May 2026**

Microsoft announced **Agent 365** as part of the new Microsoft 365 **E7: The Frontier Suite** (GA May 1, 2026, $99/user/month): a unified control plane for governing deployed AI agents across the enterprise. Features:

- **Agent Registry** — Inventory of all deployed agents (Microsoft + partner ecosystem)
- **Agent Behavior Observability** — Logging and anomaly detection across agent actions
- **Identity via Entra** — Non-human identity management for agents, plugging into existing MFA and conditional access frameworks
- **Defender + Purview Integration** — Security monitoring and data governance applied to agent workflows

**The explicit threat model in the product spec:** Microsoft's documentation directly names preventing agents from becoming "double agents" through unauthorized access, data leakage, and adversarial manipulation. This is the first time a major enterprise vendor has shipped a product with agentic security threat taxonomy as a documented design requirement.

**The governance gap it fills:** The core problem is agent sprawl — organizations deploying dozens of agents across business units, each with different permission scopes, data access, and no central visibility. Agent 365's registry and identity model creates the equivalent of an Active Directory for AI agents — which is the right architectural analog. Active Directory's success came from centralizing identity management that had previously been fragmented across applications.

**The price signal:** $99/user/month is the top-tier enterprise price point — not a broad-market SKU. Microsoft is pricing this for regulated industries and enterprises where agent governance is a compliance necessity, not a nice-to-have. If your industry has audit requirements that will eventually apply to AI agent actions (and they will), this is where Microsoft is building the control surface.

**Practitioner guidance:** Start your agent inventory now, regardless of whether you're in the E7 migration path. The discipline of knowing what agents are deployed, what they have access to, and what actions they can take autonomously is foundational security hygiene that doesn't require a product to implement. When Agent 365 GA's in May, having an existing agent inventory will accelerate onboarding. If you're evaluating E7, the agent governance capability is the strongest security-specific justification in the SKU.

### **4. OpenAI Acquires Promptfoo — Red-Teaming Capability Folds Into the Platform**

OpenAI confirmed plans to acquire **Promptfoo**, the open-source LLM red-teaming and evaluation framework used by security teams to test AI systems for prompt injection, jailbreak vulnerability, and policy violations. Promptfoo will be integrated into OpenAI's platform security tooling alongside **Codex Security** (covered March 9 — the vulnerability scanning agent that found 11,000 high-severity bugs in a month).

**The strategic consolidation signal:** OpenAI is building a security capability stack: Codex Security for outbound vulnerability scanning, Promptfoo for inbound adversarial testing of LLM deployments. This positions OpenAI as a vertically integrated AI security provider — you build with OpenAI's models, you also test them with OpenAI's tools. The market implication is significant: the red-teaming tooling ecosystem that grew up around LLM security is now being absorbed by the model vendors.

**The open-source community concern:** Promptfoo was community-developed and widely used by practitioners who preferred vendor-independent testing tooling. Post-acquisition, the independence of Promptfoo's testing coverage for OpenAI's own models becomes a legitimate concern. Watch whether Promptfoo's open-source repository maintains its model-agnostic coverage post-integration.

**Practitioner guidance:** If you're using Promptfoo in your AI security testing pipeline, evaluate whether the acquisition changes your trust model for the tool's OpenAI coverage. Consider maintaining parallel testing with non-OpenAI-affiliated red-teaming frameworks (Garak, PyRIT) for model-agnostic coverage. The acquisition of defensive tooling by model vendors is a market dynamic worth tracking across the ecosystem.
