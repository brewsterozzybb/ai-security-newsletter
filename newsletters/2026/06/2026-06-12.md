### Miasma Worm: Self-Replicating Supply Chain Attack Compromises 73 Microsoft GitHub Repos, Targets AI Coding Agents

On June 5, GitHub's automated enforcement systems detected malicious commits in **Azure/durabletask**, one of Microsoft's public repositories. Within 105 seconds, the platform disabled **73 repositories** across four Microsoft organizations — Azure, Azure-Samples, Microsoft, and MicrosoftDocs. The cause was **Miasma**, a self-replicating supply chain worm that represents a new class of attack: malware that weaponizes AI coding agents as both the infection vector and the propagation mechanism.

**How It Works:**

Miasma spreads through compromised open-source packages on PyPI, npm, and RubyGems. When a developer opens an infected repository in an AI-powered coding tool — VS Code, Claude Code, Cursor, or Gemini — the worm activates. It harvests cloud credentials (AWS, GCP, Azure) from environment variables, configuration files, and — critically — from **GitHub Actions runner process memory**, where secrets exist in unmasked form. This technique bypasses GitHub's secret masking entirely by reading `/proc/*/mem`.

The payload also injects persistent backdoors into AI coding-assistant configuration files, poisoning the code that AI agents generate for future users. As of the latest reporting, **over 304 components and 73 Microsoft GitHub repositories** have been confirmed impacted, with investigations ongoing into further downstream exposure.

**The Azure Functions Action Collateral Damage:**

When GitHub disabled the compromised `azure/functions-action` repository, every CI/CD workflow in the world that referenced `azure/functions-action@v1` stopped resolving. The incident demonstrated a structural vulnerability in the software supply chain: a single compromised action repository can cascade into a global build failure.

**Miasma v2: The npm Variant**

Within 48 hours, researchers at **Semgrep** and **StepSecurity** identified a second variant — **Miasma v2** — spreading through npm via malicious `binding.gyp` files. This variant compromised **57 packages** and added credential harvesting from 1Password, gopass, and pass credential stores alongside the cloud provider targets.

**Why It Matters:** Miasma is not a traditional supply chain attack. It is the first documented worm that uses AI coding agents as both the trigger and the propagation vector. Opening a compromised repository in an AI editor is sufficient to activate it. For organizations deploying AI coding tools, this means the security model must extend beyond code review: the act of opening a repository in an AI-assisted editor is now a trust decision. The attack also demonstrates that GitHub Actions secrets — long considered a secure mechanism — can be extracted from runner process memory, invalidating a core assumption of CI/CD security.

### Anthropic's Claude Fable 5 Data Retention Policy Sparks Enterprise Governance Clash — Microsoft Blocks Employee Use

On June 9, **Anthropic** released **Claude Fable 5**, its first Mythos-class model made generally available. The model brings capabilities that exceed any previous Anthropic release — state-of-the-art on software engineering, knowledge work, vision, and scientific research benchmarks. But the release came with a policy change that has triggered a governance confrontation between two of AI's largest players.

**The Policy:**

For Claude Fable 5 and all future Mythos-class models, Anthropic introduced a **mandatory 30-day data retention policy**. Prompts submitted to and outputs generated by these models are retained for 30 days for trust and safety purposes on every platform where the models are offered — including third-party surfaces like AWS Bedrock. Content flagged by Anthropic's trust and safety classifiers can be retained for up to **two years**. Unlike other Claude API models, Fable 5 does not support Zero Data Retention (ZDR).

Anthropic stated that the data will not be used for training and that all human access is logged. The company's rationale: "The data will help us defend against complex and novel attacks (including new jailbreaks and attacks that operate across many requests) as well as help us identify and reduce false positives."

**Microsoft's Response:**

**Microsoft** — Anthropic's close partner and a major investor — responded by **restricting employee access** to Claude Fable 5 while its legal teams evaluate the policy. The model was pulled from Microsoft's internal GitHub Copilot model picker. The restriction was first reported by The Verge and confirmed by Reuters on June 10.

The conflict is notable because Microsoft distributes Anthropic models through Azure and GitHub Copilot. A policy that applies to "every platform where these models are offered" means Microsoft's own customers on Azure are subject to the same retention terms — terms that may conflict with enterprise data residency requirements, regulatory obligations, and internal data handling policies.

**The Enterprise Governance Gap:**

The PYMNTS analysis frames the conflict as exposing a broader governance gap: enterprises deploying frontier AI models are discovering that the most capable models come with data handling terms that their compliance frameworks cannot accommodate. The 30-day retention requirement conflicts with GDPR data minimization principles, HIPAA privacy rules, and the data classification policies of regulated industries.

**Why It Matters:** This is the first major enterprise governance clash triggered by a frontier model's data policy, and it involves two companies that are supposed to be close partners. The outcome will set a precedent: either Anthropic will need to offer enterprise-grade data handling options for Mythos-class models (as it does for other Claude models), or enterprises will need to accept that the most capable AI models come with data retention terms that their legal and compliance teams may not approve. For security teams, the practical implication is that AI model procurement now requires the same data protection review as any other vendor engagement — and the most capable models may not pass that review.

### Oracle PeopleSoft CVE-2026-35273 (CVSS 9.8): Zero-Day Exploited by ShinyHunters in Data Theft Campaign Targeting 100+ Organizations

On June 10, **Oracle** issued an out-of-band security alert for **CVE-2026-35273**, a critical unauthenticated remote code execution vulnerability in **PeopleSoft Enterprise PeopleTools** versions 8.61 and 8.62. The flaw carries a **CVSS score of 9.8** and requires no authentication — just network access over HTTP.

**The Exploitation:**

**Mandiant** CTO Charles Carmakal confirmed the vulnerability is being exploited in the wild. The extortion group **ShinyHunters** claimed responsibility for breaching PeopleSoft instances at **more than 100 organizations**, predominantly educational institutions. The attackers used "a gadget chain of old and zero-day vulnerabilities" to compromise both on-premises and cloud-hosted PeopleSoft deployments.

The **University of Nottingham** confirmed it was among the victims, with ShinyHunters leaking tens of gigabytes of stolen data including personal information and academic records of nearly **half a million** current and former students. A threat researcher documented the attackers' tooling, including a purpose-built shell script (`uon_fanout.sh`) that spreads defacement markers across PeopleSoft infrastructure, and evidence that the attackers are deeply familiar with PeopleSoft internals — extracting credentials from `psappsrv.cfg`, mapping connected nodes, and identifying application, web, and batch tiers.

The activity was observed between **May 27 and June 9, 2026**, indicating the zero-day was exploited for approximately two weeks before Oracle's advisory.

**Why It Matters:** PeopleSoft is deeply embedded in higher education and government HR/payroll systems. A CVSS 9.8 unauthenticated RCE that was exploited as a zero-day for two weeks before a patch was available means that hundreds of organizations may have been compromised before they knew to look. The ShinyHunters campaign demonstrates that threat groups are actively stockpiling and chaining zero-day vulnerabilities against enterprise ERP systems — and that the window between exploitation and disclosure can be measured in weeks.

### Check Point VPN CVE-2026-50751 (CVSS 9.3): IKEv1 Authentication Bypass Actively Exploited by Ransomware Affiliates

**Check Point** disclosed on June 10 that a critical authentication bypass vulnerability — **CVE-2026-50751** (CVSS 9.3) — affecting Remote Access VPN and Mobile Access deployments configured with the deprecated **IKEv1** key exchange protocol has been actively exploited in the wild since **May 7, 2026** — more than a month before a patch was available.

**The Vulnerability:**

The flaw allows an unauthenticated remote attacker to establish VPN sessions without valid credentials. Check Point Research identified the vulnerability after detecting suspicious activity on June 4. The investigation revealed that a **ransomware affiliate** had been exploiting the flaw against "a few dozen targeted organizations."

**CISA** added CVE-2026-50751 to the Known Exploited Vulnerabilities (KEV) catalog on **June 8**, with a mandatory remediation deadline of **June 11** for all federal civilian executive branch agencies.

**WatchTowr's Analysis:**

Security research firm **WatchTowr** published a technical deep-dive titled "Marking Your Own Homework," analyzing the vulnerability as a client-controlled IKEv1 authentication bypass. The analysis notes that the vulnerability was exploited for approximately **five weeks** before Check Point's disclosure — a window that underscores the challenge of detecting VPN-level authentication bypasses, which leave minimal forensic artifacts compared to web application exploits.

**Why It Matters:** VPN appliances are the perimeter — compromising them gives attackers direct access to internal networks without triggering the alerts that accompany phishing-based initial access. The five-week exploitation window before disclosure means that organizations using Check Point VPN with IKEv1 (a protocol that should have been deprecated years ago) have been exposed for over a month. The CISA KEV inclusion and ransomware affiliate involvement make this an emergency patch situation for any organization still running IKEv1.

### Langflow CVE-2026-5027 (CVSS 8.8): Path Traversal Actively Exploited Against 7,000 Exposed AI Development Instances

Attackers are actively exploiting **CVE-2026-5027**, a high-severity path traversal vulnerability in **Langflow**, the open-source low-code platform for building AI applications. The flaw, discovered by **Tenable** and reported in late March, allows unauthenticated attackers to write files to arbitrary locations on the filesystem.

**The Exploitation:**

**VulnCheck** vice president Caitlin Condon confirmed that the vulnerability enables remote code execution. Because Langflow enables unauthenticated auto-login by default, no credentials are required — a single unauthenticated request obtains a valid session token, and a second request exploits the path traversal.

**Censys** data shows approximately **7,000 Langflow instances** publicly exposed on the internet, with a majority in North America. Exploitation efforts so far appear to be writing test files on victim systems, but the potential for full server compromise is significant.

**The Patch Situation:**

Tenable confirmed that the vulnerability was addressed in **Langflow version 1.9.0**, released on **April 15, 2026**. However, the patch was not widely communicated, and thousands of instances remain unpatched. This is the fifth Langflow vulnerability to be exploited this year, following CVE-2026-0770, CVE-2026-33017, CVE-2026-21445, and CVE-2025-34291 — the last of which was weaponized by Iranian state-sponsored group **MuddyWater**.

**Why It Matters:** Langflow is emblematic of a broader trend: AI development platforms are being targeted at scale because they are exposed to the internet, run with minimal authentication, and handle sensitive data (API keys, model configurations, training data). The pattern of repeated exploitation — five CVEs in one product this year — suggests that attackers have identified AI infrastructure as a high-value, low-difficulty target class. For organizations running Langflow or similar platforms, the baseline requirement is: do not expose them to the internet without a reverse proxy and authentication.

## Technical Deep Dives

### OpenClaw Under Fire: Imperva and Varonis Demonstrate Two Distinct Attack Vectors Against Self-Hosted AI Agents

Two security research teams published findings this week showing that **OpenClaw**, the popular self-hosted AI agent, can be compromised through ordinary-looking inputs — and the two attack vectors are different enough that fixing one does not fix the other.

**Imperva: Hidden Commands in Message Objects**

**Imperva** researcher Yohann Sillam discovered that OpenClaw flattens shared contacts, vCards, and location pins into the LLM prompt text without marking them as untrusted. While web-fetched content gets an untrusted-content wrapper, message objects do not.

The attack works because only certain fields reach the model. A shared contact sends just the name field, serialized as `<contact: name, number>`. The angle brackets are legal in a name, so the model cannot distinguish the real name from an injected instruction. The contact name is truncated on screen — both on WhatsApp and in the receiving app — so the victim never sees the payload.

In tests against **Gemini 3.1 Pro**, the hidden text instructed the agent to download and run a script from a researcher-controlled server. It did. A plain image with buried instructions failed (models are now trained to resist that attack), but the message-object route worked because models have seen far fewer examples of it.

Imperva disclosed the issue, and OpenClaw shipped a fix in **version 2026.4.23** that moves contact names, vCard fields, and location labels out of the prompt body and into a separate untrusted-metadata channel. Imperva found the same flattening pattern in other personal AI assistants, suggesting the problem is not OpenClaw's alone.

**Varonis: Agent Phishing — No Injection Required**

**Varonis Threat Labs** took a different approach. Led by Itay Yashar, the team built an agent called **Pinchy** on OpenClaw, wired it to a Gmail inbox with realistic business data and mock secrets, and ran four phishing simulations on **Gemini 3.1 Pro** and **OpenAI Codex GPT-5.4**.

Varonis draws a distinction between prompt injection (hiding instructions in data) and what they call **agent phishing**: a believable request that arrives through a normal channel and works because the agent acts before the human reviews it. A single plain email — no hidden payload, no encoded instructions — talked the agent into forwarding mock AWS keys and a fake customer export to an external address.

This is not a vulnerability that a patch can fix. It is a design limitation: an agent that can read email and take actions based on its contents cannot distinguish a legitimate request from a social engineering attack any more reliably than a human can — and it acts faster.

**Why It Matters:** The two research papers together define the current attack surface for personal AI agents. Imperva's work shows that the plumbing between the agent and the model is a trust boundary that must be explicitly managed — untrusted data must be marked as such. Varonis's work shows that even with perfect plumbing, the agent's ability to act on trusted-but-malicious inputs is a structural problem. For anyone running OpenClaw or similar agents, the practical takeaways are: update to 2026.4.23 (or later), and audit what actions your agent can take autonomously — because if it can forward data, it can be phished.

### CISA BOD 26-04: Federal Agencies Now Required to Patch Critical Vulnerabilities in Three Days

On June 10, **CISA** issued **Binding Operational Directive (BOD) 26-04**, titled "Prioritizing Security Updates Based on Risk," compressing the remediation timeline for the most dangerous vulnerabilities to **three calendar days**. The directive applies to all Federal Civilian Executive Branch (FCEB) agencies.

The new framework uses a **four-variable risk model** that considers exploitation status, CVSS severity, impact on critical infrastructure, and whether the vulnerability is in an internet-facing system. The most dangerous combinations — actively exploited, critical severity, internet-facing — trigger the three-day deadline, plus a forensic check for signs of intrusion. Longer windows apply for less severe combinations, and deferral is available for genuinely non-exploitable scenarios.

**Reuters** reported that the compressed timeline is driven in part by hackers' use of AI to accelerate exploitation. The directive represents an acknowledgment that the traditional 30-day patch window is no longer viable in an environment where AI-assisted vulnerability discovery and weaponization can produce working exploits in hours.

**Why It Matters:** BOD 26-04 is the first major regulatory response to AI-accelerated cyber attacks. While it only applies to federal agencies, CISA directives historically influence private-sector best practices through contractual requirements and industry standards. If three days becomes the expected patch timeline for critical vulnerabilities, organizations will need automated patch deployment pipelines — manual patch processes operating on monthly cycles will no longer be sufficient.

## Five Things to Take Into the Rest of the Day

1. **AI coding agents are now a supply chain attack vector — treat opening a repository as a trust decision.** The Miasma worm demonstrates that simply opening a compromised repository in an AI-assisted editor (VS Code, Claude Code, Cursor, Gemini) can trigger credential theft and backdoor installation. The worm spreads through compromised open-source packages and targets GitHub Actions runner memory — bypassing secret masking entirely. For organizations using AI coding tools, the practical response is: audit which repositories your agents can access, restrict AI coding tool permissions, and treat any repository opened in an AI editor as a potential infection vector.

2. **The three-day patch window is coming — whether you are a federal agency or not.** CISA's BOD 26-04 compresses the remediation timeline for critical vulnerabilities to three calendar days, driven by AI-accelerated exploitation. While the directive only applies to federal agencies, CISA directives historically become de facto standards through procurement requirements and industry best practices. If your organization's average patch cycle for critical vulnerabilities exceeds three days, start building the automation pipeline now — because the window is not getting longer.

3. **Frontier model procurement now requires a data protection review — and the most capable models may not pass.** Anthropic's mandatory 30-day data retention policy for Claude Fable 5 has already caused Microsoft to block employee access. The policy conflicts with GDPR, HIPAA, and enterprise data classification requirements. For any organization evaluating frontier models, the procurement checklist must include: What data is retained? For how long? Can ZDR be configured? What happens to flagged content? If the vendor cannot answer these questions to your legal team's satisfaction, the model may not be deployable in your environment — regardless of its capabilities.

4. **AI development platforms are a high-value, low-difficulty target class — and attackers know it.** The Langflow exploitation (fifth CVE this year, 7,000 exposed instances) and the Oracle PeopleSoft zero-day (exploited for two weeks before disclosure) both target platforms that are exposed to the internet with minimal authentication. The pattern is consistent: attackers are scanning for AI infrastructure, finding it exposed, and compromising it at scale. If you are running Langflow, PeopleSoft, or similar platforms, the baseline requirement is: do not expose them to the internet without a reverse proxy, authentication, and a vulnerability management process that checks for CVEs weekly, not monthly.

5. **Your AI agent can be phished — and no patch will fix it.** Varonis's OpenClaw research demonstrates that a plain email — no hidden payload, no encoded instructions — can trick an AI agent into forwarding credentials and sensitive data. This is not a vulnerability that can be patched; it is a structural limitation of agents that can read and act on email. The only defense is to limit what agents can do autonomously: if an agent can forward data, it can be phished. Review your agent's permission model and ensure that sensitive actions require human approval.
