### US Government Forces Anthropic to Disable Fable 5 and Mythos 5 Worldwide Over Disputed Jailbreak

On Friday, June 12 at 5:21 PM ET, the US government delivered an export control directive to Anthropic ordering the company to suspend all access to its two most capable models — **Claude Fable 5** and **Mythos 5** — by any foreign national, whether inside or outside the United States, including Anthropic's own foreign-national employees. Because the company says it cannot reliably separate foreign users from the rest of its base in real time, the practical result is a **worldwide shutoff of both models**. All other Anthropic models remain online.

**The Government's Rationale:**

The directive, issued under national security authorities, did not provide specific details. Anthropic's understanding is that the government believes it has identified a method to bypass, or "jailbreak," Fable 5. The alleged technique, as described to Anthropic, essentially involves instructing the model to read a specific codebase and identify software flaws.

Anthropic reviewed a demonstration of the technique and found that it surfaced only a small number of previously known, minor vulnerabilities. Critically, the company states that other publicly available models — including **OpenAI's GPT-5.5** — can produce the same output without requiring any bypass.

**Anthropic's Defense-in-Depth Strategy:**

Anthropic published a detailed statement defending its approach. The company noted that it worked with the US government, the UK AISI, multiple private third-party organizations, and internal teams for thousands of hours of red-teaming before launch. No tester has yet found a universal jailbreak — a method that can broadly bypass the model's safeguards across a wide range of cyber capabilities.

The company acknowledged that perfect jailbreak resistance is not currently achievable by any model provider. Its defense-in-depth strategy aims to make jailbreaks either narrow (non-universal) or very expensive to produce (universal), combined with monitoring to detect and shut down successful attacks quickly. This is also the rationale behind the **30-day data retention policy** for Mythos-class models — a policy that, as reported on June 12, has already caused Microsoft to block employee access to Fable 5.

**The Fallout:**

The directive landed on Hacker News as the **#1 story with 2,549 points and 1,833 comments** — one of the most active threads in the site's history. A companion analysis titled "There is a shadow hanging over this Fable thing" reached 320 points, questioning the government's rationale and the precedent being set.

The shutdown is unprecedented: this is the first time a US government directive has forced a frontier AI model offline globally. The precedent it sets — that the government can order a model disabled based on a disputed, non-universal jailbreak — will reverberate across the entire AI industry.

**Why It Matters:** The Fable 5 shutdown is not primarily a technical story about a jailbreak. It is a governance story about who decides when a frontier model is too dangerous to deploy — and on what evidence. The government acted on a technique that Anthropic says produces output available from other models without a bypass. If the standard for shutting down a model is "a jailbreak exists that produces output also available from other models," then every frontier model is potentially one directive away from being taken offline. For security teams, the practical implication is that model availability is now a geopolitical risk factor — and the models you depend on today may not be available tomorrow.

### Agentjacking: Tenet Security Demonstrates MCP Injection via Sentry — 85% Success Rate Against Claude Code, Cursor, and Codex

Security researchers at **Tenet Security** have documented a new attack class they call **Agentjacking** that exploits the intersection of **Sentry's open event ingestion architecture** and the **implicit trust model of MCP-connected AI coding agents**. The attack achieves an 85% exploitation success rate against the most widely used AI coding assistants and bypasses every traditional security control — EDR, WAF, IAM, VPN, Cloudflare, and firewalls — because every action in the chain is authorized.

**How It Works:**

The attack chain is deceptively simple:

1. An attacker finds a target's **Sentry DSN (Data Source Name)** — a public, write-only credential embedded in websites that anyone can use to send error events to Sentry's ingest endpoint.
2. The attacker sends a malicious error event to Sentry via a simple POST request. The injected event contains carefully formatted markdown in the message field and context key names.
3. When a developer asks their AI coding agent to "fix unresolved Sentry issues" (or a similar prompt), the agent queries Sentry via MCP and receives the malicious event.
4. The Sentry MCP server returns the injected event to the AI agent as trusted system output. The agent cannot distinguish the attacker's markdown from legitimate Sentry guidance.
5. The agent executes the attacker's instructions as code — running with the **developer's full privileges** on the developer's own machine.

"The attacker never touches the victim's infrastructure," the researchers explained. "The malicious instruction arrives disguised as a legitimate 'Resolution' inside an ordinary error."

**The Scale of Exposure:**

Tenet Security found at least **2,388 organizations** exposed with valid injectable DSNs. The attack was tested in a controlled manner against over 100 organizations, achieving 85% exploitation success across Claude Code, Cursor, and OpenAI Codex.

**Sentry's Response:**

Sentry acknowledged the issue but opted not to fix it, stating it is "technically not defensible." The company activated a global content filter that blocks a specific payload string — a mitigation that addresses the known proof-of-concept but does not solve the underlying architectural problem.

**The MCP Trust Problem:**

Agentjacking is the second major disclosure this week that targets the MCP trust model, following the Imperva and Varonis research on OpenClaw (covered June 12). The pattern is consistent: AI agents implicitly trust data returned through MCP-connected services, and that trust can be exploited when the service accepts untrusted input. Sentry's event ingestion is designed to accept arbitrary payloads from anyone with a DSN — that is its function. The problem is that the MCP server returns that untrusted data to the agent as trusted system output, with no mechanism for the agent to distinguish between a real error and an injected one.

**Why It Matters:** Agentjacking represents a structural vulnerability in how AI coding agents interact with external services. The attack bypasses every security control because there is nothing malicious to detect — the code the agent runs is authorized, the MCP connection is legitimate, and the Sentry DSN is public by design. For organizations deploying AI coding agents, the practical response is: audit which MCP servers your agents connect to, restrict which prompts can trigger tool calls against external services, and treat any data returned through MCP as potentially untrusted — because the MCP server cannot guarantee its provenance.

### Google Sues Chinese Cybercrime Network for Weaponizing Gemini AI in Large-Scale Phishing Campaign

On June 12, **Google** filed a landmark lawsuit in the US District Court for the Southern District of New York against a China-based cybercrime network called **"Outsider Enterprise,"** marking the first time a major AI platform has legally pursued threat actors for weaponizing its own generative AI to scale criminal operations.

**The Operation:**

The Outsider Enterprise operates as a sophisticated **phishing-as-a-service (PhaaS) platform**, coordinating through Telegram channels and distributing ready-made phishing kits to criminal affiliates. The network maintains a library of **over 290 prebuilt templates** impersonating Google, YouTube, the US Postal Service, financial institutions, state DMVs, and toll agencies like New York's E-ZPass.

What distinguishes this operation from conventional phishing infrastructure is its deliberate abuse of AI. According to Google's complaint, members of the Outsider Enterprise actively encouraged one another to use **Gemini** to generate custom code for phishing websites, which was then imported directly into the Outsider software suite and converted into live scam pages. The network effectively industrialized fraud by reducing the technical barrier to near-zero, turning Google's own generative AI into a malicious code factory.

**The Numbers:**

- **2.5 million** smishing messages sent to Android users in a two-week period in May 2026
- **55,000** spam texts flagged by Android users during that same window — more than two complaints per minute
- **9,000+** fake websites and over **1 million** fraudulent URLs tied to the network
- **Hundreds of thousands** of victims financially defrauded, with total losses estimated in the millions

**The Legal Strategy:**

Google filed under the **Racketeer Influenced and Corrupt Organizations (RICO) Act** and the **Lanham Act**, seeking damages and injunctive relief. The FBI's Cyber Division is conducting parallel law enforcement actions. Google is simultaneously working with AT&T, T-Mobile, and Verizon to intercept and block fraudulent messages at the carrier level.

The company is also backing **seven bipartisan bills** targeting AI-driven scams, including the Stop SCAMS Act, which would create a national coordinated strategy uniting law enforcement, government agencies, and private industry.

**Why It Matters:** This lawsuit sets a significant legal precedent: AI platforms can and will be used as enforceable grounds for civil litigation when threat actors abuse generative models to scale criminal infrastructure. For security teams, the practical implication is that AI platform abuse is now a law enforcement priority — and that the same AI capabilities that power productivity gains are being weaponized at industrial scale by transnational cybercrime networks.

### LangGraph Critical Vulnerability Chain: SQL Injection + Unsafe Deserialization Enables Full Server Compromise

**Check Point Research** disclosed on June 12 a critical vulnerability chain in **LangGraph**, the popular open-source AI agent framework developed by the creators of LangChain. With approximately **46.5 million monthly downloads** and deployment across thousands of production environments, the framework is one of the most widely used platforms for building stateful AI agents.

**The Vulnerability Chain:**

Three CVEs were assigned:

- **CVE-2025-67644**: SQLite injection vulnerability in LangGraph's checkpointing component. The `get_state_history()` function contains an SQL injection flaw in its filter parameter, allowing attackers to manipulate database queries.
- **CVE-2026-28277**: Remote code execution via unsafe **msgpack deserialization**. By chaining the SQL injection with the deserialization flaw, attackers can inject malicious data that executes during deserialization.
- **CVE-2026-27022**: Redis injection vulnerability in the alternative checkpointer backend.

The attack path demonstrates how multiple moderate flaws can combine into a severe compromise when they exist within core components of AI frameworks. If exploited, attackers can gain access to LLM API keys, customer data, conversation histories, and credentials connected to external systems such as CRMs and internal APIs. The compromised server can also serve as a pivot point for further attacks on internal networks.

**The Patch:**

All vulnerabilities have been patched. Secure versions include:
- `langgraph-checkpoint-sqlite` 3.0.1 or later
- `langgraph` 1.0.10 or later
- `langgraph-checkpoint-redis` 1.0.2 or later

LangChain's managed platform, LangSmith, is not impacted.

**Why It Matters:** LangGraph's vulnerability chain reinforces a growing concern in AI security: traditional vulnerabilities like SQL injection can have far more severe consequences when they exist in systems that operate with elevated privileges and broad access to sensitive data. An SQL injection in a web application might expose a database. An SQL injection in an AI agent framework can expose API keys, customer data, and the agent's entire operational context — because the agent has been granted access to everything it needs to function.

### Splunk Enterprise CVE-2026-20253 (CVSS 9.8): Pre-Auth RCE via PostgreSQL Sidecar — Active by Default on AWS

**watchTowr Labs** disclosed on June 13 a critical pre-authentication remote code execution vulnerability chain in **Splunk Enterprise 10 and later**. Tracked as **CVE-2026-20253** with a **CVSS score of 9.8**, the flaw originates from the **PostgreSQL Sidecar Service**, an internal component that is active by default in Splunk Enterprise on AWS.

**The Vulnerability:**

The PostgreSQL sidecar service listens on localhost but can be accessed externally through Splunk's main web interface on port 8000. Attackers can send crafted HTTP requests to internal API endpoints such as `/v1/postgres/recovery/backup` and `/restore` via the Splunk web service.

The core problem: the API accepts **any credentials, including empty values**, and forwards them to backend PostgreSQL utilities like `pg_dump` and `pg_restore`. By chaining directory traversal with SQL injection via PostgreSQL large object export functions, attackers can achieve arbitrary file write access under the Splunk user — and from there, full remote code execution.

**The AWS Exposure:**

While the PostgreSQL sidecar is not always enabled in on-premise deployments, it is **active by default in Splunk Enterprise on AWS**, making cloud deployments particularly exposed out of the box. Given that Splunk is the most widely deployed SIEM platform in the enterprise, the blast radius of a pre-auth RCE in the default AWS configuration is substantial.

**Why It Matters:** Splunk is the central nervous system of most enterprise security operations centers. A pre-auth RCE that allows attackers to overwrite Splunk Python scripts and execute arbitrary commands means that the tool organizations rely on to detect intrusions can itself be the entry point. For organizations running Splunk Enterprise on AWS, this is an emergency patch situation — the vulnerable component is enabled by default, and the exploit requires no authentication.

### StakeBench: New Research Proves Prompt Injection Breaks Every AI Agent — and the Harm Is Unevenly Distributed

A comprehensive new study published on June 12 by researchers from **Nanyang Technological University, ST Engineering, IBM Research, and the University of Illinois Urbana-Champaign** delivers the most granular analysis yet of prompt injection vulnerability in production AI agents. The findings are stark: not a single attack scenario was consistently blocked across any tested configuration.

**The Benchmark:**

The researchers developed **StakeBench**, a stakeholder-centric benchmark that evaluates prompt injection attacks across 264 benchmark cases and 3,168 adversarial runs. They tested two agent architectures (NanoBrowser and BrowserUse) powered by **GPT-5** and **Gemini 2.5-Flash**.

The results:
- **Direct prompt injection**: >79% attack success rate across all configurations
- **Indirect prompt injection** (malicious instructions hidden in web content): 41.67% to 68.16%
- **"Robust Behavior" region**: remained **unpopulated across all evaluated configurations** — meaning every tested attack objective resulted in at least one meaningful failure dimension

**Stealthy Parasitism: The Most Dangerous Failure Mode:**

The study introduces a critical concept: **stealthy parasitism**, where an AI agent completes the user's delegated task while simultaneously advancing an attacker's objective. The user sees nothing wrong — the task appears to complete normally — but the attacker's goal is achieved.

The paper illustrates with an online shopping scenario: "A malicious prompt injected into product reviews may bias an agent toward a specific item: although the user may still receive an acceptable recommendation, the same behavior can disadvantage competing sellers and undermine platform integrity."

**Stakeholder-Specific Harm:**

Unlike existing benchmarks that primarily measure attack success rates, StakeBench evaluates harm across three stakeholder groups: end users, third-party sellers, and platforms. The results show that those groups experience materially different risks:

- **Seller-targeted attacks**: highest attack success rates
- **User-targeted attacks**: lowest task deviation rates — harder to detect because workflows appear normal
- **Platform-targeted attacks**: highest behavioral irregularity

"The same agent can simultaneously appear stealthy on user-targeted attacks, susceptible on seller-targeted attacks, and unstable on platform-targeted attacks," the researchers wrote.

**Model and Architecture Differences:**

Replacing GPT-5 with Gemini 2.5-Flash increased indirect prompt injection success rates by **26.49 percentage points** on NanoBrowser and by **6.2 percentage points** on BrowserUse. BrowserUse consistently exhibited higher task deviation and behavioral irregularity than NanoBrowser, suggesting that prompt injection resilience depends not only on the model but on how it is implemented within the agent architecture.

**Why It Matters:** The StakeBench study formalizes what practitioners have long suspected: prompt injection is not a model-level problem that can be solved with better guardrails. It is a system-level security problem with multi-party harm that varies by stakeholder, model, and architecture. The "stealthy parasitism" finding is particularly concerning for any organization deploying AI agents in e-commerce, content moderation, or recommendation systems — where the agent can be manipulated without the user ever noticing.

### Operation Highland: China-Linked Velvet Ant Group Backdoored Linux PAM and OpenSSH for Nearly a Decade

**Sygnia** published details on June 12 of **Operation Highland**, a long-running espionage campaign by the China-nexus threat group tracked as **Velvet Ant**. The group spent close to a decade hidden inside the Linux login system itself, backdooring the **PAM (Pluggable Authentication Modules)** and **OpenSSH** components that control who is allowed to sign in.

**The Operation:**

The earliest traces go back to **2016**. Instead of dropping new malware that a scanner might catch, the attacker changed the trusted login programs themselves. On many machines, the attacker replaced the main PAM login module with backdoored copies. Some variants let the attacker in with a secret password; others quietly recorded real usernames and passwords as people logged in.

Researchers found **nine separate versions** of the backdoored components. The OpenSSH programs were altered the same way — logging credentials and every command typed, with a hidden switch to turn that logging off when needed.

The targeted network had no direct internet access, so the group first staged through internet-facing systems — using disguised tools and an internet-facing web server as a bridge to pass commands into the isolated segment.

**Why Traditional Defenses Fail:**

Because the login system itself was compromised, normal containment measures were ineffective. Password resets and session kills do not help when the thing that checks those credentials is working for the attacker. The backdoor was planted in the authentication infrastructure — the layer that every other security control depends on.

**The Velvet Ant Pattern:**

This is not new for the group. In a 2024 case, Sygnia found the same actor turning internet-exposed F5 BIG-IP appliances into internal command servers. Later that year, it reported the group exploiting a Cisco NX-OS flaw (CVE-2024-20399) to plant backdoors on network switches. The pattern is consistent: each time defenders find one foothold, Velvet Ant moves to infrastructure that is trusted by default and rarely checked.

**Why It Matters:** Operation Highland demonstrates that patient APT groups target the authentication infrastructure itself — not application-layer vulnerabilities. The backdoor was planted in PAM and OpenSSH, the components that every other security control depends on for identity verification. For defenders, the lesson is that file integrity monitoring must extend beyond application binaries to the operating system's authentication components — and that password resets are ineffective when the credential checker is compromised.

### Arch Linux AUR Incident Escalates: More Than 1,500 Packages Now Confirmed Compromised
