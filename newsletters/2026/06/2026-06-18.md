## Headliners

### AgentJacking: One Fake Bug Report Hijacked a $250 Billion Company's AI Agent — Then 100+ More

**Tenet Security Threat Labs** has demonstrated a new attack class — **AgentJacking** — that hijacks AI coding agents into executing attacker-controlled code on a developer's machine, triggered by a single fake error report and invisible to every security control in place. Using only public Sentry APIs, breaching nothing, the researchers found **2,388 organizations exposed**, saw **100+ agents act on injected errors** in controlled testing, and confirmed agent execution at organizations spanning from Fortune 500 enterprises down to independent developers. ([Tenet Security](https://tenetsecurity.ai/blog/agentjacking-coding-agents-with-fake-sentry-errors/))

**The attack chain:**

1. **Find the target's Sentry DSN** — a public, write-only credential that Sentry intentionally documents as safe to embed in frontend JavaScript. Discovery methods include inspecting any website's JavaScript source, Censys searches, or GitHub code search.

2. **POST a crafted error event** to Sentry's ingest endpoint. No authentication beyond the DSN is required. The attacker controls the entire event payload: error message, tags, context keys, and stack traces. Sentry accepts it and processes it identically to a legitimate application error.

3. **Markdown injection** — the injected event contains carefully formatted markdown in the message field and context key names. When the Sentry MCP server returns this event to an AI agent, the markdown renders as structured content — headings, code blocks, and tables that are visually identical to Sentry's own system template. The injected content includes a fake `## Resolution` section with an `npx` command.

4. **Agent execution** — when a developer asks their AI agent to "fix unresolved Sentry issues," the agent queries Sentry via MCP and receives the injected event. The agent is carefully steered away from investigating source code and toward executing the suggested diagnostic tool. The agent cannot distinguish this from legitimate guidance.

**The result:** A single injected error puts environment variables (AWS keys, GitHub tokens, Sentry auth tokens), git credentials, private repository URLs, and developer identity within an attacker's reach — silently exfiltrated to their server, with no credential phishing, no prior server compromise, and no user interaction beyond the developer's normal workflow of asking their AI agent to investigate Sentry errors.

**The open-source response:** Tenet has released **[agent-jackstop](https://github.com/tenet-security/agent-jackstop)** — drop-in configs that harden Cursor and Claude Code against this attack class by cutting the risk from untrusted telemetry and log ingestion.

**Why this is a Headliner:** AgentJacking is a category-defining attack that exploits the architectural trust gap between telemetry data and AI agent execution. It is not a vulnerability in Sentry, Cursor, or Claude Code — it is a structural limitation of how AI agents process data from MCP-connected tools. The same pattern will replicate across every telemetry, monitoring, and log-ingestion service that exposes a write API and connects to an AI agent. Every organization running AI coding agents needs to audit their MCP tool connections and treat telemetry data as an untrusted input surface.

## Breaking News

### 144 Mastra npm Packages Compromised via Hijacked Contributor Account in 88-Minute Supply Chain Attack

As many as **144 npm packages** associated with the **@mastra/\*** namespace — a popular open-source JavaScript/TypeScript framework for building AI applications — were compromised in an automated supply chain attack codenamed **easy-day-js**. The campaign was independently detected by **Endor Labs, JFrog, SafeDep, Socket, and StepSecurity**. ([The Hacker News](https://thehackernews.com/2026/06/144-mastra-npm-packages-compromised-via.html))

**The mechanics:** A single npm account (`ehindero`), a legitimate former Mastra contributor whose scope access was never revoked, was hijacked. The attacker mass-published 140+ malicious packages across the Mastra scope within an 88-minute window on June 17, 2026. The infected packages themselves do not include malicious code — instead, the payload is introduced through a third-party library named **easy-day-js**, a clone of the `dayjs` date library, added to each package's dependency list.

**The payload:** The `easy-day-js` package (published by npm user `sergey2016`) launches an obfuscated payload during a `postinstall` hook. The payload acts as a dropper for a second-stage cross-platform information stealer that:
- Harvests browser history and stored data from **160+ cryptocurrency wallet browser extensions**
- Installs persistence across **Windows, macOS, and Linux**
- Exfiltrates captured data to a C2 server (`23.254.164[.]123`)
- Polls the C2 server for commands, including downloading and executing arbitrary modules

**The detection gap:** Mastra ships its real releases from CI through npm's trusted publisher flow with SLSA provenance attestations. The attacker pushed malicious versions from a personal token and dropped the provenance. A signature-verifying install (`npm audit signatures` or a policy requiring attestations) would have rejected every package in this wave.

**The response:** npm has pulled the malicious versions from the highest-profile packages and reverted their latest tag. Any workstation, CI runner, or build environment that installed the affected versions should be treated as potentially compromised — credentials should be rotated and hosts audited for artifacts linked to the campaign.

**Why it matters:** Because Mastra sits at the intersection of AI development and cloud infrastructure, its packages are routinely installed in environments that hold some of the most sensitive credentials in modern software development. This is the first large-scale supply chain attack specifically targeting an AI application framework, and it demonstrates that the AI tooling ecosystem has inherited all the supply chain vulnerabilities of the npm ecosystem — with higher-value targets.

### Microsoft Defender "RoguePlanet" Zero-Day (CVE-2026-50656): SYSTEM-Level Privilege Escalation, No Patch Available

Microsoft has acknowledged a local elevation of privilege vulnerability in **Microsoft Defender** tracked as **CVE-2026-50656 (CVSS 7.8)** , publicly dubbed **"RoguePlanet."** The flaw stems from improper link resolution before file access and can be exploited in low-complexity attacks by authenticated attackers with no user interaction required. ([Help Net Security](https://www.helpnetsecurity.com/2026/06/17/rogueplanet-zero-day-cve-2026-50656/) | [BleepingComputer](https://www.bleepingcomputer.com/news/microsoft/microsoft-defender-rogueplanet-zero-day-grants-system-privileges/))

**The exploit:** RoguePlanet abuses a race condition in Windows Defender to spawn a command shell running with **SYSTEM-level privileges**. It affects fully patched Windows 10 and Windows 11 devices. The PoC works regardless of whether Real-Time Protection is enabled on Microsoft Defender. The researcher who published it — **Nightmare Eclipse** (also known as Chaotic Eclipse) — noted that signature-based detection is ineffective because "small changes in the PoC can completely bypass your mitigations."

**The disclosure context:** RoguePlanet is the **sixth zero-day exploit** released by Nightmare Eclipse since March 2026, in an ongoing disclosure campaign apparently motivated by a dispute with Microsoft. Previous releases include BlueHammer, RedSun, UnDefend, YellowKey, and GreenPlasma. Microsoft shipped patches for YellowKey and GreenPlasma in the June 2026 Patch Tuesday — the same day RoguePlanet was released.

**The response:** Microsoft has acknowledged the vulnerability and is "working to provide a high quality security update." The company has not detected exploitation in the wild but rates the vulnerability "Exploitation More Likely" under its Exploitability Index. No patch timeline has been provided.

**Why it matters:** The RoguePlanet disclosure is the latest in an accelerating cadence of zero-day releases targeting Microsoft's security stack. The researcher's claim that signature-based detection is ineffective against the PoC means organizations cannot rely on Defender's own detection capabilities to protect against this vulnerability. The only viable mitigation is waiting for a Microsoft patch — a position that leaves every Windows endpoint running Defender exposed to local privilege escalation.

### Bipartisan "Great American AI Act" Draft Proposes Federal AI Governance Office, 3-Year Preemption of State Laws

A long-awaited federal answer to the chaotic spread of state-level AI rules arrived on **June 4, 2026**, when Representatives **Jay Obernolte (R-CA)** and **Lori Trahan (D-MA)** released the discussion draft of the **Great American Artificial Intelligence Act**. The 112-page proposal establishes a national AI governance framework, mandates new transparency and testing obligations for high-risk systems, and — most controversially — preempts state AI laws for three years while the federal regime takes hold. ([Windows News](https://windowsnews.ai/article/bipartisan-great-american-ai-act-draft-aims-to-replace-patchwork-state-ai-laws-with-3-year-federal-p.427478))

**What's inside:**
- Creates a new independent agency — the **Federal Artificial Intelligence Governance Office (FAIGO)** — within the Department of Commerce
- Mandates **pre-deployment safety assessments** for high-risk AI systems (critical infrastructure, employment, healthcare, law enforcement, financial services)
- Requires **transparency disclosures** — consumers must be informed when interacting with AI, and generative AI outputs must carry invisible, tamper-resistant watermarking
- Establishes a **$3 billion retraining fund** financed by fees on large AI model training runs

**The preemption debate:** Section 501 preempts any state law "regulating the development, deployment, or use of artificial intelligence" for 36 months from enactment. Proponents argue this prevents a balkanized market where startups cannot scale. Critics — particularly from California and Colorado — see it as gutting stronger state protections like California's SB 1047, which requires safety testing that the federal draft merely encourages.

**Why it matters:** This is the first bipartisan, bicameral effort at federal AI legislation. For security teams, the practical implication is that AI governance is moving from voluntary frameworks to statutory requirements. The pre-deployment safety assessment mandate, if enacted, would create a formal regulatory gate for AI system deployment — with compliance obligations that security teams will need to operationalize.

## Technical Deep Dives

### 973 MCP Packages, 71% Single-Maintainer: GitGuardian Maps the MCP Supply Chain Risk

**GitGuardian's 2026 State of Secrets Sprawl** report has published the most comprehensive quantitative analysis yet of the **Model Context Protocol (MCP)** ecosystem's security posture. The findings paint a picture of a rapidly growing package ecosystem with structural vulnerabilities that the Mastra compromise (above) has now demonstrated in practice. ([Security Boulevard](https://securityboulevard.com/2026/06/973-mcp-packages-71-single-maintainer-a-practitioners-guide-to-ai-developer-security/))

**The numbers:**
- **973 MCP packages** cataloged across public registries
- **71% are single-maintainer** — a single point of failure for package maintenance and security response
- **24,008 unique secrets** found in MCP config files on public GitHub
- **2,117 secrets confirmed live** at the time of scanning
- Commits co-authored by AI coding tools leaked secrets at **2x the baseline rate**

**The MCP-specific risk:** MCP servers operate at a privileged layer — they have access to the tools, data, and systems that AI agents use to execute tasks. A compromised MCP package doesn't just inject code into a build pipeline; it injects instructions into the agent's runtime environment. The AgentJacking attack (Headliner above) is the proof of concept: the Sentry MCP server returned attacker-controlled data that the agent treated as trusted system output.

**The secrets problem:** The 24,008 secrets in MCP config files include API keys, database credentials, and cloud provider tokens — exactly the kind of credentials that the Mastra campaign was designed to steal. The 2x leak rate from AI-assisted commits suggests that AI coding tools are accelerating the secrets sprawl problem even as they create new attack surfaces.

**The practitioner's checklist:**
- Inventory every MCP server connected to your AI agents
- Verify the maintainer profile and maintenance history of each MCP package
- Scan MCP config files for embedded secrets before committing
- Treat MCP server output as untrusted input — apply the same validation you would to user-supplied data
- Require provenance attestations for MCP package installations (the same control that would have blocked the Mastra attack)

**Why it matters:** The MCP ecosystem is growing faster than its security practices. The combination of single-maintainer packages, widespread secrets exposure, and the privileged execution context of MCP servers creates a supply chain risk profile that is structurally worse than the npm ecosystem at its worst. Every organization deploying MCP-connected AI agents needs to treat MCP package management as a security-critical function — not a developer convenience.

## Five Things to Take Into the Rest of the Day

**1. Your telemetry is now an RCE vector.** AgentJacking proves that any MCP-connected telemetry service with a write API is a potential code execution path. Audit your MCP tool connections and treat telemetry data as untrusted input.

**2. The AI tooling supply chain is the npm supply chain — with higher-value targets.** The Mastra compromise demonstrates that AI application frameworks inherit all the supply chain vulnerabilities of their package ecosystems, with the added risk that compromised packages run in credential-rich environments.

**3. MCP package management is a security function, not a developer convenience.** With 71% of MCP packages single-maintainer and 24,000+ secrets exposed in config files, every MCP connection should be treated as a security boundary.

**4. Federal AI regulation is coming — and it will have teeth.** The Great American AI Act's pre-deployment safety assessment mandate would create a formal regulatory gate for AI system deployment. Start building the compliance infrastructure now.

**5. The OAuth-abuse playbook is repeatable and widely adopted.** The Klue/Salesforce compromise is the third major OAuth-abuse campaign against the Salesforce ecosystem. Third-party SaaS integrations remain a high-value, little-monitored attack surface that deserves the same scrutiny as direct infrastructure access.
