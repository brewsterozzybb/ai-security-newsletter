# AI Security Newsletter
## Saturday, June 20, 2026

> **Today's theme:** The AI agent framework supply chain is under active, in-the-wild attack — Langflow, LangGraph, and LangChain all share the same bug class and 7,000+ servers are exposed, while AutoJack and SearchLeak prove that parameter-to-prompt injection and WebSocket origin bypasses are the new RCE vectors that every AI deployment needs to patch today.

## Headliners

### 7,000+ Langflow Servers Under Active Attack — LangGraph and LangChain Share the Same Holes

**Three of the most widely deployed AI agent frameworks — Langflow, LangGraph, and LangChain — each turned a known, ordinary bug class into a remote code execution path,** and attackers are already exploiting one of them in the wild. Check Point Research, Tenable, VulnCheck, and Cyera independently disclosed vulnerabilities across the LangChain ecosystem this week, and the pattern is the same in every case: the framework accepted untrusted input where it should not have, and the result is a shell on the box holding your OpenAI key, database credentials, and CRM tokens. ([VentureBeat](https://venturebeat.com/security/7000-langflow-servers-under-attack-langgraph-langchain-same-holes) | [Check Point Research](https://research.checkpoint.com/2026/from-sqli-to-rce-exploiting-langgraphs-checkpointer/) | [Cyera](https://www.cyera.com/research/langdrained-3-paths-to-your-data-through-the-worlds-most-popular-ai-framework))

**The Langflow chain — actively exploited.** CVE-2026-5027 (CVSS 8.8) is a path traversal in Langflow's `POST /api/v2/files` endpoint. The filename is taken straight from form data and written to disk unsanitized. An attacker packs traversal sequences and drops a file anywhere — a cron job in `/etc/cron.d/`, for example. Because Langflow ships with auto-login enabled by default, an exposed instance needs no credentials at all. A single unauthenticated request reaches the endpoint, and the next cron run hands over a shell. VulnCheck's Caitlin Condon confirmed exploitation on June 9: "Our Canaries observe active exploitation of CVE-2026-5027." Approximately 7,000 Langflow servers are internet-facing and reachable.

**The LangGraph chain — SQL injection to Python shell.** CVE-2025-67644 (CVSS 7.3) is a SQL injection in LangGraph's SQLite checkpointer. The function that builds the WHERE clause for checkpoint lookups drops user-controlled filter keys straight into the query with no parameterization. A deployment is exposed when it self-hosts LangGraph on the SQLite or Redis checkpointer and lets untrusted input reach `get_state_history()`. CVE-2026-28277 (CVSS 6.8) finishes the job: LangGraph's msgpack checkpoint decoder rebuilds Python objects from stored data, which lets it import a module and call a named function with attacker-supplied arguments — including `os.system`. A third issue, CVE-2026-27022 (CVSS 6.5), reaches the same place through the Redis checkpointer. No confirmed in-the-wild exploitation yet, but a working PoC is public.

**The LangChain-core chain — path traversal reads secrets off disk.** Cyera documented a path traversal in LangChain-core's prompt loader that reads secrets off disk. The same architectural pattern — untrusted input reaching a file-loading function — that makes all three frameworks vulnerable.

**The fixes.** LangGraph: `langgraph-checkpoint-sqlite` to 3.0.1, `langgraph` to 1.0.10, `langgraph-checkpoint-redis` to 1.0.2. Langflow: patch available in the latest release. LangChain-core: update to the latest version.

**Why this is a Headliner:** These frameworks became production infrastructure faster than anyone secured them. They store agent state, take file uploads, load prompt configs, and hold the credentials to databases, CRMs, and internal APIs. The edge tools watch traffic. The endpoint tools watch processes. Neither was built to treat an imported framework as a boundary worth guarding, and that blind spot is exactly where all three chains live. Every organization running LangChain-family frameworks needs to inventory their deployments, confirm patch levels, and treat internet-facing Langflow instances as an emergency.

## Breaking News

### AutoJack: A Single Web Page Hijacks Microsoft AutoGen Studio's AI Agent to Execute Arbitrary Code

**Researchers have demonstrated AutoJack, a three-vulnerability exploit chain targeting Microsoft's AutoGen Studio** that allows a single malicious web page to hijack the browsing agent and execute arbitrary code on the host machine — with no user interaction beyond submitting a URL. Microsoft's maintainers have hardened the main branch in commit b047730; the published PyPI package was confirmed not affected. ([Cybersecurity News](https://cybersecuritynews.com/autojack/) | [Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/06/18/autojack-single-page-rce-host-running-ai-agent/))

**The chain.** AutoJack chains three independent weaknesses in AutoGen Studio's MCP WebSocket surface:
- **CWE-1385 — Missing Origin Validation in WebSockets:** The MCP WebSocket only accepts connections from `http://127.0.0.1` or `http://localhost`. While this blocks a human browser tab on `evil.com`, it does not block JavaScript rendered by a headless browser owned by an AutoGen browsing agent — which inherits localhost identity, bypassing the check entirely.
- **CWE-306 — Missing Authentication for Critical Function:** AutoGen Studio's authentication middleware explicitly skipped `/api/mcp/*` paths, assuming the WebSocket handler would enforce its own checks. It never did.
- **CWE-78 — OS Command Injection via `server_params`:** The WebSocket endpoint accepted a `server_params` query parameter, base64-decoded it, parsed it into `StdioServerParams`, and passed `command + args` directly to `stdio_client()` with no executable allowlist.

**The end-to-end flow.** A developer runs AutoGen Studio on localhost:8081 alongside a browsing agent. An attacker plants a malicious page. The headless browser navigates to it; its JavaScript opens a WebSocket to `ws://localhost:8081/api/mcp/ws/<id>?server_params=<base64_payload>`. Because the browsing agent runs locally, the origin check passes; because auth middleware skips `/api/mcp/*`, no token is required. AutoGen Studio decodes the payload and spawns the attacker-specified command under the developer's account. In PoC testing, `calc.exe` launched within seconds.

**Why it matters:** AutoJack is the third major "agent hijacking" attack class disclosed this week, after AgentJacking (Tenet Security, June 18) and the Claude.ai shared-chat ClickFix campaign (June 19). The common thread: AI agents trust localhost, and localhost is not a security boundary. Every organization running AI agents with web-browsing capabilities needs to treat the loopback interface as an attack surface and apply authentication to every MCP endpoint.

### SearchLeak (CVE-2026-42824): M365 Copilot Parameter-to-Prompt Injection Leaks Corporate Data via a Single Click

**Varonis Threat Labs has disclosed SearchLeak, a critical information disclosure vulnerability in Microsoft 365 Copilot Enterprise Search** that allows attackers to exfiltrate sensitive corporate data — including two-factor codes, emails, meeting invites, SharePoint documents, and OneDrive files — by tricking a user into clicking a specially crafted link. Microsoft patched the vulnerability server-side and rated it Critical. ([CSO Online](https://www.csoonline.com/article/4186970/m365-copilot-searchleak-your-prompt-injection-attack-surface-just-got-bigger.html) | [Varonis](https://www.varonis.com/blog/searchleak) | [MSRC](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-42824))

**The mechanics.** Copilot Enterprise Search accepts natural language prompts via the `?q=` URL parameter — a design choice that turns every search URL into a potential injection vector. An attacker crafts a link where the `q=` parameter contains instructions to search across the user's accessible M365 data and exfiltrate results via HTML `<img>` tags that force the browser to send data to an attacker-controlled server. Because Copilot has broad access to corporate data on behalf of the user, the blast radius includes "anything the user has access to inside the organization."

**The exfiltration path.** Microsoft had a guardrail in place that prevented direct HTML rendering of exfiltrated data, but Varonis found a bypass using a whitelisted `bing.com` domain. The attack combines three weaknesses: the parameter-to-prompt (P2P) injection surface, the HTML rendering exfiltration path, and the broad data access Copilot inherits from the user's identity.

**The broader pattern.** Varonis also disclosed Reprompt, a similar attack against Microsoft Copilot Personal. The researchers noted that "we did check many other LLMs, and some of them had a similar technique." The P2P injection class — where URL query parameters become AI instructions — is the new attack surface that makes classic web bugs exploitable in ways they would not be otherwise.

**Why it matters:** SearchLeak establishes parameter-to-prompt injection as a first-class web vulnerability class. Every AI-powered search feature that accepts natural language via URL parameters is potentially exploitable. For security teams, the immediate action is to audit which AI-enhanced web services in your environment accept prompt-style URL parameters and whether they have guardrails against data exfiltration via HTML rendering.

### WARP: 13 Words in a Reddit Comment Can Steer ChatGPT Deep Research and Gemini Toward Scams

**Cornell Tech researchers have demonstrated Web Agent Retrieval Poisoning (WARP)** — an attack that requires as few as 13 words slipped into an ordinary Reddit comment to steer AI search tools like ChatGPT's Deep Research and Google's Gemini toward fake products and scams. The attack never breaks into OpenAI, Google, or Reddit — it simply adds promotional text to a page the AI agent already reads. ([NeuralBuddies](https://www.neuralbuddies.com/p/ai-news-recap-june-19-2026) | Cornell Tech — Zhang, Triedman, Shmatikov)

**The results.** In testing, fictional decoys — a fake Austin restaurant called Sol Azteca and a made-up dating app named SilverPath — were name-dropped as genuine recommendations 38 to 51 percent of the time. The success rate climbed to 62 percent when the bait was spread across several threads. The attack exploits the fundamental trust AI agents place in web content they retrieve: if the content is on a page the agent reads, the agent treats it as fact.

**Why it matters:** WARP is the content-poisoning equivalent of prompt injection. It does not require compromising any system — it poisons the data the AI already trusts. For organizations deploying AI agents that search the web for research, competitive intelligence, or customer-facing answers, WARP demonstrates that the retrieval layer is now an attack surface that requires content provenance validation, not just domain reputation checks.

**Norway announced a near-total ban on AI use in elementary schools** on June 19, 2026, becoming the first major European country to impose broad AI restrictions in primary education. The decision reached 719 points and 496 comments on Hacker News, making it the most-discussed AI policy story of the day. ([Reuters](https://www.reuters.com/technology/norway-imposes-near-ban-ai-elementary-school-2026-06-19/) | [HN #48600093](https://news.ycombinator.com/item?id=48600093))

The Norwegian government cited concerns about data privacy, developmental impact on young children, and the risk of AI replacing foundational learning skills.

**Why it matters:** Norway's move is the most aggressive European education-sector AI restriction to date and sets a precedent that other European governments may follow. For AI vendors selling into education markets, the regulatory landscape just shifted: the EU AI Act's education provisions are one thing, but individual member-state bans create a patchwork that is harder to navigate than a single federal rule.

## Technical Deep Dives

### NRT-Bench: Multi-Turn Jailbreaks That Walk AI Agents Past Their Guardrails — Demonstrated on a Simulated Nuclear Plant

**A new arXiv preprint (arXiv 2606.20408, published June 18, 2026) introduces NRT-Bench, a benchmark that evaluates LLM agents under sustained, multi-turn adversarial pressure** — and the results show that safety scaffolding that holds up under single-prompt attacks degrades sharply when the attacker is patient. The test environment is deliberately dramatic: an LLM agent acting as a supervisory operator inside a simulated nuclear power plant control room, with access to plant telemetry and the ability to issue control recommendations. ([LufSec Blog](https://blog.lufsec.com/ai-security-threats-multi-turn-jailbreaks-career/) | [arXiv 2606.20408](https://arxiv.org/abs/2606.20408v1))

**The attack pattern.** The red team does not use a single crafted payload. Instead, they engage the agent across many turns with adaptive strategies: building rapport, reframing requests, planting false context earlier in the conversation to cash in later, and slowly redefining what "safe" means inside the conversation's own frame. The agent does not get tricked once and recover — it gets walked, step by step, into a state where its own internal narrative of the conversation no longer matches the policy it was deployed with.

**Why existing frameworks miss this.** Most jailbreak benchmarks score one prompt, one response. NRT-Bench scores trajectories. The OWASP LLM Top 10 categories do not cleanly carve this attack: prompt injection (LLM01) and excessive agency (LLM08) both apply, but the actual exploit is the interaction between them across time. Detection is harder than for one-shot attacks because each turn looks reasonable in isolation. The attack only exists when you look at the whole conversation.

**The generalization.** The nuclear plant scenario is a stress test, but the attack pattern generalizes to every LLM agent already shipping in production: SOC copilots, IT helpdesk bots, code-review agents, customer support deflection systems. The closest analogue from classic security is social engineering pretexting — except the target is a system with no fatigue, no suspicion budget, and a strong prior toward continuing to be helpful.

**Why it matters:** Multi-turn jailbreaks are the next frontier in AI security, and most organizations have no detection capability for them. The NRT-Bench results suggest that any agent deployed with a multi-turn conversation capability is potentially vulnerable to gradual policy erosion. Security teams should evaluate whether their AI monitoring tools can detect trajectory-level attacks, not just single-turn prompt injections.

## The Daily Feed

- **DragonForce Ransomware Hid C2 Traffic in Microsoft Teams for Two Months** — Symantec and Carbon Black published an investigation report on June 16 detailing how DragonForce ransomware operators used a Go-based RAT called Backdoor.Turn to abuse Microsoft Teams' TURN relay servers, masking C2 traffic as legitimate Teams connections. The attackers obtained an anonymous Teams visitor token from Microsoft's Skype-backed identity services, then ran a QUIC transport session linking the infected machine to an attacker-controlled server. Requires physical USB access and DFU mode, but can run code before iOS loads, bypassing signature checks and booting modified software. Affected devices include iPhone XS, XR, 11, and SE (2nd gen). ## Five Things to Take Into the Rest of the Day

**1. Your AI agent framework is production infrastructure — patch it like it.** Langflow, LangGraph, and LangChain all share the same bug class (untrusted input reaching execution paths), and 7,000+ Langflow servers are actively under attack. Inventory every LangChain-family deployment, confirm patch levels, and treat internet-facing Langflow instances as an emergency.

**2. Localhost is not a trust boundary for AI agents.** AutoJack proves that any agent with web-browsing capabilities can be hijacked through a single malicious page because the agent inherits localhost identity. Apply authentication to every MCP endpoint, even on loopback, and allowlist executables that MCP servers may invoke.

**3. URL parameters are now AI instructions — audit your AI-powered search features.** SearchLeak (CVE-2026-42824) establishes parameter-to-prompt injection as a first-class vulnerability class. Every AI-powered search feature that accepts natural language via URL parameters is a potential data exfiltration vector. Audit your environment for P2P injection surfaces.

**4. Multi-turn jailbreaks are the next frontier — and you have no detection for them.** NRT-Bench demonstrates that safety scaffolding degrades under sustained multi-turn pressure. Most organizations have no capability to detect trajectory-level attacks. Evaluate whether your AI monitoring tools can detect gradual policy erosion across conversation turns.

**5. Content poisoning is the new prompt injection.** WARP proves that 13 words in a Reddit comment can steer AI search tools toward scams. The retrieval layer is now an attack surface. For AI agents that search the web, content provenance validation is no longer optional — it is a security control.
