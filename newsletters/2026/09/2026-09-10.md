## 1) AWS Labs Postgres MCP — Critical `COPY … TO PROGRAM` RCE (CVE-2026-87911)

AWS Security Bulletin **2026-104-AWS** (publication **2026-09-09 12:30 PM PDT** / **19:30 UTC**) and GHSA-fph8-pg5w-78fv disclose that `awslabs.postgres-mcp-server` **before 1.1.7** has incomplete SQL deny-list / read-only enforcement: a crafted `COPY … TO PROGRAM` statement in content processed when an authenticated user interacts with the MCP server in default read-only mode can execute OS commands on the host of a **self-managed** PostgreSQL server if the DB role holds `superuser` or `pg_execute_server_program`. Amazon rates **CVSS v3.1 9.6** / **v4.0 9.0**. NVD published **2026-09-09T20:21:02Z**. Fix: **1.1.7+**; do not connect the MCP role as superuser / `rds_superuser` / master.

New OS-command disclosure — distinct from Sep 4’s CVE-2026-85787 (same package/fix floor, different bug class). No in-window primary claim of wild exploitation.

**Consulting angle:** inventory `awslabs.postgres-mcp-server` and forks; ask whether “read-only” MCP modes are enforced only by app denylists or also by DB role grants that cannot run `COPY … TO PROGRAM`.

Sources: AWS bulletin 2026-104-AWS, 2026-09-09 19:30Z — https://aws.amazon.com/security/security-bulletins/2026-104-aws/ ; GHSA-fph8-pg5w-78fv, Sep 9, 2026 — https://github.com/awslabs/mcp/security/advisories/GHSA-fph8-pg5w-78fv ; NVD CVE-2026-87911, published 2026-09-09T20:21:02Z — https://nvd.nist.gov/vuln/detail/CVE-2026-87911
