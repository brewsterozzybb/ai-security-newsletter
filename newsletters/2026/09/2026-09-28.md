## 1) Citrix NetScaler ADC/Gateway — exploited unauth RCE zero-days → KEV (due Sep 30)

Citrix **CTX697096** (**Initial Publication 2026-09-27**) discloses eight NetScaler ADC/Gateway CVEs. The two under active exploitation: **CVE-2026-88771** (improper input validation → unauthenticated command execution on **all** default-config ADC/Gateway deployments; vendor **CWE-20**; CVSS v4 **9.5**) and **CVE-2026-88772** (memory overflow RCE/DoS when **DTLS** is enabled — **default on VPN vServer**; **CWE-119**; CVSS v4 **9.5**). Fixed builds include **14.1-73.37** and **13.1-64.23** (plus FIPS/NDcPP peers). Citrix states exploits of both **have been observed** on unmitigated deployments.

CISA advanced KEV to **`catalogVersion=2026.09.27`**, **`dateReleased=2026-09-27T21:30:35Z`**, **count 1728** (+2). Same-day CISA Alert confirms **global active exploitation** and urges IoC/compromise assessment **before** patching (updates can destroy forensic visibility). Sibling CVEs (88773–88778) cover HTTP smuggling, feature-policy bypass, mem-overflow DoS, and TCP ISN prediction — the patch train is broader than the two KEV rows.

**Evidence type:** official advisory (Citrix + CISA KEV + CISA Alert). **Caveat:** KEV’s `cwes` field for **88771** lists **CWE-119**, while the vendor table assigns **CWE-20** to 88771 and **CWE-119** to 88772 — lead on listing + due date; use the vendor table for technical typing.

**Consulting angle:** inventory customer-managed NetScaler ADC/Gateway; treat pre-fixed builds as emergency; hunt IoCs and preserve forensics **before** upgrade; plan the BOD window through **Sep 30**.

## 2) LuaRocks.org — LuaJIT bytecode rockspec sandbox escape (exploited Jul–Aug; public Sep 27)

**LuaRocks.org** published its **Security Incident, September 2026** page (community clocks **~13:58–20:13Z Sep 27**: Lobsters, HN, site push). The rockspec upload path called LuaJIT `loadstring` **without rejecting precompiled bytecode**, so a registered user could escape the empty `setfenv` sandbox and reach **root-equivalent** on the package host. Vendor: exploitation **Jul 9 – Aug 20 2026** (shell; malicious packages **`bcrcewon`**, **`7e0b94029db0`**, **`7e0b9402f9c8`**); report via **CISA Sep 25**; **fixed Sep 26**; site rebuilt; **all API keys / sessions / 2FA secrets revoked**. Vendor asserts **no evidence existing packages were modified** (mirror-diff). Client risk remains: LuaRocks **≤3.11.1** on LuaJIT/Lua 5.1 can still load bytecode from a hostile server — upgrade **≥3.12**. Researcher Vhyrro write-up carries `article:published_time=2026-09-27T00:00:00Z` (**OUT**) — technique amp only; **lead on the official incident page**.

**Evidence type:** observed incident (vendor) + researcher write-up (blog clock OUT). In-window clock is **public incident + community surfacing**, not first exploitation.

**Consulting angle:** inventory Lua/OpenResty/Neovim-plugin luarocks consumers; rotate credentials for anyone who authenticated to the index; treat hosts that installed the three named packages as compromised; do not treat “empty env + instruction limit” as a sandbox when the loader accepts bytecode.

Sources: LuaRocks incident — https://luarocks.org/security-incident-september-2026 ; Researcher (OUT clock) — https://vhyrro.neorg.org/posts/critical-luarocks-exploit-cve/

## 3) Obot AI agent / MCP platform — NVD formalization cluster (quickstart docker.sock + MCP connect bypass)

NVD published **2026-09-27 ~21:17Z** (GHSA-DB mirrors ~21:31Z) a cluster against **obot-platform/obot**:
- **CVE-2026-101065** (CVSS v3.1 **9.8**): Docker quickstart binds `0.0.0.0:8080` with auth disabled → synthetic Owner/Admin plus **`/var/run/docker.sock`** → host compromise via attacker MCP servers. Remediation called **documentation-only** (`OBOT_SERVER_ENABLE_AUTHENTICATION=true`). Upstream GHSA **May 8** (OUT).
- **CVE-2026-101084** (CVSS v3.1 **9.6**): `/mcp-connect` skips ACRs → any authenticated user with a server ID can invoke restricted MCP tools (incl. stored OAuth). Patched **v0.21.1** (**2026-05-07**, OUT).
- Siblings: OAuth DCR without auth/redirect allowlist (**CVE-2026-101062**, fix **v0.23.0** Jun OUT), MCP Registry readable without auth (**101063**), privileged remote-MCP URL SSRF (**101064**).

**Evidence type:** official advisory (NVD/GHSA-DB formalization; upstream May–Jun). **Do not imply a brand-new May/June patch day** — in-window clock is CVE/NVD visibility.

**Consulting angle:** inventory Obot (and peer agent platforms) for default-open quickstarts and docker.sock mounts; require auth before any network bind; re-check `/mcp-connect` / registry ACLs even for “authenticated” users.

Sources: NVD CVE-2026-101065 — https://nvd.nist.gov/vuln/detail/CVE-2026-101065 ; GHSA-DB — https://github.com/advisories/GHSA-m95h-j2gj-xrgq ; Upstream — https://github.com/obot-platform/obot/security/advisories
