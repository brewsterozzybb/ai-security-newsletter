## 1) LiteLLM — JWT email-fallback account takeover → proxy_admin (CVE-2026-93355)

OX Security published **CVE-2026-93355** (**`2026-09-29T06:59:10Z`**; NVD **`2026-09-28T20:17:11Z`**): LiteLLM’s JWT path matches `user_id` / `sso_user_id` first; on miss it falls back to the token’s **`email` claim without checking `email_verified`**. An attacker with any **validly signed JWT from the configured IdP** (low privilege) can authenticate as an existing user — including **`proxy_admin`** — and the handler **permanently rewrites** the victim’s `sso_user_id`. OX: reported **2026-05-18**; public after ~120 days with **no vendor patch** (“Unpatched”; through **1.100.1** / VulnCheck ≤**1.102.1**). Scoring: OX **8.8** (CVSS v3.1) vs VulnCheck/NVD **7.6** (CVSS v4); NVD also lists VulnCheck v3.1 **8.1** — cite carefully; do not invent a fixed release.

**Evidence type:** researcher experiment (OX) + official advisory (NVD); **not** a vendor-acked patch. **Prerequisite:** valid IdP JWT (**PR:L**) — not unauthenticated internet RCE. Patch status disputed (OX “Unpatched” vs VulnCheck ceiling); confirm live BerriAI/litellm release before “upgrade to X.” Enforce `email_verified=true` at the trust boundary; treat standing `sso_user_id` rebinds as durable compromise.

Sources: OX — https://www.ox.security/blog/litellm-an-ordinary-login-token-can-become-someone-elses-admin-account/ ; NVD — https://nvd.nist.gov/vuln/detail/CVE-2026-93355 ; VulnCheck — https://www.vulncheck.com/advisories/litellm-weak-jwt-authentication-via-email-based-user-lookup
