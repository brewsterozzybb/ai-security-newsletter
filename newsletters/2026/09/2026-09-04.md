# AI-security brief — Sep 4, 2026

*Coverage: Aug 28–Sep 4, 2026 ET. Primary-source claims are linked and dated; vendor/researcher claims are labeled.*

This week’s hard signal is tool- and gateway-trust: an MCP auth bypass entered KEV, a runtime-gated MCP metadata campaign got a fresh research note, and two papers measured stealthy agent prompt injection. Separately, three labs shipped or gated stronger cyber-capable models under restricted access. Several of those capability and safeguard claims remain vendor-stated.

## 1) CISA adds LiteLLM MCP auth bypass to KEV

On Sep 2, CISA added seven vulnerabilities to its Known Exploited Vulnerabilities catalog on evidence of active exploitation. One AI-gateway entry, CVE-2026-59822 in BerriAI LiteLLM, concerns improper authentication on the MCP Streamable HTTP endpoint. KEV text says an unauthenticated attacker could establish an authenticated MCP session using an arbitrary Bearer token. Due date is Sep 16; ransomware use is listed as Unknown; forensic triage is not required for this entry.

The vendor advisory (Jun 30) says affected versions are LiteLLM before 1.84.0, with a fix in 1.84.0. It describes an OAuth2-passthrough fallback that could replace failed key validation with an empty `UserAPIKeyAuth()`, allowing a fabricated Bearer token to reach configured MCP tools (CVSS 8.8). Workaround noted there: disable or block `/mcp/` routes.

This is a newly cataloged exploited vulnerability, not a newly disclosed bug. CISA does not name exploiters, campaigns, or AI-agent involvement. Same-day KEV companions CVE-2026-48710 (Starlette request smuggling) and CVE-2026-49869 (Kestra OSS auth-bypass RCE) are adjacent common stack issues; CISA does not market them as “AI bugs.”

Sources: CISA, Sep 2, 2026 — https://www.cisa.gov/news-events/alerts/2026/09/02/cisa-adds-seven-known-exploited-vulnerabilities-catalog ; LiteLLM advisory, Jun 30, 2026 — https://github.com/BerriAI/litellm/security/advisories/GHSA-7488-6r32-c95q ; NVD — https://nvd.nist.gov/vuln/detail/CVE-2026-59822

## 2) Deadbugz: runtime-gated MCP metadata poisoning

On Sep 2, the Cloud Security Alliance published a research note on Deadbugz, restating Pillar Security’s Aug 12 disclosure of a malicious MCP server campaign. Treat the Aug 10 PR burst and Aug 12 Pillar writeup as out-of-window origins; the CSA note is this week’s primary packaging, not a new discovery.

Per Pillar (as restated): account `zellkernel` opened 23 unsolicited GitHub PRs in roughly 75 minutes on Aug 10 UTC promoting `productivity-suite`; none were merged via GitHub review at disclosure. After three `tools/call`s, `tools/list` / `prompts/get` reportedly flip to credential-seeking instructions (SSH keys, AWS credentials, kubeconfig, shell history) plus concealment guidance. Cited IoCs include `productivity-suite-mcp.onrender.com/mcp` and a local artifact under `~/.config/.cache/.sys/.deadbug-mcp.py`. CSA says no CVE was assigned as of the note date and frames tool metadata as a runtime security boundary.

Whether any target actually ran the server locally, and whether the campaign remains active beyond the authors’ statements, are unverified here.

Sources: CSA, Sep 2, 2026 — https://labs.cloudsecurityalliance.org/research/csa-research-note-deadbugz-mcp-metadata-poisoning-20260902-c/ ; Pillar Security, Aug 12, 2026 — https://www.pillar.security/blog/deadbugz-currently-active-mcp-supply-chain-campaign

## 3) Coding agents: Git config sinks before trust prompts

Manifold Security disclosed Sep 1 that a repository delivered with a malicious `.git/config` can set `core.fsmonitor` (a Git configuration execution sink, not a hook) when coding agents run ordinary context commands such as `git status` or `git diff`. The reported risk is host-level execution as the user, before an agent’s prompt, trust dialog, or authentication flow.

Delivery requires a pre-populated `.git` directory (zip, shared folder, USB). Clone, fetch, and pull do not deliver this vector as described.

Goose’s advisory for CVE-2026-72718 is hard vendor corroboration of the same class: `goose review` could lead to unsandboxed `git diff` and `core.fsmonitor` RCE; fixed in 1.44.0. Multi-agent patch-status tables in the Manifold post are researcher-reported and were not independently re-verified for this edition.

Sources: Manifold Security, Sep 1, 2026 — https://www.manifold.security/blog/ai-coding-agents-git-hijack ; Goose advisory, Jul 24, 2026 — https://github.com/aaif-goose/goose/security/advisories/GHSA-r5pp-p5r8-466r

## 4) Labs gate stronger cyber models

Three in-window lab posts describe higher cyber capability under restricted access. These are vendor-stated evaluations and plans unless marked otherwise.

**OpenAI (Sep 1):** Path to Astra says Astra is its first model to meet the Preparedness Framework’s “Critical” cybersecurity level—with tools and access, able to find unknown flaws and develop exploits across many hardened systems without step-by-step human guidance. OpenAI reports delayed parts of development/release while strengthening cyber-misuse and unauthorized-action protections; a paused large frontier RL run for future Astra versions restarted Aug 28 after higher training-environment bars. It plans broader availability soon, with advanced cyber access first for alpha testers and then Daybreak Blue for defense. Jailbreak refuse rate on its cyber set: 91.5% vs 59% for GPT-5.6 Sol (vendor eval).

Source: https://openai.com/index/path-to-astra/

Anthropic calls Mythos 5.1 its strongest released cyber capabilities while still placing that evaluation in a lower Frontier Compliance Framework category with safeguards off for the eval. Fable cyber safeguards are described as allowing vuln discovery but not exploit development.

Sources: https://www.anthropic.com/claude-fable-and-mythos-5-1 ; https://www.anthropic.com/claude/mythos

## 5) Research: stealthy agent prompt injection

Two in-window arXiv papers (author-reported experimental results, not independent replications):

**ECLIPSE (submitted Aug 31):** Self-evolving stealthy prompt injection against long-horizon agents, combining one-shot injection with tool-description steering (SWE) and corrective signals in tool results (DTC). LASE-Bench: 120 tasks, 198 tools; 96.7% of tasks involve ≥5 tool calls. Reported ASR up to 96.7% undefended and 69.2% under a common safety filter (+27.5 pp vs strongest baseline in the DeepSeek setting). Case studies on OpenClaw and Hermes; authors say they withhold live-tuned prompts.

Source: https://arxiv.org/abs/2608.30441

**ICoA / covert IPI (submitted Aug 31, revised Sep 1):** Separates Covert Success Rate from Overt Success Rate based on whether the final user-facing reply discloses the injected action. On AgentDojo across four models, ICoA achieves the highest CSR, with gains of 3.79–12.01 percentage points over the strongest baseline (author-reported). A RETURN-trajectory anchor alone can raise CSR by up to 23.71 pp. Sandboxed evaluation; authors plan to share findings with the four target-model providers before public artifacts.

Source: https://arxiv.org/abs/2608.30362

## Editor’s takeaway

The operational lesson is narrower than “align the model.” Treat MCP gateways, tool metadata, and host-side context gatherers as executable trust boundaries; patch KEV’d AI gateway components on the federal clock; and assume long-horizon agents can succeed without the user-facing reply disclosing it.

KEV due dates and the Goose `core.fsmonitor` advisory support the host/gateway points directly. Covert-vs-overt ASR and Deadbugz concealment guidance are researcher/vendor-reported. Broader control recommendations beyond those citations are editorial synthesis.
