## 1) Serena MCP — default `0.0.0.0` + no auth (CVE-2026-38924)

MITRE/NVD published **CVE-2026-38924** on **2026-09-14** (MITRE `datePublished` **2026-09-14T00:00:00Z**; NVD **2026-09-14T03:16:36.893Z**). Oraios AI **Serena** before **1.0.0**, in HTTP mode, listens on **`0.0.0.0`**. Combined with unauthenticated SSE/streamable-HTTP and a shell tool (`subprocess.Popen(..., shell=True)` per Dash Security), a network-reachable caller can drive command execution as the Serena process user.

Dash’s July 13 write-up (background) frames three co-present conditions in ≤0.1.4: network exposure by default, no HTTP auth, unsanitized shell. Fix lineage includes commit `b00ae29` (Mar 29) and the v1.0.0 line. MITRE notes the supplier called `0.0.0.0` a “potential security hazard” while docs still recommended sandboxing Serena rather than mandating localhost.

**Evidence type:** official advisory + researcher experiment. **Not** observed mass exploitation in KEV this window.

**Consulting angle:** inventory coding-agent MCP transports that bind beyond loopback without auth; treat them as privileged local middleware. Stdio-only deployments are a different boundary.

Sources: NVD CVE-2026-38924, published 2026-09-14T03:16:36.893Z — https://nvd.nist.gov/vuln/detail/CVE-2026-38924 ; MITRE CVE List — https://cveawg.mitre.org/api/cve/CVE-2026-38924 ; Dash Security, Jul 13, 2026 (background) — https://dash.security/blog/cve-2026-38924-unauthenticated-rce-in-the-serena-mcp-server ; fix commit — https://github.com/oraios/serena/commit/b00ae292ac2d49947506886f44eb1cad7b7d7cd1

## 2) CrewAI — import blocklist ≠ sandbox (CVE-2026-37008)

NVD published **CVE-2026-37008** on **2026-09-13T21:17:01.303Z** (MITRE **2026-09-13T00:00:00Z**). CrewAI before commit **`fb2323b`** uses an import-time Python module blocklist that does **not** constrain the interpreter object graph — e.g. `ctypes.CDLL(None)` loads libc without an import. NVD explicitly separates this from **CVE-2026-2275** (Docker→sandbox fallback).

**Evidence type:** official advisory + researcher experiment (Yeran Gamage write-up linked from NVD). Exploitation typically needs an agent code-execution path plus ability to influence executed code. Confirm customer pins include `fb2323b`+ / current release behavior.

**Consulting angle:** ask whether “sandbox” for agent code tools is process-local allow/deny or real isolation (container/VM/dedicated runtime). Prompt injection into a blocklist sandbox is still host compromise risk.

Sources: NVD CVE-2026-37008, published 2026-09-13T21:17:01.303Z — https://nvd.nist.gov/vuln/detail/CVE-2026-37008 ; patch — https://github.com/crewAIInc/crewAI/commit/fb2323b3deb3ec62b3965526857e77a2264e4cd0 ; researcher — https://yerangamage.com/cves/detail/?slug=crewai-sandbox-escape

## 3) Flowise Evaluations SSRF — Host / X-Forwarded-Proto (CVE-2026-90580)

NVD published **CVE-2026-90580** on **2026-09-13T20:16:51.317Z**. FlowiseAI Flowise **≤3.0.2**: evaluations controller builds outbound prediction base URL from client-controlled **`Host` / `X-Forwarded-Proto`**, enabling SSRF. Fixed in **3.1.3** (commit `7001377…`). Public issue #6687 opened Jul 30 (background).

**Evidence type:** official advisory (VulDB/NVD) + public researcher issue. NVD notes a support-status caveat for the affected line — verify whether client builds are on a maintained/patched release. Auth posture of the evaluations endpoint is not fully specified in the NVD blurb.

**Consulting angle:** classic reverse-proxy header trust bug in an LLM workflow platform; SSRF from the Flowise host identity toward metadata/internal APIs.

Sources: NVD CVE-2026-90580, published 2026-09-13T20:16:51.317Z — https://nvd.nist.gov/vuln/detail/CVE-2026-90580 ; GH issue #6687 (background) — https://github.com/FlowiseAI/Flowise/issues/6687

## 4) Cheshire Cat AI — missing auth via `user_id` (CVE-2026-90579)

NVD published **CVE-2026-90579** on **2026-09-13T19:16:53.517Z**. Cheshire Cat AI **≤1.9.2**: `_authorize_http_key` in `custom_auth_handler.py` — manipulation of **`user_id`** leads to missing authentication; remote; exploit disclosed publicly; NVD states the project was informed early and has not responded. Default installs without an API key are especially exposed (per issue metadata).

**Evidence type:** official advisory + community issue. Patch availability **uncertain**. PoC not re-run here.

**Consulting angle:** force API keys / network isolation on agent frameworks that ship auth-optional defaults; don’t assume lab defaults stay lab-only.

Sources: NVD CVE-2026-90579, published 2026-09-13T19:16:53.517Z — https://nvd.nist.gov/vuln/detail/CVE-2026-90579 ; GH issue #1137 (background) — https://github.com/cheshire-cat-ai/core/issues/1137

## Worth keeping

1. **MCP HTTP default bind `0.0.0.0` + no auth is an RCE path, not a config nit.** Serena’s CVE text and Dash’s three-condition kill chain make the identity-broker failure concrete for coding-agent MCP.  
   - **Use:** assessment check — “Does every non-stdio MCP transport bind loopback-only and require auth?”  
   - **Source:** NVD/MITRE CVE-2026-38924, 2026-09-14 (above).  
   - **Limits:** Formal CVE pub of an older finding; analyst generalization to “all coding MCP servers” is inference. Not KEV.  
   - **Tags:** `mcp-http-bind` `agent-control-plane`

2. **Import-time blocklists are the wrong abstraction for agent code sandboxes.** CrewAI’s CVE shows object-graph escapes (`ctypes.CDLL(None)`) that never touch a blocked import.  
   - **Use:** workshop question / assessment check for agent code-exec tools.  
   - **Source:** NVD CVE-2026-37008, 2026-09-13 (above).  
   - **Limits:** Vendor/researcher CVE path; not a surveyed fleets finding. Distinct from Docker-fallback CVE-2026-2275.  
   - **Tags:** `agent-sandbox` `wrong-abstraction`
