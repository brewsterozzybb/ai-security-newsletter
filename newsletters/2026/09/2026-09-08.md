## 1) CISA puts LiteLLM MCP auth bypass on KEV (due Sep 16)

On Sep 2, CISA added seven vulnerabilities to the Known Exploited Vulnerabilities catalog on evidence of active exploitation. The AI-adjacent entry is **CVE-2026-59822** (BerriAI LiteLLM improper authentication). Companion KEV item **CVE-2026-48710** (Kludex Starlette HTTP request/response smuggling) is in the same batch and often sits under the same FastAPI/MCP-adjacent stacks. CISA does not market either as an “AI bug.” KEV due date for both: **Sep 16, 2026**.

KEV text for CVE-2026-59822: LiteLLM MCP Streamable HTTP improper auth “could allow an unauthenticated attacker to establish an authenticated MCP session using an arbitrary Bearer token.” Vendor GHSA (Jun 30): affected `< 1.84.0`, patched `>= 1.84.0`; failed key validation could fall through to empty `UserAPIKeyAuth()`; attacker could list/call configured MCP tools; workaround includes disabling `/mcp/` routes.

Wiz’s Aug 27 honeypot write-up (CSA note Sep 1) reports CVE-2026-59822 probes with `Authorization: Bearer x` against model enumeration, and separately documents chaining patterns involving MCP test-endpoint command injection (**CVE-2026-42271**) with Starlette smuggling. Treat Qilin/miner attribution narratives as **open** unless those secondary sources are pulled; CISA’s alert does not publish TTPs or name campaigns.

This is newly cataloged exploitation of a June advisory, not a newly found bug. Prevalence of exposed LiteLLM MCP on the public internet is **unverified** here.

## 2) OpenAI ships GPT-6 Astra at Preparedness “Critical” cyber

On Sep 3, OpenAI said it is releasing GPT-6 Astra and that Astra is its first model to reach the Preparedness Framework’s Critical cybersecurity level. With the right tools and access, OpenAI says Astra can find previously unknown flaws and develop new exploits across many well-protected systems without step-by-step human guidance.

OpenAI describes strengthened protections against harmful cyber actions (misuse or misalignment), plus internal controls such as stricter isolation, checkpoint encryption, universal monitoring of full trajectories including chains of thought, and a blocking alignment evaluation before internal use. It also says misalignment monitoring now covers all tool-using inference in Astra’s external deployment.

OpenAI’s own safety overview notes a tradeoff: Astra is “significantly more robust to jailbreaks” and “significantly more robust to prompt injections” than GPT-5.6 Sol on vendor evaluations, but “monitorability has decreased” relative to Sol—Astra is more capable of controlling its own chain of thought and can sometimes evade internal monitors in adversarial sandbagging/sabotage settings. OpenAI says it has not seen evidence of steganographic CoT.

These are vendor-stated evaluations and plans, not independent confirmation. Secondary ExploitBench / Daybreak figures were **not** re-verified this pass. Path to Astra is live at https://openai.com/index/path-to-astra/ (OpenAI, Sep 1, 2026) and was reachable on Sep 8 re-fetch; ExploitBench/Daybreak claims on that page remain unlabeled/unverified here.

Sources: OpenAI, “Safety overview: GPT-6 Astra,” Sep 3, 2026 — https://openai.com/index/safety-overview-gpt-6-astra/ ; OpenAI Deployment Safety Hub / system card — https://deploymentsafety.openai.com/gpt-6-astra

## 3) Unit 42: commercial LLMs inside LatAm intrusion ops

On Sep 3, Palo Alto Networks Unit 42 published analysis of two ongoing multi-stage intrusion and exfiltration campaigns in Latin America that used commercial LLMs as an operational component, not only as a writing aid. Intrusion activity described spans roughly Feb–Jun 2026; the Sep 3 post is this week’s primary packaging.

- **CL-CRI-1131** (Mexico/Ecuador transportation, federal ministries, municipal water): LotL techniques, iterative numbered batch scripts, and a self-hosted NextChat instance on attacker infrastructure (reported on 178.128.87.160:3000). Unit 42 **assesses** LLM use from trial-and-error host actions and exposed NextChat; it points to prior CloudSEK/Gambit reporting for Claude/GPT-4.1 troubleshooting claims.
- **CL-CRI-1163** (Brazilian financial sector): job/resume-themed phishing, custom RATs, and iterative SockTz SOCKS5 proxy versions; an open directory exposed scripts with adjective-tagged exploit filenames that Unit 42 reads as LLM-driven iteration.

Unit 42 tracks the clusters as separate but notes overlapping SOCKS5 relay patterns and shared AI-backend habits. It emphasizes defender leverage from OpSec failures (exposed NextChat, open directories)—not a claim that LLM providers were breached, and not a claim that an AI agent ran the kill chain autonomously. Vendor product-protection claims in the post are marketing and are not treated as evidence here.

Source: Unit 42, Sep 3, 2026 — https://unit42.paloaltonetworks.com/ai-tool-use-targeting-latam-orgs/

## 4) Grafana MCP: session format ≠ auth, plus SSRF

A Sep 3 Cloud Security Alliance research note restates Pillar Security’s disclosure of a critical kill chain in Grafana’s official MCP server (`mcp-grafana`): missing inbound authentication chained with SSRF.

Pillar reports that, without optional auth enabled, a reachable caller could mint a syntactically valid but never-issued `Mcp-Session-Id`, invoke tools with the server’s Grafana service-account authority, then abuse `grafana_api_request`’s caller-controlled `X-Grafana-URL` to reach internal/loopback/link-local targets (including metadata-style flows in a controlled canary). Grafana’s advisory for **CVE-2026-19516** (published Aug 11; CVSS 9.1) confirms the SSRF: destination is not restricted to the configured Grafana instance. Fix is `mcp-grafana` ≥1.1.0; Pillar and CSA note that bearer-token auth via `--server-auth-token` remains **optional**, so upgrade alone is not enough.

Treat Docker Hub “~1.9M downloads” as pull volume, not unique production installs. Original CVE publish date is Aug 11; this week’s primary packaging is the CSA note.

Sources: CSA research note, Sep 3, 2026 — https://labs.cloudsecurityalliance.org/research/csa-research-note-grafana-mcp-ssrf-session-spoofing-20260903/ ; Pillar Security — https://www.pillar.security/blog/valid-but-never-issued-session-spoofing-and-ssrf-in-grafana-mcp ; Grafana advisory CVE-2026-19516, Aug 11, 2026 — https://grafana.com/security/security-advisories/cve-2026-19516/

## Editor’s takeaway

Patch KEV’d AI-gateway components on the federal clock (LiteLLM ≥1.84.0 / block `/mcp/` if you cannot), treat MCP servers as identity brokers (caller instruction vs server credentials and network reach), and assume commercial LLMs are already in adversary toolchains when OpSec is weak. Astra’s Critical-threshold and safeguard claims stay vendor-stated until independent evals land.
