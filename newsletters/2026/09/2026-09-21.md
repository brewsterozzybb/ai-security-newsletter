## 1) REDCap — unauthenticated RCE via survey passthrough + Data Import (CVE-2026-90817)

NVD published **CVE-2026-90817** on **2026-09-20T13:17:44.973Z** (CVSS **9.8** Critical): **REDCap ≥13.3.0** — an attacker who knows a **valid public survey hash** can abuse survey passthrough routing into Data Import handling and achieve arbitrary code execution on the REDCap server. Aggregators cite floors **16.0.49 LTS / 17.3.10 LTS / 17.4.4 Standard** (confirm against your Vanderbilt/REDCap upgrade channel).

**Evidence type:** official advisory (NVD + CNA Securifera). Not AI-native — **operationally significant cyber** for universities, hospitals, and clinical-research clients with public surveys. Survey-hash knowledge is a realistic precondition (shared URLs, bookmarks, referrer logs), not a fully blind internet spray.

**Consulting angle:** inventory internet-reachable public surveys; patch or isolate until floors are confirmed; treat survey hashes as semi-secrets in logs and tickets.

Sources: NVD — https://nvd.nist.gov/vuln/detail/CVE-2026-90817 ; CVE.org — https://www.cve.org/CVERecord?id=CVE-2026-90817

## 2) ChatGPT ads `__obi` — cross-site identity join via OpenAI ad collector

Independent researcher **buchodi** (page dated **20 Sep 2026**) documents that OpenAI’s ads collector at `bzr.openai.com` sets `__obi` (`Domain=.openai.com`, `SameSite=None`, `Secure`) bound to the ChatGPT account (or a stable anonymous subject), then receives that cookie when third-party advertiser sites load OpenAI’s pixel/SDK — joining off-site browsing/conversion events to a ChatGPT identity. Observed on Chrome for Android; Safari ITP / iOS WebKit block the path. Cookie policy lists `__obi` under **Analytics**; the post reports sync tokens with `consent_decision: analytics_allowed` even when marketing consent is refused. HN created **2026-09-20T15:18:44Z** (~**724** pts / ~**386** comments at research pull).

**Evidence type:** researcher experiment + community amplification. **Not** a CVE. Do **not** claim advertisers can read ChatGPT chats — advertiser JS cannot read `__obi`. Server-side account resolution is inferred from design, not directly observed. ~1/5 sessions produced sync tokens in author tests.

**Consulting angle:** treat logged-in ChatGPT on Chrome as a higher-risk adtech join surface; block `bzr.openai.com` / `bzrcdn.openai.com` where policy allows; review analytics consent with privacy stakeholders.

Sources: buchodi — https://www.buchodi.com/chatgpt-now-knows-what-you-do-on-other-websites-via-ad-collector/ ; OpenAI cookie policy (background) — https://openai.com/policies/cookie-policy/

## 5) CRI-O checkpoint restore — privilege retention (CVE-2026-92574)

**CVE-2026-92574** (CVSS **8.8**): a pod created from a **malicious checkpointed container** can bypass the destination Kubernetes security context — retaining credentials, capabilities, `no_new_privs`, and seccomp from the checkpoint. Upstream CRI-O **1.34+**; OpenShift from **OCP 4.17**. NVD: fixes applied to supported branches but **“not yet released.”** RH `public_date` **2026-09-21T09:00:00Z**; NVD **10:17Z**.

**Evidence type:** official advisory (Red Hat + NVD + GHSA). Not AI-specific — material for agent/sandbox hosts using checkpoint/restore. Needs checkpoint-restore enabled + permission to create pods from checkpoint images.

**Consulting angle:** disable checkpoint-restore until patched packages ship; ask agent-sandbox vendors which runtime/restore path they use.

Sources: NVD — https://nvd.nist.gov/vuln/detail/CVE-2026-92574 ; Red Hat — https://access.redhat.com/security/cve/CVE-2026-92574
