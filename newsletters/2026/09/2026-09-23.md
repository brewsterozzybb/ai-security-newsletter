## 2) WordPress — unauthenticated page-template path traversal → conditional RCE (CVE-2026-87902)

WordPress published **GHSA-7hp8-65ch-5whp** on **2026-09-22T13:57:27Z** (updated **14:24:56Z**): an unauthenticated attacker can make `get_page_template()` include a chosen readable local `.php` outside theme directories. With named preconditions (e.g. themes with top-level `page-*` dirs such as Twenty Twelve/Fourteen, Neve, Hestia, Sydney; Docker `php` / cPanel PHP&lt;8.5 `pearcmd` paths; `register_argc_argv=On`), that can reach **RCE**. Patched in **7.1.2** and backports through **4.7+**. GHSA rates **CVSS 9.2** with Attack Requirements Present — **not** “universal unauth RCE on every install.” HN spiked the advisory (~**208** pts, **16:33Z**).

**Evidence type:** official advisory (WordPress GHSA). First public GHSA clock is in-window; not covered in prior Prism editions.

**Consulting angle:** patch WordPress across branches; inventory themes with `page-*` layout and PHP hosts that ship `pearcmd`; do not treat “conditional” as “ignore.”

Sources: GHSA-7hp8-65ch-5whp — https://github.com/WordPress/wordpress-develop/security/advisories/GHSA-7hp8-65ch-5whp ; CVE-2026-87902

## 4) 9Router — public LLM API auth bypass via spoofable `X-9r-Real-Ip` (CVE-2026-56681) — formalization

**GHSA-DB / NVD formalization** (**GHSA-5mj8-gf6m-fhw8** published **`2026-09-22T16:34:06Z`**; NVD **`2026-09-22T16:17:48.350Z`**): prior to **0.5.6**, when Next.js is reachable without the sanitizing `custom-server.js` wrapper, client-controlled `X-9r-Real-Ip: 127.0.0.1` makes `isLocalRequest` treat the caller as local and **skip API-key checks on `/api/v1/*`**, granting unauthenticated use of the public LLM API / provider relay. Sibling **CVE-2026-56682** bypasses login lockout the same way. Code fixed in **v0.5.6** (GitHub release **`2026-06-20T09:13:12Z`** — **background**; repo advisory first appeared mid-July). **In-window novelty is CVE/GHSA-DB publication, not a new patch day.**

**Evidence type:** official advisory (NVD/GHSA-DB formalization). Classic confused-deputy / trusted-header failure on an AI gateway. Vulnerable only where Next.js is exposed without the header-regenerating custom server; operators already on **≥0.5.6** are patched.

**Consulting angle:** inventory AI gateways that trust `X-*-Real-Ip` / similar; never expose Next.js LLM APIs without the intended reverse-proxy header rewrite; rotate provider keys if the path was internet-reachable on pre-0.5.6 builds.

Sources: GHSA-5mj8-gf6m-fhw8 — https://github.com/decolua/9router/security/advisories/GHSA-5mj8-gf6m-fhw8 ; NVD CVE-2026-56681 — https://nvd.nist.gov/vuln/detail/CVE-2026-56681 ; fix — https://github.com/decolua/9router/releases/tag/v0.5.6

## 5) Nuclei — Goja JavaScript templates → scanner-host RCE (GHSA-vxg7; CVE-2026-76819 Rejected)

GitHub Advisory DB published **GHSA-vxg7-f2jj-jmqm** on **2026-09-22T20:37:13Z**: the Goja JS engine used by Nuclei’s `javascript:` protocol allows **native code execution on the scanner host** when evaluating untrusted templates (OOB heap write). Alias **CVE-2026-76819** is **NVD Rejected** (“Further research determined the issue results from a dependency”) — **lead on the GHSA / ProjectDiscovery advisory**, not the Rejected CVE ID. Fix path: bump Goja via **Nuclei ≥3.10.0** (JS template signing hardening in **3.11.0**). Same-day **non-rejected** siblings include DAST code-signature command exec (**CVE-2026-76802**), MySQL sandbox LFR (**76803**), workflow file-protocol LFR (**76804**), and env disclosure (**76805**).

**Evidence type:** official advisory (GHSA). Requires processing attacker-influenced JS templates — not a default pre-auth remote against a Nuclei daemon story.

**Consulting angle:** pin Nuclei ≥3.10.0; treat community/third-party template sources as code execution trust; isolate scanner hosts from secrets and production credentials.

Sources: GHSA-vxg7-f2jj-jmqm — https://github.com/advisories/GHSA-vxg7-f2jj-jmqm ; NVD Rejected note — https://nvd.nist.gov/vuln/detail/CVE-2026-76819
