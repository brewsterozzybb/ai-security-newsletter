## 2) OpenCode — drive-by host RCE via `/global/upgrade` content-type confusion (GHSA-632h-h47v-g4x4)

**Datadog Security Labs** (Christophe Tafani-Dereeper; **September 24, 2026**) + Anomaly **GHSA-632h-h47v-g4x4** (same day): OpenCode’s `opencode serve` / `opencode web` **`POST /global/upgrade`** parsed bodies as JSON **without requiring `Content-Type: application/json`**, so a malicious page could submit a top-level HTML form (`enctype=text/plain`) that assembles valid JSON, point `target` at an **attacker-controlled npm tarball**, and run a **preinstall** lifecycle script as host RCE. Affects **1.14.30–1.18.21** when installed via **npm/pnpm/Bun**; fixed in **1.18.22**. Datadog cites **~647k downloads** of vulnerable builds in a Sep 17–23 week sample (not unique hosts). Anomaly **did not request a CVE** (GHSA-only). Patch merged **Aug 24**; public write-up delayed ~1 month at vendor request — **in-window clock is disclosure**, not patch day. Vendor X call-to-update **2026-09-24T14:53:34Z**; HN thin (~4 pts).

**Evidence type:** researcher experiment + vendor advisory. Needs vulnerable serve/web running (often default-unauthenticated on `127.0.0.1`), npm-family install, and a browser path that reaches localhost (modern Local Network Access prompts may reduce drive-by success). Do not conflate with OpenCode’s earlier unauth-server GHSA-vxw4 / CVE-2026-22812.

**Consulting angle:** inventory OpenCode (and peer coding agents with local HTTP UIs); require password on serve/web; pin **≥1.18.22**; treat upgrade/install endpoints that accept remote package URLs as RCE-class.

Sources: Datadog — https://securitylabs.datadoghq.com/articles/opencode-upgrade-remote-code-execution/ ; GHSA — https://github.com/anomalyco/opencode/security/advisories/GHSA-632h-h47v-g4x4

## 3) Cloudflare Containers / Sandboxes — cross-tenant residual disk via `skip_block_zeroing`

**Cloudflare** (joint with Accomplish / Oren Yomtov; blog **September 24, 2026**) disclosed that Containers and Sandboxes (built on Containers) used Linux **dm-thin** pools with **`skip_block_zeroing`**. A **Workers Paid** customer could force allocation of a reused **64 KiB** block with a small **4 KiB** write into guest free space, then read residual bytes (~60 KiB) from a prior tenant’s container disk (`/dev/vdc` in Firecracker). Researchers reported residual material on many placements (directory structures, DB pages, SQLite). Fix: remove the flag; retire running disks + cached snapshots; cleanup completed **Sep 19**. Cloudflare reports **no evidence of malicious exploitation** and **no customer action required**. Cannot target a specific victim; residual data not guaranteed. Reported **Sep 4**; disclosed **Sep 24**. Researcher/press claims that **Browser Run** shares the disk class are **not** in Cloudflare’s affected-product list — treat as claimed, not vendor-confirmed. “Sixth sandbox escape since July” is Accomplish self-framing across prior products — not independently re-verified here.

**Evidence type:** vendor + researcher joint disclosure. Not a CVE. Strong X amp; thin HN.

**Consulting angle:** treat “safe place to run agent code” products as still owning storage-pool hygiene; ask multi-tenant sandbox vendors how thin-provisioning / block-zeroing is configured and how residual-disk risk is monitored.

Sources: Cloudflare — https://blog.cloudflare.com/containers-cross-tenant-vulnerability/ ; THN amp — https://thehackernews.com/2026/09/cloudflare-fixes-flaw-that-let-one.html

## 4) IBM ContextForge MCP Gateway — Admin log path traversal (CVE-2026-77825)

IBM bulletin **`publishDate` / `effectiveDate` = 2026-09-24** and NVD **`2026-09-24T15:17:38Z`**: ContextForge MCP Gateway **v1.0.0–v1.0.8** Admin API `GET /v1/admin/logs/file` used `str.startswith()` for path confinement, letting an **authenticated admin** read `.log` / `.jsonl` / `.json` files **outside** configured `LOG_FOLDER` via sibling-directory prefix tricks (IBM CVSS **4.9**, PR:H, C:H). Remediation: upgrade to **≥1.0.9**.

**Evidence type:** official advisory. Same-day vendor stamp (rarer than NVD-only formalizations). Confidentiality-only; needs admin authn.

**Consulting angle:** inventory ContextForge admin API exposure; upgrade to **≥1.0.9**; do not treat “admin-only” as low risk when logs may hold tokens or tool traces.

Sources: IBM — https://www.ibm.com/support/pages/node/7289314 ; NVD — https://nvd.nist.gov/vuln/detail/CVE-2026-77825

## 5) Cline Hub dashboard — cross-origin WebSocket hijack → ACE (CVE-2026-59723) — formalization

**GHSA-3cj3-hqcr-g934** published **`2026-09-24T19:48:34Z`** (**CVE-2026-59723**, CVSS **8.8**): `@cline/cline-hub` (`cline dashboard`) accepts WebSocket connections on `/browser` **without validating `Origin`**. When `ROOM_SECRET` is unset (default on `127.0.0.1`), any visited site can open `ws://127.0.0.1:8787/browser`, send `desktopCommand` frames, mutate MCP/provider settings, and — with default **`autoApprove: true`** — trigger **arbitrary command execution**. Listed fix **`cli-v3.0.30` / package `< 3.0.30`** — GitHub release **`2026-06-26`** → **lead as GHSA-DB formalization**, not a June patch day.

**Evidence type:** official advisory. Needs local dashboard running + victim visits malicious page (UI:R; AV:A).

**Consulting angle:** inventory Cline dashboard use; set `ROOM_SECRET` / disable autoApprove; pin patched CLI; treat localhost agent dashboards as drive-by RCE surfaces (pairs with OpenCode Main #2).

Sources: GHSA — https://github.com/advisories/GHSA-3cj3-hqcr-g934 ; NVD — https://nvd.nist.gov/vuln/detail/CVE-2026-59723
