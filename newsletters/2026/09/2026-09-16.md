## 1) `@zereight/mcp-gitlab` — unauth SSE file-read → PAT + token SSRF + DNS rebinding (CVE-2026-61560 / 61559 / 61568)

NVD published three criticals for the popular GitLab MCP server: **CVE-2026-61560** on **2026-09-15T22:16:58.040Z** (CVSS **9.8**) — with `SSE=true`, MCP tools are exposed **without authentication** and `upload_markdown` reads unsanitized `file_path`, so a network attacker can exfil `/proc/self/environ` and steal `GITLAB_PERSONAL_ACCESS_TOKEN` (default Docker-style deploys). **CVE-2026-61559** (**2026-09-15T21:16:41.390Z**, CVSS **9.6**) — with `ENABLE_DYNAMIC_API_URL=true`, attacker-controlled `X-GitLab-API-URL` becomes the outbound API base with the victim’s `Private-Token` attached (no hostname allowlist). **CVE-2026-61568** (**2026-09-15T21:16:41.570Z**, CVSS **9.6**) — Streamable HTTP lacks effective Host/Origin allowlist → DNS rebinding to a local MCP listener. Floors: **≥2.1.27** for 61560/61559; **≥2.1.30** for 61568.

**Evidence type:** official advisory (GHSA + NVD). **GHSAs ~June–July 2026** — novelty is NVD formalization. Reachability + risky flags (`SSE=true`, dynamic API URL) are prerequisites; stdio-only local differs. Thin same-day X amplification (last30days) is discovery only, not independent corroboration. No wild-exploitation claim here.

**Consulting angle:** inventory network-exposed GitLab MCP bridges; treat unauth SSE and header-driven API-base override as credential-proxy failures; rotate any PATs that may have been reachable; prefer authenticated single-tenant / stdio until patched.

Sources: NVD CVE-2026-61560 — https://nvd.nist.gov/vuln/detail/CVE-2026-61560 ; NVD CVE-2026-61559 — https://nvd.nist.gov/vuln/detail/CVE-2026-61559 ; NVD CVE-2026-61568 — https://nvd.nist.gov/vuln/detail/CVE-2026-61568 ; GHSA-cv3r-c5h8-f4g5 (background, 2026-06-22) — https://github.com/zereight/gitlab-mcp/security/advisories/GHSA-cv3r-c5h8-f4g5

## 2) MySQL MCP — SSE without Origin/Host auth → unauthenticated SQL (CVE-2026-59971)

NVD published **CVE-2026-59971** on **2026-09-15T15:17:19.947Z** (CVSS **10.0**): `designcomputer/mysql_mcp_server` prior to **0.4.2**, with `MCP_TRANSPORT=sse`, builds `SseServerTransport` **without** DNS-rebinding protection / security settings, and Starlette routes `/`, `/sse`, `/messages/` lack authentication — unauthenticated callers (direct or DNS-rebinding) can drive SQL tool execution against the bound MySQL.

**Evidence type:** official advisory (GHSA + NVD). **GHSA ~2026-06-21** — formalization-only novelty. Confirm SSE vs stdio before paging DB owners.

**Consulting angle:** database MCP over default SSE is data-exfil / destructive-SQL class; require auth + Origin/Host controls on any HTTP MCP transport that can run queries.

Sources: NVD CVE-2026-59971 — https://nvd.nist.gov/vuln/detail/CVE-2026-59971 ; GHSA-rqfv-2mw9-78g2 (background) — https://github.com/designcomputer/mysql_mcp_server/security/advisories/GHSA-rqfv-2mw9-78g2 ; fix v0.4.2 — https://github.com/designcomputer/mysql_mcp_server/releases/tag/v0.4.2

## 3) IBM MCP Context Forge — RestrictedPython sandbox escape via `getattr` (CVE-2026-53710)

NVD published **CVE-2026-53710** on **2026-09-15T17:17:19.117Z** (CVSS **10.0**): IBM **MCP Context Forge** prior to **1.0.2** — `python_sandbox_server` exposes raw `getattr` through `safe_builtins`, omits a required `_getattr_` guard, and relies on incomplete dangerous-import checks → sandbox escape / arbitrary Python on the gateway host. **Consulting angle:** treat MCP-gateway “sandboxes” as attack surface on the tool-execution path; pin Context Forge past **1.0.2** and ask whether RestrictedPython (or similar) actually constrains the object graph customers care about.

Sources: NVD CVE-2026-53710 — https://nvd.nist.gov/vuln/detail/CVE-2026-53710 ; GHSA-xm98-3vcf-fph7 (background) — https://github.com/IBM/mcp-context-forge/security/advisories/GHSA-xm98-3vcf-fph7 ; fix v1.0.2 — https://github.com/IBM/mcp-context-forge/releases/tag/v1.0.2

## 4) Docker Sandboxes — macOS virtio-fs symlink escape to host (CVE-2026-77179)

NVD published **CVE-2026-77179** on **2026-09-15T14:17:11.273Z** (CVSS **9.4**): on **macOS**, the virtio-fs host server used by **Docker Sandboxes** improperly follows symlinks when reopening an unlinked file from a stored path. A malicious guest can escape the shared workspace and read/modify arbitrary host files as the VMM user, **potentially** achieving host code execution. Fixed in Sandboxes **0.42.0** (release clock **2026-09-07** = background). Docker documents Sandboxes for agent / Claude Code / Codex / Gemini CLI-style isolation.

**Evidence type:** official advisory (NVD + vendor release/docs). **macOS-specific**; requires a malicious/compromised guest. No KEV / no claimed in-wild exploitation in sources reviewed. In-window novelty is NVD formalization of a Sep 7 fix.

**Consulting angle:** agent sandboxes are only as strong as the filesystem bridge; on macOS Docker Sandboxes fleets, verify **≥0.42.0** and treat guest workloads as hostile when assessing isolation claims.

Sources: NVD CVE-2026-77179 — https://nvd.nist.gov/vuln/detail/CVE-2026-77179 ; fix v0.42.0 (background, 2026-09-07) — https://github.com/docker/sbx-releases/releases/tag/v0.42.0 ; Docker Sandboxes isolation docs — https://docs.docker.com/ai/sandboxes/security/isolation/
