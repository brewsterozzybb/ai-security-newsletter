## 1) LiteLLM — salt-key dual-use → proxy_admin + MCP stdio RCE (GHSA-7hp6-4w63-5g45)

BerriAI published **GHSA-7hp6-4w63-5g45** (**`2026-09-30T01:13:51Z`**; Critical, CVSS **9.9** `AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H`): LiteLLM Proxy reuses one encryption **salt key** both to seal secrets at rest and to mint session tokens. An authenticated **`internal_user`** requests a new API key whose crafted metadata “secret” embeds a forged admin credential; the proxy encrypts and returns it; presented as a bearer token, decryption yields a trusted **`proxy_admin`** identity, including **arbitrary command execution via the MCP stdio endpoint**. Patched: **1.100.4 / 1.101.3 / 1.102.2 / 1.103.1 / 1.104.0rc2** (releases ~**`2026-09-30T00:58–00:59Z`**). Temporary mitigation: `EXPERIMENTAL_UI_LOGIN=false` (breaks CLI SSO / Claude Code gateway login). Credit: Hoa X. Nguyen (OPSWAT Unit 515). **No CVE ID yet** — do not invent one.

**This is not CVE-2026-93355** (Sep 29 JWT email-fallback ATO). Different root cause, different patch train, vendor-acked releases here.

**Evidence type:** official advisory (vendor GHSA) + patched releases. **Prerequisite:** authenticated **`internal_user`** (**PR:L**) — not unauthenticated internet RCE. Confirm deployed line matches a patched tag.

Sources: GHSA — https://github.com/BerriAI/litellm/security/advisories/GHSA-7hp6-4w63-5g45 ; Releases — https://github.com/BerriAI/litellm/releases
