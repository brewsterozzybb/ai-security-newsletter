Siblings: **CVE-2026-78501** (Business Chat info disclosure, **7.4**), **CVE-2026-55946** (Copilot info disclosure, **6.1**), **CVE-2026-85887** (incorrect permission assignment, **7.7**). SecurityWeek’s broader “18 Azure/AI vulns” count was not independently expanded here; only these four Copilot-tagged IDs are led.

## 2) MCP missing-auth wave — Obsidian Web MCP unauth vault R/W (CVE-2026-54618), NetLicensing API-key passthrough (54446), Doc Server bind-all (54504)

Three independent MCP servers got first NVD pubs on **2026-09-17** (all CWE-306-class missing authentication on reachable MCP/HTTP surfaces):

- **CVE-2026-54618** (**9.4** Critical) — **Obsidian Web MCP** &lt; **0.2.0**: `/oauth/authorize` issues a code **without login/consent/session**; token exchange yields static `VAULT_MCP_TOKEN` → unauthenticated vault read/write/search/delete on reachable tunnel deployments. Fixed **0.2.0**. NVD **2026-09-17T20:16:51Z**.
- **CVE-2026-54446** (**8.1**) — **Labs64 NetLicensing MCP** &lt; **0.1.6**: `/mcp` requests omitting API key pass middleware; tools run under operator `NETLICENSING_API_KEY`. Fixed **0.1.6**. NVD **18:16:46Z**.
- **CVE-2026-54504** (**8.8**, AV:A) — **MCP Documentation Server** **1.13.0** until **1.13.1**: `app.listen(PORT)` binds **all interfaces** with unauthenticated document APIs on default **3080**. Fixed **1.13.1**. NVD **19:16:50Z**.

**Evidence type:** official advisory (GHSA + NVD). **In-window novelty is NVD formalization**; GHSAs are **June 2026 background**. Same recurring deployment failure mode as prior Prism weeks (auth optional / bind-all / OAuth theater).

**Consulting angle:** inventory internet- or LAN-exposed MCP servers; require auth; bind localhost or reverse-proxy with authn; pin floors above.

Sources: NVD CVE-2026-54618 — https://nvd.nist.gov/vuln/detail/CVE-2026-54618 ; CVE-2026-54446 — https://nvd.nist.gov/vuln/detail/CVE-2026-54446 ; CVE-2026-54504 — https://nvd.nist.gov/vuln/detail/CVE-2026-54504

## 3) ZCode (Z.ai / GLM coding desktop) — silent workspace + full `.git` upload to Aliyun OSS

**ferstar** reports (**`datePublished` 2026-09-18T02:00:00+08:00** = **2026-09-17T18:00:00Z**) that logged-in **ZCode** silently packages the entire workspace — including complete **`.git` history**, LFS cache, reflogs, and app configs — encrypts with AES-256-CTR, wraps the key with an RSA-OAEP public key from `zcode.z.ai`, and uploads to **Aliyun OSS**. Local `.enc` artifacts are not client-decryptable (private key stays server-side). Sample local state showed a large encrypted snapshot with high `failureCount` (retrying upload). In-window HN (~107 / ~47 pts) and high-engagement X amplified the teardown; some X posts attribute a vendor “Repo Wiki” explanation and a claimed latest-build fix — **not independently verified** here.

**Evidence type:** researcher experiment / reverse-engineering (ferstar primary) + community amplification. **Not** a CVE/NVD formalization in this window.

**Consulting angle:** treat closed coding harnesses as network-exfil surfaces even when model weights are open; uninstall/disable on sensitive repos until a fix is independently verified; rotate secrets that lived in git history on machines that ran logged-in ZCode.

Sources: ferstar — https://blog.ferstar.org/en/posts/zcode-silent-workspace-snapshot-upload/ ; HN — https://news.ycombinator.com/item?id=49752422 ; X @ferstar_org — https://x.com/ferstar_org/status/2100805861002355154

## 4) SQLBot (LLM Text-to-SQL / RAG) — file-write and second-order SQLi → RCE (CVE-2026-53554 / 53557)

**dataease/SQLBot** received four same-day NVD first-pubs (**2026-09-17T22:16–22:17Z**), fixed in **v1.9.0**. Highest impact: **CVE-2026-53554** (CVSS **7.3**) — `parseExcel` uses attacker-controlled multipart filename to plant content under Alembic versions → code execution; **CVE-2026-53557** (CVSS **7.7**) — crafted Excel `tableName` stored unsafely; on datasource DELETE, interpolated into cleanup SQL → PostgreSQL **COPY TO PROGRAM** → OS commands as postgres in the container. Also **53556** (previewData SQLi file-read) and **53555** (stored XSS via SVG logo).

**Evidence type:** official advisory (GHSA + NVD). Most paths need authenticated upload/datasource privileges. GHSA June discovery = **background**; NVD formalization is the in-window novelty.

**Consulting angle:** “chat with your database” assistants concentrate DB credentials + LLM tool surfaces — treat upload/datasource APIs as RCE-class; upgrade to **≥1.9.0**; isolate DB roles (no `COPY PROGRAM` / superuser).

Sources: NVD CVE-2026-53554 — https://nvd.nist.gov/vuln/detail/CVE-2026-53554 ; CVE-2026-53557 — https://nvd.nist.gov/vuln/detail/CVE-2026-53557 ; release — https://github.com/dataease/SQLBot/releases/tag/v1.9.0

## 5) Plugin4Shell — claimed zero-click marketplace SHA-pinning bypass RCE across Claude Code / Codex / Copilot / Gemini CLI

**AIR Security** (Niv Hoffman; page date **September 17, 2026**) describes **Plugin4Shell**: agent plugin/skill marketplace install checks out the **pinned commit SHA** but **never verifies** the checkout landed on that SHA, so a repo controller can swap malicious code while the pin “looks honored,” worsened by **default plugin auto-update**. Affects (per AIR) **Claude Code, OpenAI Codex, GitHub Copilot, Gemini CLI**. Thin in-window HN (~11 pts, **2026-09-17T20:05:31Z**) + author X. AIR states its own marketplace customers were unaffected — **vendor product claim**.

**Evidence type:** vendor assertion / researcher experiment (AIR blog). **No CVE IDs** and **no Anthropic/OpenAI/Google/GitHub patches** captured in this pass. Do not promote to “all installs owned today.”

**Consulting angle:** verify marketplace checkouts with content hash / `git rev-parse HEAD` after fetch, not pin strings alone; disable plugin auto-update on enterprise agents; allowlist internal plugin feeds.

Sources: AIR — https://www.air.security/blog-posts/plugin4shell ; HN — https://news.ycombinator.com/item?id=49745809
