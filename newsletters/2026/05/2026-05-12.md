## 1. Headliners

### The First AI-Developed Zero-Day Exploit Was Real — And Google Stopped It

For the first time, Google Threat Intelligence Group (GTIG) has documented a criminal threat actor using AI to develop a working zero-day exploit — and has disclosed that it disrupted the campaign before the planned mass exploitation event could be executed.

The target was a popular open-source, web-based system administration tool. The exploit allowed an attacker to bypass two-factor authentication by exploiting a semantic logic flaw: a developer had hardcoded a trust assumption that contradicted the authentication enforcement downstream. On its own, the flaw was real but subtle — the kind that can survive years of human code review. What changed is that AI found it anyway.

**The forensic fingerprints:** GTIG identified the exploit's AI origin through structural evidence in the Python script:
- A "hallucinated CVSS score" — a severity rating format characteristic of LLM training data, not a human exploit author
- Structured, textbook docstrings inconsistent with operational exploit tradecraft
- "Educational" commentary embedded in weaponized code

GTIG stated it does not believe Google's Gemini was used. The threat actor was a criminal group, not a nation-state — though the report notes that PRC- and DPRK-affiliated actors have separately demonstrated significant interest in AI-assisted vulnerability discovery.

**The wider picture from the GTIG May 2026 report:**
- **AI-augmented malware development:** Russia-nexus actors are using AI to generate polymorphic malware and obfuscation networks, dramatically accelerating defense-evasion iteration cycles.
- **Autonomous malware operations:** PROMPTSPY (see Technical Deep Dives) and its predecessors signal a shift toward AI agents that interpret live system state and self-direct attacks.
- **Supply chain targeting:** Threat group "TeamPCP" (UNC6780) compromised AI and security tooling supply chains — Trivy, Checkmarx, LiteLLM, BerriAI — by poisoning GitHub Actions workflows, extracting OIDC tokens from runner memory, and deploying the SANDCLOCK credential stealer. Subsequent pivots enabled ransomware and extortion operations.
- **Obfuscated LLM access infrastructure:** Criminal actors now operate professionalized middleware for anonymized, premium-tier AI model access, enabling large-scale misuse while cycling through trial accounts programmatically.

**Why it matters:** This report marks the transition from "AI will eventually be used in attacks" to "AI is already being used in attacks, at scale." The 2FA exploit is significant not because it succeeded — it didn't — but because it demonstrates that the capability to generate weaponizable exploits from semantic code analysis now exists outside of controlled research environments. The CVSS hallucination is a tell today; tomorrow's attacker will know to strip it.

### TanStack npm Supply Chain: 84 Malicious Versions, 42 Packages, Six Minutes

Yesterday evening (UTC), an attacker published 84 malicious versions of 42 official @tanstack/* npm packages by exploiting a chain of GitHub Actions misconfigurations — without ever stealing an npm token. The attack ran from 19:20 to 19:26 UTC and was detected by an external researcher within 20 minutes. All versions have been deprecated.

**The attack chain (from Tanner Linsley's postmortem):**
1. **Pwn Request (pull_request_target):** The attacker submitted a PR from a fork, triggering a workflow that grants elevated permissions to fork-sourced code — a well-known but persistently dangerous GitHub Actions pattern.
2. **Cache poisoning across the fork↔base trust boundary:** The attacker injected a poisoned cache entry that the base-branch workflow picked up on its next run.
3. **OIDC token extraction from runner memory:** The attacker's code read a short-lived GitHub OIDC token from the Actions runner's in-process memory, using it to authenticate an npm publish without possessing any npm credentials directly.
4. **Payload deployment:** Each affected package received two malicious versions. The payload — a ~2.3 MB obfuscated `router_init.js` — fires on `npm install` via the `prepare` lifecycle hook and harvests:
   - AWS IMDS / Secrets Manager credentials
   - GCP metadata service tokens
   - Kubernetes service-account tokens
   - Vault tokens
   - `~/.npmrc`, GitHub tokens, `.git-credentials`
   - SSH private keys from `~/.ssh`

**Exfiltration channel:** The Session messenger file-upload network (end-to-end encrypted), making traffic interception ineffective. The attacker's infrastructure was designed to be resistant to standard network-level DLP.

**Affected packages:** 42 packages — primarily @tanstack/router/* and @tanstack/react-router/*. Confirmed-clean: @tanstack/query*, @tanstack/table*, @tanstack/form*, @tanstack/virtual*, @tanstack/store.

**Immediate action items:**
- Check lock files for any @tanstack/* version published on 2026-05-11 (deprecated versions visible in npm audit)
- If affected: rotate AWS, GCP, Kubernetes, Vault, GitHub, npm, and SSH credentials reachable from the install host
- Track: [GitHub Advisory GHSA-g7cv-rxg3-hmpx](https://github.com/TanStack/router/security/advisories/GHSA-g7cv-rxg3-hmpx)

**Why it matters:** This attack used no stolen credentials, no social engineering against maintainers, and no vulnerabilities in npm itself. It exploited the trust model of GitHub Actions CI — a configuration gap that exists in thousands of popular repositories. The exfiltration channel (Session) bypassed conventional DLP. Security teams that assume "no token theft, no supply chain risk" need to update that model today.

*Source: [TanStack Official Postmortem](https://tanstack.com/blog/npm-supply-chain-compromise-postmortem) | [Aikido Security detection analysis](https://www.aikido.dev/blog/fake-tanstack-packages-steal-env-files) | [GitHub Advisory GHSA-g7cv-rxg3-hmpx](https://github.com/TanStack/router/security/advisories/GHSA-g7cv-rxg3-hmpx)*

## 2. Breaking News

### RL-Hammer Breaks "Robust" Prompt Injection Defenses — 98% ASR Against GPT-4o at ICLR 2026

**Published:** ICLR 2026 (accepted; conference proceedings May 2026)

Researchers from Meta AI, UC San Diego, and the University of Maryland have published RL-Hammer, a reinforcement learning-based attacker that achieves attack success rates (ASR) that should concern anyone relying on current prompt injection defenses.

**Key results:**
- **98% ASR against GPT-4o** with Instruction Hierarchy — one of the leading published defenses
- **72% ASR against GPT-5** with Instruction Hierarchy
- **80%+ ASR across every evaluated target** — including models with near-zero vulnerability to prior state-of-the-art attacks (GCG, NeuralExec)
- **Complete evasion of perplexity-based detectors** — the standard detection approach fails entirely
- **Transfer attacks:** The attacker achieves 56% ASR against Gemini-2.5-Flash and 70% against Meta-SecAlign-70B despite never training on those targets

**How it works:** RL-Hammer uses Group Relative Policy Optimization (GRPO) to train an attacker model entirely from scratch — no warm-up data required. The core insight is that naive GRPO fails against defended models because defenses produce near-zero reward signals. RL-Hammer introduces techniques to escape this sparse-reward trap, enabling the attacker to learn effective injections that survive sophisticated instruction hierarchy filtering. The resulting prompts are natural enough to evade perplexity filters.

**The uncomfortable finding:** Models like SecAlign and Instruction Hierarchy that were specifically designed to make LLMs ignore injected instructions are demonstrably defeatable by automated RL-trained attackers. The "robust defense" framing should be retired.

**For red teams:** RL-Hammer represents a significant step toward automated, scalable prompt injection testing that can replace or augment manual adversarial prompting. For blue teams, the message is that perplexity-based detection of prompt injections should not be treated as a reliable safeguard.

*Source: [arXiv:2510.04885](https://arxiv.org/abs/2510.04885) | [OpenReview (ICLR 2026)](https://openreview.net/forum?id=VTyL1y4Lab)*

### TeamPCP's AI Tooling Supply Chain Hits: Trivy, Checkmarx, LiteLLM, BerriAI

**Published:** May 11, 2026 (within GTIG report)

The criminal group TeamPCP (tracked by Mandiant as UNC6780) claimed responsibility in late March 2026 for simultaneous supply chain compromises of multiple GitHub repositories used widely in AI security workflows. The GTIG report published yesterday provides the most detailed public account to date.

**Targeted repositories confirmed:** Trivy (vulnerability scanner), Checkmarx (SAST platform), LiteLLM (LLM API proxy), BerriAI (LLM ops).

**Method:** TeamPCP gained initial access via compromised PyPI packages and malicious pull requests. Once inside the CI pipelines, they embedded the SANDCLOCK credential stealer, extracting high-value cloud secrets — AWS keys, GitHub tokens — directly from build environments. Stolen credentials were monetized through partnerships with ransomware and data extortion groups.

**The compound risk:** These are tools used specifically for AI development and security. Compromising Trivy affects the pipelines that scan container images for vulnerabilities; compromising LiteLLM affects organizations routing production LLM traffic through it. An attacker who gains credentials from these builds has access to both the organization's cloud infrastructure and its AI infrastructure simultaneously.

**Mitigation posture:** Organizations using these tools should audit their build logs for the March–April 2026 window, verify current versions against known-good hashes, and review which CI workflows have access to production cloud credentials.

*Source: [Google Cloud Blog — GTIG](https://cloud.google.com/blog/topics/threat-intelligence/ai-vulnerability-exploitation-initial-access)*

## 3. Technical Deep Dives

### PROMPTSPY: Android Malware That Uses Gemini to Navigate Your Phone

ESET Research has published the first detailed analysis of PROMPTSPY, the most technically novel Android malware discovered to date — one that uses Google's Gemini API as a real-time instruction engine for autonomous UI manipulation.

**How PROMPTSPY works:**

The malware's core innovation is replacing hardcoded tap coordinates with live AI reasoning. At execution time, PROMPTSPY:
1. Uses Android Accessibility Services to dump the current screen's full UI hierarchy as XML — every element, its text, type, class name, package, and screen bounds.
2. Sends this XML to the Gemini API along with a natural-language prompt describing the desired action (e.g., "lock this app in the recent apps list").
3. Receives back a JSON response containing precise tap coordinates and gesture commands.
4. Executes those gestures via Accessibility Services.

This means PROMPTSPY can navigate *any* device, screen size, or Android version without modification. Traditional behavior-based detection expecting specific tap sequences or screen coordinates finds nothing to match.

**Additional capabilities:**
- **Biometric capture:** Records PINs and lock patterns and replays them to unlock a locked device
- **Overlay persistence:** Renders an invisible touch-intercepting layer over the uninstall button, silently blocking removal attempts
- **Remote API key update:** Gemini API keys can be swapped via C2 without redeploying the payload — extending malware lifespan beyond a single compromised key
- **VNC backdoor:** Full real-time screen viewing and remote control for the operator

**The C2 infrastructure** communicates to a hardcoded IP (54.67.2[.]84) over AES-encrypted VNC protocol.

**ESET context:** PROMPTSPY is the second AI-powered malware family ESET has documented, following PromptLock (August 2025, AI-driven ransomware). The convergence of autonomous UI capability and persistent backdoor access represents a meaningful escalation over prior Android RATs.

**Detection status:** Google confirmed no PROMPTSPY-containing apps are currently live on Google Play. Android devices with Google Play Services and Play Protect enabled are protected. Sideloaded apps and enterprise MDM-enrolled devices with reduced Play Protect coverage are the primary risk surface.

**For defenders:** The novel attack surface is the Gemini API call itself. Organizations with enterprise Android management should monitor for unusual Accessibility Service grants combined with outbound API traffic to `generativelanguage.googleapis.com` from apps without legitimate AI use cases. The malware's C2 IP (54.67.2[.]84) is a concrete IOC.

**IOCs:**
- C2: `54.67.2[.]84` (VNC protocol, AES-encrypted)
- API calls: `generativelanguage.googleapis.com` (Gemini API)
- Malware behavior: Accessibility Service + XML screen dump + JSON tap coordinate receipt

*Source: [ESET WeLiveSecurity — PROMPTSPY analysis](https://www.welivesecurity.com/en/eset-research/promptspy-ushers-in-era-android-threats-using-genai/) | [Help Net Security — GTIG summary](https://www.helpnetsecurity.com/2026/05/11/google-ai-vulnerability-exploitation/)*

### Microsoft Agent Governance Toolkit v3.5.0: The OWASP Agentic Top 10 Coverage Gets Enterprise Rails

Microsoft's open-source Agent Governance Toolkit shipped v3.5.0 last week, and this release substantially raises the toolkit's enterprise readiness for organizations deploying autonomous AI agents.

**What's new in 3.5.0:**

**Citadel Integration (Phase 1 + 2):** An Entra identity bridge and Azure API Management policy fragment that ties agent identity to enterprise identity infrastructure. Agents receive verifiable, attestable identities bound to Entra — not just API tokens. This directly addresses the "Agent Identity Spoofing" risk in the OWASP Agentic Top 10.

**Multi-Agent Collective Policy Evaluator:** Rate limits, concurrent execution caps, and constraint enforcement now operate across entire agent workflows, not just individual agents. In a multi-agent pipeline, a collective policy can prevent a malicious or compromised agent from using the combined bandwidth of the system.

**Decision BOM Reconstructible View:** Every agent action can now be reverse-engineered from observability signals — even when some sources are unavailable. This is the forensic paper trail that security teams need to answer "what did this agent actually do, and why" after an incident.

**Intent-Based Authorization:** A declare/approve/execute/verify lifecycle for multi-agent orchestration with drift detection. When an agent's behavior deviates from its declared intent, the toolkit flags it before the action executes.

**Cost Governance:** Tiered budgets at the per-task, per-agent, and org-wide level, with auto-throttle and anomaly detection. Includes kill switches — literally the ability to halt an agent that is consuming anomalous resources.

**Why this matters for security teams:** The AGT now maps controls against all 10 OWASP Agentic AI risks with sub-millisecond policy enforcement latency. The Citadel integration is particularly relevant as more organizations require that AI agents operate within the same identity governance frameworks as human users. The Decision BOM is the closest thing the industry has to an audit log standard for agent behavior — and it's open source.

### HN: "Postmortem: TanStack npm supply-chain compromise" — The Community Reacts

The TanStack postmortem hit Hacker News yesterday and sparked a substantive thread on the structural problem it represents: the `pull_request_target` GitHub Actions pattern is widely understood to be dangerous and widely used anyway.

The top comments coalesce around several themes:

1. **"This is not a TanStack failure — this is a GitHub Actions design failure."** The `pull_request_target` pattern grants elevated permissions to fork-sourced code by design (it exists to allow forks to use secrets for posting CI status). The fix is either to never use it or to implement extremely careful conditional gates.

2. **"OIDC token extraction from runner memory is the scary part."** The attack didn't require a stolen npm token — it obtained publishing rights through a short-lived OIDC token read from the runner process. This means any repository using OIDC-based npm publishing with `pull_request_target` is potentially vulnerable, regardless of how carefully it protects its npm credentials.

3. **"The Session exfiltration channel was deliberate."** Using Session's e2e-encrypted file upload network to exfiltrate credentials means conventional DLP scanning of outbound HTTP wouldn't catch it. The attacker specifically chose an encrypted channel with no central visibility point.

4. **Immediate community action:** Several maintainers of other popular libraries posted within hours that they were auditing their workflows for the same pattern.

## 5. The Daily Feed

**Pipelock v2.3.0 — Open-Source AI Agent Firewall (Go Binary, Apache 2.0)**

Pipelock, developed by Joshua Waldrep under PipeLab, is the most complete open-source implementation of an out-of-process AI agent security proxy available today. Unlike SDK-based agent security tools that depend on the agent cooperating with its own guardrails, Pipelock sits at the network egress boundary — a compromised or poisoned agent cannot bypass it because it never touches the agent's process.

Architecture: the agent process holds secrets but has no direct network access; the Pipelock proxy holds network access but no secrets; all traffic crosses an 11-layer scanning boundary. Layers include: scheme enforcement, CRLF injection detection, path traversal blocking, domain blocklisting, DLP (48 credential patterns, Luhn/mod-97/ABA/WIF checksum validators), entropy analysis, SSRF protection, rate limiting, URL length checks, and per-domain data budgets.

The v2.3.0 release added class-preserving request redaction and SSE streaming response scanning. Protocol coverage: HTTP forward proxy, CONNECT tunnels, WebSocket (both directions), MCP stdio and streamable HTTP, Google Agent-to-Agent protocol. Compliance mappings: OWASP MCP Top 10, OWASP Agentic AI Top 10, MITRE ATT&CK, EU AI Act, SOC 2, NIST 800-53. Output: SARIF v2.1.0 for GitHub Code Scanning.

## 6. Five Things to Take Into the Rest of the Day

**1. The AI exploit development threshold is crossed — and the forensic tells won't last.**
Today's GTIG report documents the first confirmed AI-developed zero-day exploit in a criminal operation. The hallucinated CVSS score and LLM-structured docstrings gave it away. Neither of those artifacts is inherent to AI-generated exploits — they are artifacts of current LLM behavior under prompting. Within one or two model generations, attacker workflows will strip these markers. Start assuming AI-developed exploits are possible now; do not wait for a "confirmed" case without forensic tells.

**2. Your GitHub Actions CI/CD is probably your softest supply chain surface.**
The TanStack attack required no stolen credentials. It required misconfiguration of a GitHub Actions permission model that tens of thousands of open-source projects share. Audit your workflows today for `pull_request_target` combined with OIDC-based publishing. If you find it, either gate it behind PR label restrictions or remove it.

**3. "Robust" prompt injection defenses are not robust against automated RL attackers.**
RL-Hammer achieves 98% ASR against GPT-4o with Instruction Hierarchy at ICLR 2026. Perplexity-based detection fails entirely. If your agentic system's safety posture relies on prompt injection defenses at the model layer, that posture deserves re-evaluation. Defense-in-depth at the application layer — strict output schemas, action allowlists, human-in-the-loop for sensitive operations — is more durable.

**4. PROMPTSPY redefines the Android threat model for enterprises with BYOD or MDM.**
A malware family that uses live AI reasoning to navigate any device UI bypasses signature-based and heuristic-based mobile threat detection. The detection pivot: look for Accessibility Service grants combined with unusual outbound API traffic to Gemini endpoints from apps that have no declared AI use case. Add this to your MDM policy review criteria.

**5. Open-source agentic governance is maturing faster than most enterprise deployments.**
Microsoft's AGT v3.5.0 covers all 10 OWASP Agentic Top 10 risks with sub-millisecond policy enforcement and now includes Entra identity attestation. Pipelock provides out-of-process network boundary enforcement. If your organization is deploying autonomous agents without this category of tooling, you are building on governance infrastructure that does not yet exist. These tools are available, free, and production-ready.
